# CNS RPi

树莓派端 MAVLink 数据汇聚与 MQTT 转发程序。默认单台树莓派连接一台采用 STM32F407 的 CNS 主控箱，负责身份获取、遥测解析与上报；主控箱下行命令经 MAVLink 转发并回传执行结果。固件、MQTT broker 和服务器数据库、路由程序不属于本仓库。

## 当前支持范围

程序接入 F407 主控箱：被动接收 `OPEN_DRONE_ID_BASIC_ID.uas_id` 作为唯一业务身份，汇聚已实现的 MAVLink 遥测并发布快照、实时状态和命令回执。显式设置 `rtk_base.enabled=true` 时，在同一个箱子主流程中另接 3DR/PX4 与 9Ps 两条独立串口；MQTT 注册、遥测外层和实验 target 仍使用 F407 箱子 `device_id`、`device_type=cns_box`，PX4 身份仅作为实验元数据。树莓派不提供设备业务身份。配置不提供旧设备自动识别模式或局域网地面站桥接；主控箱固件内部的 `Px4Lite` / `px4lite_*` 名称仍沿用原协议。

旧配置中的 `device.mode=auto|cns_box` 和关闭的 `qgc_udp` 可由部署迁移移除；其他设备模式或已启用的桥接会明确拒绝。废弃的 `px4_realtime` 不再决定实时发布参数，旧版遥测结构迁移后实时通道使用 100 ms 默认值。当前源码清理尚不代表实体 Pi、服务器/Web 或云端版本已完成验收。

部署使用普通可写根文件系统，现场配置保存在 `/var/lib/cns-rpi/config.json`。V1.0 不使用 OverlayFS 或独立配置卷，不新增 MQTT TLS。主程序和 5G 守护服务均由 systemd 开机自启动，保留自动恢复、有界日志与主程序 watchdog。

发布收尾状态见 [发布准备清单](docs/V1.0发布准备清单.md)，历史 V1.0 基线能力与验收边界见 [V1.0.0 发布说明](docs/V1.0发布说明.md)，当前修订内容见 [V1.0.5 发布说明](docs/V1.0.5发布说明.md)。

## 远程更新与预编译安装

远程设备采用“Web 选择版本并点击更新 → 后端 MQTT 更新消息 → 路由服务器任务 → Pi 主动领取 → 安装并回报”的流程。CI 生成 trixie ARM64 包，Pi 只安装；普通业务更新不重启 5G，失败可恢复上一版本。

批量首次部署使用同一预装镜像：烧录、连接 F407/5G 模块、上电；编号由 F407 提供，设备首启生成一份接入密钥，服务器首次确认后即可更新。不再增加维护节点编号或专用升级令牌。镜像生成、真实启动与服务器联调分别记录。原有已安装系统仍可经 LAN/Wi-Fi 初始化。

## RTK 基站与移动站实验

2026-11-09 增量：树莓派支持本地 RTCM→MAVLink 改正转发、开始/暂停/恢复/停止，以及真实 UBX/RTCM/GPS 原帧、实际发送分片、定位样本新鲜度和状态变化。完整原文进入低频快照，高频实时帧只传状态和计数。进程重启默认停止转发；不需要 QGC。服务器和网页本轮未修改，数据接入及实体验收边界见 [移动站实验与教学数据接口](docs/RTK移动站实验与教学数据接口.md)。下段为原第一实验基础。

`rtk_base` 默认关闭。启用后增加基站识别、RAM Survey-in 配置、真实观测与 RTCM 输出统计，F407、G2、配置及控制流程继续运行。`serial.device/baud` 属于 F407，仍可使用 `auto`，自动发现排除 RTK 两个设备；`rtk_base.px4_device/px4_baud` 属于 3DR/PX4，`rtk_base.device/baud` 属于 9Ps，后两者须为不同的明确绝对路径，并与 F407 端口分开。已有合法持久化箱子绑定且无身份冲突时，允许 F407 未连接的缓存身份 RTK 发布；此时不携带旧 F407 普通传感数据，内部会话保留 cached/offline/unknown，常规状态帧独立上报 online。无箱子绑定时仅本地观测，不使用 PX4 注册。PX4 失联只撤销其实验状态，不关闭箱子 MQTT。不接入 NTRIP 或飞控控制；改正转发必须显式发起移动站操作。第一实验操作、MQTT 请求/回执和本地状态字段见 [RTK 基站第一实验操作与接口](docs/RTK基站第一实验操作与接口.md)。

缓存 RTK 快照按现有服务器 schema 3 合同保留精确空 `"drone_id":{"basic_id":{}}`，其中没有 F407 实时观测值；schema 1 实时帧仍不含 `drone_id`，服务器代码未改。

配置读回成功、Survey-in 完成、RTCM 可见及移动端 RTK Fixed 是不同事实。当前缓存箱子身份的正式服务已部署并完成 MQTT、HTTP 和服务重启验证，见 [常驻交付记录](docs/validation/2026-11-06-rtk-base-service.md)；F407 接回后的实体三链路/G2 同时运行和室外测量仍待验。旧 PX4 独立注册实测保留为历史组件证据。

## 源码开发部署

目标为 Raspberry Pi 5、Raspberry Pi OS 64-bit（trixie / Debian 13）、用户 `dcdw`，仓库路径固定为 `/home/dcdw/cns_rpi`。用户须具备 sudo 权限；未配置免密 sudo 时，交互执行脚本会请求密码。

```bash
git clone https://ghfast.top/https://github.com/oran9eLi/cns_rpi.git /home/dcdw/cns_rpi
cd /home/dcdw/cns_rpi
cp config/config.example.json config/config.json
nano config/config.json
./scripts/install_deps.sh
```

默认 F407 部署先确认现场 MQTT 地址、APN、串口自动发现、上报周期及 `identity.binding_file`，再执行脚本。`install_deps.sh` 安装依赖并调用 `deploy.sh` 构建、初始化配置、安装 helper 和两个常驻服务。已有现场配置会保留，不用仓库样例覆盖。完整步骤与旧只读设备迁移边界见 [新设备部署手册](docs/新设备部署手册.md)；RTK 第一实验见 [研发正式常驻部署](docs/RTK基站第一实验操作与接口.md#31-研发正式常驻部署)。

```bash
systemctl status cns-rpi.service cellular-dialup.service --no-pager
journalctl -u cns-rpi.service -u cellular-dialup.service -n 100 --no-pager
```

## 遥测通道

| 通道 | Topic | 默认周期 | 用途 |
|---|---|---|---|
| 完整快照 | `{namespace}/{device_id}/telemetry/snapshot/v1` | 1000 ms | 数据库维护完整状态 |
| 实时状态 | `{namespace}/{device_id}/telemetry/realtime/v1` | 100 ms | 查看当前设备的动态数据 |

两个通道均为 QoS 0、`retain=false`，失败帧直接丢弃。快照包含实时通道的核心动态数据。服务端须先支持新 Topic，再更新设备。详细契约见 [高低频遥测发布协议](docs/高低频遥测发布协议.md) 和 [服务端迁移说明](docs/服务端对接-高低频遥测Topic迁移.md)。

当前发布准备见 [V1.0.8 发布说明](docs/V1.0.8发布说明.md)。

## 主控箱常规状态与内部三态

主控箱在 `{namespace}/{device_id}/runtime/status/v1` 以 QoS 1、`retain=true` 发布[十一字段常规设备状态帧](docs/常规设备状态上报.md)：设备 SN、学校中文名、角色号、Pi 软件版本、设备名称、设备类型、能力、产品信息、在线声明、整机状态和异常模块名 `fault_modules`。2026-11-11 新增的 `fault_modules` 尚未发布部署，现有 v1.0.8 安装包仍发送十字段。连接后立即发布，之后每 10 秒以及重连、内容变化时发布。`online="0"` 表示 Pi MQTT 控制连接在线，`online="1"` 为主动离线声明或异常断线遗嘱；F407 业务暂时离线不影响此周期上报。

`device_status` 为 `"0"` 可用、`"1"` 维修中、`"2"` 损坏。各模块只累计设备运行中的离线/故障时间，任一模块达到 12 小时报损坏；未知和启动状态暂停，在线、降级或主动关闭结束该模块连续故障。进度与维修标记保存在绑定文件旁的 `.health.json`，重启续计，关机不计。默认每 60 秒、整机健康等级变化及正常退出保存；突然掉电可能丢失最后一个未保存检查点。

`fault_modules` 为模块名称数组，已核验的离线／故障立即列出，不等 12 小时，降级和主动关闭不计。已累计满 12 小时的致损模块在重启或断开 F407 后保留到明确恢复。无已确认异常为 `[]`，不表示所有模块已确认健康；缺少可核验模块数据且无保留致损原因为 `null`。维修中仍报实际列表。遗嘱中的列表是连接时快照，仅列表变化不额外重连；不能据此认定故障已恢复。模块名及中文对照见上述契约。

学校名称由现场 `identity.school_name` 首次填写；名称、类型、角色号、能力和产品信息支持可选 `device_status` 本地资料配置。设备 ID、Pi 软件版本、在线声明和异常模块名只读，不接受本地资料或 Web 覆盖。Web 修改握手与云端下发尚未接入；维修仅预留内部设置/解除接口，自动健康判断不会覆盖维修标记。

Pi 将首次真实核验的 F407 身份保存到 `identity.binding_file`。重启或串口暂时失联时可用缓存身份恢复 MQTT；身份重新出现后必须一致才允许遥测和需向主控板下发的命令，冲突不会自动改绑。RTK 启用且已有合法持久化箱子绑定、无身份冲突时，可在缓存身份下发布 RTK，帧中不携带失联 F407 的普通传感数据，具体条件见 [RTK 第一实验接口](docs/RTK基站第一实验操作与接口.md)。Pi 控制链、F407 业务链和身份核验三态继续用于内部控制和实验 ACK，不再以旧五字段 runtime 载荷发布。协议、维护边界和验收命令见 [设备运行三态发布与验收](docs/设备运行三态发布与验收.md)。

阶段一里程碑三的只读 `inspect_pi_link` 已在 Pi 侧实现：Pi 控制在线且身份为 `verified|cached` 时，返回当前控制链、身份、F407 业务链和串口端点事实，不要求 F407 业务在线，也不向 UART6 发实验帧。它与需下发主控板的命令门禁不同；串口端点已打开不能当作 UART6 通信成功。设备侧格式见 [Pi 控制链自检跨端契约](docs/2026-09-22-阶段一Pi控制链自检跨端契约.md)，部署记录与剩余验收边界见 [Pi 控制链自检实现与验证](docs/阶段一Pi控制链自检实现与验证.md)。直达 Pi 的 MQTT 自检已验证，Server/Web 闭环尚未验收。

阶段一 H1 的 `uart_echo` 已完成树莓派端候选实现：沿用唯一串口读写者发送 MAVLink `TUNNEL` 请求，核对 F407 回显、双方实际波特率和动作后新业务帧，再向 `experiment/ack` 发布完整帧与单调 RTT。2026-09-23 已在实体 Pi 完成隔离 Broker 测试，并将提交 `0b86a59` 部署到生产服务；现网直达 MQTT 的受限文本回显成功，双方报告速率均为 115200。Broker 匿名来源控制与 Server/Web 闭环仍未验收，不将 Pi↔F407 单项通过写成跨端完成。详见 [H1 本端验证记录](docs/阶段一H1真实回显树莓派端离线实现与待验收.md)和[现网部署记录](docs/2026-09-23-H1树莓派现网部署记录.md)。

阶段一 M1 的 Pi 端新增 `set_f407_baud`、`uart_probe`、`set_pi_baud`：F407 改速须当前身份已核验，缓存身份下的失配探测仍须可信串口拓扑；动作身份先落盘，再按类型 3/4 记录旧速率接受事实。失配探测沿用 H1 Echo，三轮各有独立随机数和真实帧；Pi 本地换速先保存 `serial.baud`，再由同一进程关闭、重开并读回串口。2026-09-24 已在实体 Pi 取得 B0/B1 两档真实业务帧与 Echo、F407 实际回报 57600，以及实体复位后恢复 B0 的证据；Server/Web 闭环仍待验收。详见 [M1 树莓派端实施记录](docs/change_history/2026-09-24_M1树莓派端.md)。

第二阶段链路排障实验在 Pi 侧增加临时教学 `RPICELL` 状态覆盖、周期报送开关及唯一业务串口临时换速，均不写入真实 5G 或持久串口配置。MQTT 控制链中断、租约超时或进程重启会清除覆盖；F407 屏幕和 Server/Web 闭环仍须现场验收。设备侧协议与事实边界见 [链路排障 Pi 端临时控制](docs/第二阶段链路排障Pi端临时控制.md)。

128 条是尚未获得 MQTT 完成确认的实验 ACK 队列容量，不是单次 Session 的累计命令次数上限。队列满时新的链路排障动作暂不执行，以免发生动作已执行却无法保存 ACK；服务端应控制在途动作量并将无 ACK 视为未确认，不能把超时当作执行成功。

H1/M1 的 128 条持久化去重记录在处理新动作时，仅自动回收已过期且已有终态的旧记录；未完成记录即使过期也保留，不能通过清空现场文件恢复容量。详见 [动作去重记录容量修复](docs/change_history/2026-10-13_H1M1动作去重记录容量修复.md)。

F407 的 `DCDW-XXX` 节点编号可修改，不作为设备唯一身份。Pi 以稳定的 `device_id` 维持 MQTT Topic；节点编号变化时核验新的 MAVLink 端点与 Basic ID，并在核验期间暂停新的串口下行。实体 Pi 已验证 F407 改为节点 110 并复位后自动恢复接入；执行中实验的跨端连续性仍待 Server 联调。详见 [动态节点 ID 实施与验证记录](docs/change_history/2026-10-13_F407动态节点ID端点复核.md)。

主控箱 Pi 进程重启后先按持久化 `serial.baud` 发现串口；若保存值为 57600 且未收到合法帧，才在已绑定设备的受信 USB 拓扑路径上被动尝试基准 115200。只有重新核验同一 F407 身份和串口实际速率后才持久化恢复值；仅打开串口或收到其他 MAVLink 帧不算恢复。启动复核期间的 M1 `uart_probe` 返回串口暂不可用，避免抢占自动发现；现有 `set_pi_baud` 仍可用于人工恢复。运行中的 M1 失配观察不自动跟速，MQTT 控制链不因探测失败而退出。本端尚未在实体 Pi 验证该重启恢复分支。
