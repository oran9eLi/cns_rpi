## 身份、配置与运行边界

Pi 与 F407 属于同一套实验设备，继续使用真实 F407 身份建立的 `device_id`、现有 MQTT 会话及实验 Topic，不新增 Pi 业务身份。视频不写 UART；Pi 控制在线且身份已核验或有合法缓存时，F407 业务暂时离线不应阻止 Pi 本地视频操作。身份冲突及无绑定状态仍按现有规则拒绝。

配置新增可选 `video` 对象。缺少该对象时默认禁用，兼容旧现场配置；`enabled=false` 时不启动摄像进程。示例：

```json
{
  "video": {
    "enabled": false,
    "executable": "/usr/bin/rpicam-vid",
    "ffprobe": "/usr/bin/ffprobe",
    "work_directory": "/tmp/cns-rpi-video"
  }
}
```

三个路径要求非空且为绝对路径。程序通过固定 argv 启动子进程，不接收任意 shell 命令；不因启用配置而自动采集。采集、推流与验证异步轮询，不阻塞 MQTT、串口和 watchdog 主循环。正常退出终止并回收本进程拥有的子进程。

## MQTT 请求

请求 Topic 为 `{namespace}/{device_id}/experiment/set`，结果 Topic 为同设备的 `experiment/ack`，沿用 QoS 2、`retain=false` 和现有 ACK outbox。MQTT 发布调用成功只表示入队，完成回调到达后才移除待发 ACK；无处保存结果时不执行新的副作用。

五个固定操作：

| operation | 附加字段 | 结果含义 |
|---|---|---|
| `video_probe` | 无 | 异步等待摄像头枚举完成，再返回最终 ACK |
| `video_test` | `parameters` | 异步有限采集及 ffprobe 验证，完成后返回最终 ACK |
| `video_start` | `parameters`、`destination` | 完成 ACK 只表示推流子进程已启动，不证明编码、收流或播放成功 |
| `video_stop` | 无 | 异步停止并回收子进程，再返回最终 ACK |
| `video_status` | 无 | 返回当前 Pi 侧状态及已经取得的观测 |

所有请求均为 schema 1，公共字段严格限定为：

```json
{
  "schema_version": 1,
  "command_id": "11111111-1111-4111-8111-111111111111",
  "request_id": "22222222-2222-4222-8222-222222222222",
  "target": { "device_id": "DCDWCNS1GHC0G6LF8MY6" },
  "session_id": "33333333-3333-4333-8333-333333333333",
  "action_id": "22222222-2222-4222-8222-222222222222",
  "lease_version": 1,
  "operation": "video_probe",
  "expires_at": "2026-11-05T12:00:00.000Z"
}
```

上述 ID 和时点仅展示格式，不能直接发送。实际目标必须为当前绑定设备，Session、动作、租约和有效期由平台生成。`command_id/session_id/action_id` 为 UUID，`request_id=action_id`，租约版本为正整数；`expires_at` 为有效 UTC 毫秒时间。单个载荷最多 4096 字节，不接受未知键或错误类型。

`video_test` 和 `video_start` 必须增加完整的 `parameters`：

```json
{
  "camera": 0,
  "width": 1280,
  "height": 720,
  "framerate": 25,
  "bitrate_bps": 2000000,
  "duration_seconds": 3
}
```

| 参数 | 精确范围 |
|---|---|
| `camera` | 整数 0～3 |
| `width` | 偶数整数 64～1920 |
| `height` | 偶数整数 64～1080 |
| `framerate` | 整数 1～30 |
| `bitrate_bps` | 整数 100000～8000000，单位 bit/s |
| `duration_seconds` | test 为整数 1～10；start 为整数 1～1800 |

`video_start` 还必须增加完整的 `destination`：

```json
{
  "host": "media.example.com",
  "port": 8890,
  "stream_path": "g2/group01"
}
```

`host` 为 1～253 字符，由点分标签组成；每段 1～63 字符，首尾为英文字母或数字，中间可含连字符。不接受协议前缀、路径、空格、IPv6 冒号或结尾点。IPv4 地址按此语法接收，不在解析器中验证实际可达性。端口为整数 1～65535。`stream_path` 长 1～128，仅允许英文字母、数字、下划线、连字符、斜杠，不能以斜杠开头或结尾，不能包含双斜杠。

目的地最终形成 `srt://HOST:PORT?streamid=publish:PATH&pkt_size=1316`。这不等同于 MediaMTX 已配置或接收成功。其余三类操作不带 `parameters/destination`。

## 动作、Session 与观测语义

同 `action_id` 的等价重投只忽略 `command_id` 差异，不重复启动进程；相同动作内容冲突时拒绝。待完成操作重投可更新最终应答使用的 `command_id`。去重范围为当前进程内最多 128 项、300 秒，不写持久日志；进程重启后不保留动作去重记录，不承诺跨重启恰好执行一次。

当前摄像任务受所属 Session 与租约控制，其他 Session 不可停止它。当前进程保存设备级最高租约；较低版本及不同 Session 使用相同版本均被拒绝，新 Session 必须取得更高版本。忙时拒绝覆盖当前采集任务。显式停止可终止尚未完成的 probe/test，原动作返回 `cancelled`，stop 等退出回收后完成，各自保留终态。

ACK 沿用 `schema_version/command_id/session_id/action_id/operation/observed_at` 外壳及 `completed/rejected` 终态。拒绝返回 `error_code`。probe/test/stop 不在操作仍运行时伪造 completed。

`fact` 包含 `state/mode/process_running/pid`、配置 `parameters`、`cameras`、可空编码事实及 `exit_code`、有界 `diagnostic`。`run_id` 是本次或最近一次 probe/test/start 的 action_id，`owner_session_id` 是对应 Session。状态查询可观察设备最近一次运行，必须同时检查 `belongs_to_session=true` 且 `run_id` 等于期望运行，才可用于该组实验取证；另一组历史不会标为当前组证据。新启动失败也归属于本次尝试的 run_id。推流启动后再退出/失败，通过新的 `video_status` 动作查询，不改写已完成的启动 ACK。

控制器拒绝码包括 `video_disabled/action_expired/identity_unavailable/observation_unavailable/session_conflict/stale_lease/camera_busy/duplicate_conflict/start_failed`；异步任务还可能返回 `camera_not_found/process_failed/timeout/invalid_video/verification_failed/cancelled`。无法可靠关联身份或解析失败只记录诊断，不生成猜测 ACK。

观测必须分开解释：

- `capture_frames` 仅来自摄像进程的采集进度，不代表 H.264 编码帧数。
- `encoded_frames/encoded_duration_seconds/actual_width/actual_height/actual_codec` 只在有限文件经过 ffprobe 核验后提供。
- 实时 SRT 推流期间没有有限文件验证依据，`encoded_*` 等未知编码事实保持 `null`；配置码率不能称为实测吞吐量。
- 产品 MQTT 结果尚不提供接收字节、MediaMTX 收流、浏览器解码、端到端延迟或公网稳定性证据；这些字段不得用 Pi 进程状态代替。部署后的维护测试取得了 Pi 本机 SRT 接收文件证据，未实现远端接收观测字段。

## 有限采集与进程行为

使用 `rpicam-vid` 的 libav/MPEG-TS 模式，H.264 baseline、无预览、限定运行时长。当前已确认的 rpicam-apps 1.12.0 在该模式下不使用 `--save-pts`，不额外生成每帧 metadata。

`video_test` 写入本进程拥有的临时 TS 文件，采集结束后异步运行 ffprobe 计帧并读取 JSON。成功条件为 H.264、正编码帧数、实际宽高与请求一致；空文件、无帧、格式错误或尺寸不符不能报告通过。处理后只清理本任务拥有的临时文件。

probe 的超时为 10 秒；采集/推流上限为请求时长加 10 秒；ffprobe 阶段另有 10 秒上限；停止先发 SIGTERM，2 秒后仍未退出则 SIGKILL。持续排空子进程输出并限制保留诊断量，避免输出堵住主循环。子进程关闭非标准文件描述符，避免继承主进程的 UART 锁和 MQTT socket。活动视频、控制器待交付终态或实验 ACK outbox 非空时，现有配置更新返回 `control_command_busy`，待动作停止并交付结果后重试。

运行前需要带 libav/SRT 能力的 `rpicam-vid` 及 `ffprobe`；测试还需要 ffmpeg 与 Python 3。`scripts/install_deps.sh` 的 ffmpeg 包提供 ffmpeg/ffprobe，不替代树莓派系统的 rpicam 安装。当前目标为 Raspberry Pi OS / Debian 13；spawn 的非标准描述符关闭使用 glibc 2.34 起提供的接口，WSL Ubuntu 24.04 也支持。
