# 常规设备状态上报

修订日期：2026-11-11。

本帧供设备资料、在线状态和整机可用状态接入使用，直接替换原 `runtime/status/v1` 五字段运行三态载荷。本契约对应 v1.0.9 候选包，在原十字段基础上新增只读 `fault_modules`，形成十一字段；正式发布的 v1.0.8 安装包仍发送十字段。服务器解析、入库和 Web 修改入口另行接入。

## Topic 与频率

- Topic：`{namespace}/{device_id}/runtime/status/v1`，默认命名空间为 `cns_rpi`；沿用 `mqtt.topics.runtime_status`，不新增 Topic。
- QoS 1，`retain=true`。
- 有合法设备身份且 MQTT 已连接后立即发布，之后每 10 秒发布一次。
- MQTT 重连、载荷变化时立即发布；本地发布失败时下一轮重试，不推进周期。
- 发布不依赖 F407 当前在线或遥测通道开关。首次无身份时等待 F407，已有合法绑定缓存时可恢复上报。

原 runtime 的 `schema_version`、`control_status`、`business_status`、`identity_status` 不再出现在本帧。内部三态继续用于控制门禁和实验 ACK。registration、遥测和实验 ACK 格式不变；不向服务器的 `device/online/{device_id}` 发布。

## 十一字段定义

更新后的帧固定包含以下十一字段。不附加 `schema_version`；Topic 的 `/v1` 后缀保持不变，Pi 软件版本使用 `model_version`。示例使用本候选包的软件版本 `1.0.9`；正式发布的 v1.0.8 包不包含 `fault_modules`。

| 字段 | JSON 类型 | 含义与来源 |
|---|---|---|
| `device_id` | string | F407 提供的设备 SN，与 Topic 设备段相同；只读。 |
| `school_id` | string | 学校中文名，复用本地 `identity.school_name`，首次由交付方填写；未填写时为空字符串。 |
| `dcdw_label` | string / null | 优先取本地资料配置，否则取当前身份匹配的 F407 角色号，如 `DCDW-001`；尚未取得时为 null。 |
| `model_version` | string | Pi 应用软件版本，来自 CMake `PROJECT_VERSION`，当前候选为 `1.0.9`；只读。CNS 一代不支持 F407 固件更新，本字段不表示 F407 版本。 |
| `device_name` | string | 默认 `CNS 一代实训平台`，可由本地资料配置覆盖。 |
| `device_type` | string | 实体主控箱默认 `cns_box`，与注册协议一致；`xn_box` 仅用于虚拟箱子。可由本地资料配置覆盖。 |
| `capabilities` | string[] | 默认沿用 `telemetry`、`remote_id`、`runtime_config`、`box_private_control`，可由本地资料配置覆盖。 |
| `product` | object / null | 沿用 `manufacturer_code`、`model_code` 结构，当前产品为 `DCDW`、`CNS1`；优先取本地资料配置，否则取匹配身份的 F407 信息，尚未取得为 null。 |
| `online` | string | 只读，由 Pi MQTT 控制连接产生；`"0"` 在线，`"1"` 为主动离线声明或 Broker Last Will。与 F407 故障、维修、损坏分开。 |
| `device_status` | string | 整机状态：`"0"` 可用、`"1"` 维修中、`"2"` 损坏，按下文规则生成。 |
| `fault_modules` | string[] / null | 只读异常模块名称列表；当前已核验的离线／故障立即列出，已累计满 12 小时的致损模块保留到明确恢复。没有已确认异常为 `[]`；当前不可核验且没有保留的致损模块为 `null`。 |

`version` 和没有可靠来源的 `provisioned_at` 已删除，不发送占位 null。

Topic 示例：`cns_rpi/DCDWCNS1S2MEAG1VTA0C/runtime/status/v1`。以下为已取得匹配身份的模块数据、没有已确认异常时的合法 JSON 示例：

```json
{
  "device_id": "DCDWCNS1S2MEAG1VTA0C",
  "school_id": "示例职业技术学院",
  "dcdw_label": "DCDW-001",
  "model_version": "1.0.9",
  "device_name": "CNS 一代实训平台",
  "device_type": "cns_box",
  "capabilities": ["telemetry", "remote_id", "runtime_config", "box_private_control"],
  "product": {"manufacturer_code": "DCDW", "model_code": "CNS1"},
  "online": "0",
  "device_status": "0",
  "fault_modules": []
}
```

同一示例逐行解释如下。此处为便于阅读使用 JSONC，注释不属于实际 MQTT JSON：

```jsonc
{
  "device_id": "DCDWCNS1S2MEAG1VTA0C", // F407 的唯一设备 SN
  "school_id": "示例职业技术学院", // 学校中文名，由交付方首次填写
  "dcdw_label": "DCDW-001", // 学校内的角色号，不是全局唯一身份
  "model_version": "1.0.9", // 当前树莓派应用软件版本
  "device_name": "CNS 一代实训平台", // 给用户阅读的设备名称
  "device_type": "cns_box", // 常规状态帧中的箱子类型
  "capabilities": ["telemetry", "remote_id", "runtime_config", "box_private_control"], // 遥测、Remote ID、运行配置、主控箱控制能力
  "product": {"manufacturer_code": "DCDW", "model_code": "CNS1"}, // 厂家代码与产品型号代码
  "online": "0", // Pi MQTT 控制连接在线；离线声明为 "1"
  "device_status": "0", // 可用；"1" 维修中，"2" 损坏
  "fault_modules": [] // 没有已确认异常；不等于14个模块都已确认健康
}
```

## 本地资料配置与后续 Web 修改

学校名称使用现场配置 `identity.school_name`。其他资料使用可选顶层 `device_status` 对象，只允许 `device_name`、`device_type`、`dcdw_label`、`capabilities`、`product` 五项；未提供的项目继续使用默认值或匹配身份的 F407 信息。修改现场配置后重启业务进程生效，本次不新增热加载或 Web 修改入口。

```json
{
  "identity": {"school_name": "示例职业技术学院"},
  "device_status": {
    "device_name": "CNS 一代实训平台",
    "device_type": "cns_box",
    "capabilities": ["telemetry", "remote_id", "runtime_config", "box_private_control"]
  }
}
```

上例是资料配置片段，完整配置见 `config/config.example.json`。需要覆盖角色号或产品时，可增加非空字符串 `dcdw_label`，或包含非空 `manufacturer_code`、`model_code` 字符串的 `product` 对象。`device_name`、`device_type` 必须为非空字符串。`capabilities` 必须是字符串数组，元素不能为空；允许空数组并保持为空。覆盖值不会在上报时被 F407 后续信息替换。注册消息仍使用原资料来源，不随这些常规状态资料覆盖值变更。

`device_id`、`model_version`、`online`、`fault_modules` 只读，不接受本地资料覆盖或 Web 修改。其余字段后续需支持 Web 修改，流程为“Web 询问某参数是否允许修改 → 设备确认允许 → Web 下发修改值”；本次不设计、不实现握手和云端下发。维修标记仅预留内部 `HealthTracker::SetMaintenance` 接口，目前没有 MQTT 或 Web 调用入口，不能通过普通资料配置设为维修中。

## 异常模块明细

`fault_modules` 只输出模块名称字符串，不附加状态码、故障时间或错误码，按下表编号顺序排列且不重复：

| 编号 | 上报名称 | 中文含义 |
|---|---|---|
| 0 | `GNSS` | 卫星导航 |
| 1 | `IMU` | 惯性测量 |
| 2 | `BARO` | 气压计／环境 |
| 3 | `BATTERY` | 电源／电池 |
| 4 | `LORA` | LoRa 通信 |
| 5 | `5G` | F407 的 5G-A AT 连接管理 |
| 6 | `STORAGE` | SD／FatFs 存储 |
| 7 | `REMOTE_ID` | Remote ID 广播 |
| 8 | `DISPLAY` | 显示 |
| 9 | `CONTROL` | 控制命令预留模块 |
| 10 | `ALARM` | 告警 |
| 11 | `SYSTEM` | 系统健康 |
| 12 | `ESTIMATOR` | 姿态／导航估计 |
| 13 | `BUSINESS` | 业务应用 |

- 仅 F407 已核验模块的 `OFFLINE(4)`／`FAILED(5)` 立即进入列表，不必等 12 小时。故障尚未累计满 12 小时，`device_status` 仍可为 `"0"`。
- `UNINITIALIZED(0)`／`STARTING(1)` 不当作故障；恢复 `ONLINE(2)`、`DEGRADED(3)` 或 `DISABLED(6)` 会结束该模块本次故障并移出列表。降级、主动关闭不计异常。
- 已累计满 12 小时的模块继续列出，即使重启、F407 断开或身份暂不可核验；只复用同一绑定设备的既有健康进度，不改变健康文件格式。这样 `device_status="2"` 时仍能指出已确认的致损模块。
- 身份不可核验或模块数据缺失，且没有保留的致损模块时，返回 `null`。有可核验模块数据但没有已确认异常时返回 `[]`；部分模块尚未收到或正在启动时，`[]` 不表示 14 个模块全部健康。
- 维修中仍保留实际异常列表。F407 整链路离线不会伪造成 14 个模块全部故障；本字段的 `5G` 是 F407 模块，不能当作树莓派拨号服务的状态。

例如 GNSS 和 IMU 已报告离线／故障，均未累计满 12 小时时，同一 Topic 上报以下帧；此为协议示例，不是新增字段的实机采集记录：

```json
{
  "device_id": "DCDWCNS1S2MEAG1VTA0C",
  "school_id": "示例职业技术学院",
  "dcdw_label": "DCDW-001",
  "model_version": "1.0.9",
  "device_name": "CNS 一代实训平台",
  "device_type": "cns_box",
  "capabilities": ["telemetry", "remote_id", "runtime_config", "box_private_control"],
  "product": {"manufacturer_code": "DCDW", "model_code": "CNS1"},
  "online": "0",
  "device_status": "0",
  "fault_modules": ["GNSS", "IMU"]
}
```

若其中 GNSS 累计达到 12 小时，整机状态变为 `"2"`；随后 F407 断开或设备重启，在重新核验前仍保留 `"GNSS"` 作为致损原因。若从未取得模块数据且没有致损进度，则为 `fault_modules=null`。

## 整机状态与故障累计

| `device_status` | 含义 | 规则 |
|---|---|---|
| `"0"` | 可用 | 一切正常时为可用；模块故障未累计满 12 小时仍为可用，实际故障由模块明细显示。 |
| `"1"` | 维修中 | 维修标记优先于自动判断，保持到显式解除；后续只允许云端设置、解除，云端入口尚未接入。 |
| `"2"` | 损坏 | 任一模块的连续失效进度累计到 12 小时运行故障时间；不同模块时长不相加。 |

14 个 F407 模块分别计时，仅 `OFFLINE`（4，离线）和 `FAILED`（5，故障）累计；4 与 5 相互切换继续累计。未收到模块状态、`UNINITIALIZED`（0）和 `STARTING`（1）暂停并保留进度。`ONLINE`（2）、`DEGRADED`（3）和 `DISABLED`（6）结束该模块连续故障并清零；降级和主动关闭均不计入故障，之后再次故障重新累计。

计时使用单调时钟，只累计设备运行期间已观测的故障时间。串口或身份暂不可核验时暂停；MQTT 断开本身不停止已核验模块的运行故障累计。健康进度独立于瞬时遥测缓存和 MQTT 会话，重连、串口恢复或进程重启不清零持久进度。重启后首次采样只建立时间基准，不补算关机的自然时间。

健康文件路径为 `identity.binding_file` 追加 `.health.json`，默认 `/var/lib/cns-rpi/device_binding.json.health.json`。文件包含 `schema_version=1`、绑定的 `device_id`、14 个模块的 `failure_ms` 数组及布尔型 `maintenance`。每项最多累计 43,200,000 毫秒（12 小时）；加载时只恢复同一设备进度，不借用其他 F407 的故障或维修标记。

主循环每 60 秒、整机健康等级变化时，以及正常退出时保存，采用临时文件加原子重命名。突然掉电可能丢失最后一个未保存检查点，正常运行且保存成功时最多约 60 秒；写入失败会记录错误，不能据此承诺已保存。维护时应连同配置和绑定文件备份健康文件，不要通过删除健康文件清除维修或故障进度。

## 离线声明与服务器接入

正常退出或通常的主动关闭 MQTT 会话时，向同一 Topic 发送十一字段离线帧，`online="1"`，其他资料、整机状态和最近一次异常模块明细保留。`PublishAndWait` 最多等待 2 秒，超时仍继续退出或关闭，不承诺离线消息必达。因整机健康等级变化而刷新遗嘱的连接重建是例外：主动断开时不发布中间离线帧，重连后立即上报最新在线状态。

唯一 Last Will 使用同一 Topic、十一字段、QoS 1、`retain=true`，`online="1"`。整机健康等级变化时，程序重建 MQTT 连接，刷新遗嘱中的 `device_status`。`fault_modules` 和其他元数据仍是建立该连接时的快照；仅异常列表变化不额外重连，之后取得的新明细、角色号或产品信息不会自动改写 Broker 保存的遗嘱，其值可能为 null 或早于最近在线帧，不能据此清除、回退平台已有资料或认定旧故障已恢复。

异常掉电、强制终止或网络中断时，由 Broker 检测异常断开后交付遗嘱，不承诺立即到达。retained 消息仅表示最近声明，接收端应结合后续实时消息和接收超时判断在线状态。`dcdw_label`、`product` 的 null 表示“设备尚未掌握该事实”，不提供清空资料的指令。

服务器旧 runtime 解析器需要按本契约调整。本次范围为 Pi 端代码、测试和文档，不代表 Server/Web 已接入。

## 验证范围

本次新增字段的验证范围为十一字段 JSON、模块固定顺序与只读规则、即时异常、未知与空列表、致损原因跨重启保留、维修优先和遗嘱快照；10 秒周期、12 小时故障计时、内部三态、控制门禁及实验 ACK 继续回归。本契约对应 v1.0.9 候选包，实际构建、测试和设备部署结果以相应 CI 与验收记录为准；契约示例不代表实机验证结果。

2026-11-09 完整验证结果：WSL Ubuntu 24.04 / GCC 13 构建通过，`-Wall -Wextra` 无警告或错误；65/65 项 CTest、额外 16/16 项拨号脚本测试通过。真实进程 MQTT 用例 109 条断言通过，覆盖自定义资料、已保存损坏状态启动为 `"2"`、维修状态启动为 `"1"`、实际由可用跨阈值变为损坏后 SIGKILL 遗嘱仍为 `"2"`，以及首次绑定恢复后的实验订阅。

12 小时边界使用可推进单调时间的真实类测试和临界进度 fixture 验证，没有让实物设备实际运行满 12 小时。本机软件回归不代表实物 Pi、真实 F407、ARM64 包、公网 5G 或 Server/Web 验收。本地实现验证阶段未推送、未运行 ARM64 CI，未部署到设备或服务器；后续提交及远程 CI 结果以仓库记录为准。
