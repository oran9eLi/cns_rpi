# V1.0.7 发布说明

版本：`v1.0.7`。日期：2026-11-06。

在已有 `1.0.6` F407 专用主线及远程维护、ARM64 CI/发布包体系上合入 G2 视频实验。上一公开 Release 为 `v1.0.5`；主线 `1.0.6` 未单独创建 Release。本版本不修改 F407 固件或服务器代码，不恢复 PX4/QGC 能力。

## 主要变化

- 增加 `video_probe/video_test/video_start/video_stop/video_status` 五项操作，沿用设备的 `experiment/set`、`experiment/ack`、Session/租约和 QoS 2 待发结果队列，不新增 Pi 业务身份。
- 摄像子进程异步运行并停止回收，有限 TS 采集由 ffprobe 验证 H.264、尺寸和编码帧数；SRT 启动 ACK 仅证明进程已启动，接收及播放须另行取证。
- 摄像任务按 Session 管理，进程内等价动作去重；配置更新等待活动摄像任务及尚未交付的实验结果处理完成。
- `video` 配置默认关闭，旧配置缺少该对象可继续加载。CI 构建及发布运行依赖补充 `ffmpeg`，运行容器检查 `ffprobe` 可用。
- 保留主线的 F407 单设备接入、绑定身份与串口复核、业务/拨号分组件更新、校验与失败回退、普通可写根目录部署方案。

接口、参数、结果语义与限制见 [G2 树莓派视频实验接口](G2树莓派视频实验接口与本地验证.md)。

## 安装与启用

目标为 Raspberry Pi 5、trixie / ARM64。使用随 Release 发布的 ARM64 包、SHA-256、manifest 和 bootstrap 入口，按 [部署手册](远程更新部署手册.md)导入服务器并安装；原现场配置、绑定及实验状态保留，不使用样例覆盖。

`ffmpeg` 运行依赖提供 `ffprobe`。启用视频还要求设备预装支持 libav/MPEG-TS/SRT 的 `rpicam-vid`、正确连接 CSI 摄像头，且业务服务用户具备摄像设备权限。该 Pi 专用工具不随通用 Debian 发布包提供。现有设备的普通 `app` 更新不安装系统依赖，须在启用前单独准备工具；首次 bootstrap 和新工厂镜像按 manifest 安装运行依赖。

在已有现场配置中启用：

```json
{
  "video": {
    "enabled": true,
    "executable": "/usr/bin/rpicam-vid",
    "ffprobe": "/usr/bin/ffprobe",
    "work_directory": "/tmp/cns-rpi-video"
  }
}
```

按现场配置流程重启主服务后才加载该开关；启用不会自行开始持续推流。首次没有真实 F407 身份绑定时仍不会建立生产设备 MQTT 会话。已有合法绑定的设备即使 F407 业务暂时离线，也可按现有视频门禁处理 Pi 本地动作。

## 验证与已知边界

合并后的 `1.0.7` 候选代码在 Ubuntu 24.04 WSL / x86_64 构建通过，`-Wall -Wextra` 无告警；完整 CTest **62/62** 通过，耗时 58.49 秒，使用隔离真实 Broker 验证收发与断线重连；另有 **16/16** 项拨号脚本测试通过。独立复审确认主线集成及发布依赖均无剩余阻断项。首次检查发现版本测试仍期待 1.0.6，更新为本版本后重新跑完整套件通过。

合并前 G2 开发分支已重新验证 WSL CTest **57/57**。11 月 5 日源码快照曾在实体 Pi 完成 ARM64 专项 **9/9**、65 帧 720p H.264 实拍及 66 帧本机 SRT 收流，见 [当日记录](2026-11-05-G2树莓派部署与实拍验证.md)。这些是合并前证据；本次发布产物的验证以对应提交的 CI、Release 测试日志和产物摘要为准。

本次合并发布不进行现场升级，不将开发快照实拍或服务器工作线的云端视频测试当成本发布包的生产 MQTT、浏览器或长期稳定性验收。原生 GCC 14 优化构建已有的时间戳格式截断告警仍按 CI 日志记录，未扩大本次范围修复。

## 回退

升级和回退前先结束活动实验及摄像任务；业务组件使用已有安装器回退至上一已验证版本，普通业务回退不重启拨号。回退到不支持视频的版本后，平台应停止下发五项视频操作。保留原配置和依赖；如需更改视频开关，使用现场配置流程操作。
