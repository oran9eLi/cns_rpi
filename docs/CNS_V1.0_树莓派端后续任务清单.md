# CNS V1.0 树莓派端待办

日期：2026-09-17。依据：`/home/oran9e/CNS_V1.0_总体目标与开发边界.md`。本清单仅覆盖树莓派端，按一次可独立提交、验证的工作划分。当前已发布的 `v1.0.0` 是现状基线，下述 mavlink-router 双支路是**待实施架构**，不能作为已完成功能。

## 当前已经完成

| 能力 | 当前状态 |
|---|---|
| 受控设备接入 | 主程序可自动发现 MAVLink 串口，识别一台主控箱或 PX4，串口拔插后重新发现；目前由主程序直接持有串口。 |
| 身份与在线 | 从受控设备获取身份，向服务器注册在线/离线；PX4 身份可主动请求。 |
| 业务数据 | 已解析部分标准飞行遥测和主控箱业务数据，重组 JSON 并以快照、实时两种频率上报。 |
| 控制与配置 | 主控箱命令下发及执行回执、运行参数持久化与服务重启已经接入；这些命令不是 QGC 的飞控通道。 |
| 本地 QGC | 存在可选的同局域网 QGC 转发，默认关闭；尚无经 CNS Server 的远程 QGC 透传。 |
| 运行维护 | 5G 链路监测与自恢复、日志限制、服务自启和一键部署已有实现。 |

## 为达到 V1.0 目标还要完成

以下每行对应一个相对独立的提交目标。顺序表示依赖关系，不表示工期。**服务端制定注册握手协议；树莓派端收到协议后实现并遵守，不预先规定握手报文。** 5760 是已指定的服务器入口端口；连接方式和握手细节以服务端协议为准。

| 编号 | 树莓派端任务 | 完成后应看到的效果 | 前置或跨端依赖 |
|---|---|---|---|
| P1 | 让 mavlink-router 独占飞控/主控箱串口 | 同一串口只有路由器持有；设备上电、串口重枚举和重启后，路由器能恢复输入；原主程序不再抢占串口 | 需确定现场主控箱、飞控的连接方式 |
| P2 | 将现有业务解析接到路由器的第一路 | 原有身份识别、JSON 快照/实时上报持续工作，业务字段及服务器现有设备记录不退化 | 路由器输入可用；Server 消费现有业务数据 |
| P3 | 恢复业务支路的双向交互 | 主控箱已有控制与回执、PX4 身份请求、树莓派心跳等需要回到设备的消息仍能正常往返 | P1、P2；主控板与飞控按现有行为响应 |
| P4 | 完成服务器端口 5760 的连接准备与状态管理 | 树莓派能建立、维护并识别远程透传连接的可用状态；连接失败不拖垮业务上报 | CNS Server 开放并明确 5760 入口的连接约定 |
| P5 | 按服务器注册协议完成透传前握手 | 握手成功后远程透传才可开始；握手失败、超时或身份不符时不会向服务器发送飞控数据或接收飞控控制 | **CNS Server 先发布并实现注册握手协议**；设备身份可获取 |
| P6 | 建立飞控到服务器的原始 MAVLink 上行透传 | QGC 经 Server 能持续收到飞控完整消息，不受业务 JSON 解析字段范围限制 | P5；Server 建立对应转发支路 |
| P7 | 建立服务器到飞控的原始 MAVLink 下行透传 | QGC 经 Server 发出的合法飞控交互能到达目标飞控并收到响应 | P5、P6；Server 负责目标会话与下行转发 |
| P8 | 保证单机单 QGC 的目标与会话一致 | 断开、重连或设备更换后，旧连接不能把数据或控制送到另一台设备 | Server 提供会话归属与状态规则；单 QGC 接入约束 |
| P9 | 处理两路并行与故障恢复 | QGC Mission 交互期间 JSON 遥测仍持续；透传断开后重新连接并重新握手，业务支路独立恢复 | P2～P8；Server 配合断连和重连 |
| P10 | 更新部署与运行配置 | 新树莓派一次部署可安装并自启动串口路由、业务程序和 5G 服务；重启后两路都恢复，现场参数保留 | P1～P9；现场网络与设备可用 |
| P11 | 联调 Web 所需的设备和飞行状态 | Web 能显示在线状态、位置、实时航迹、高度、速度、航向、电量及飞行模式；缺失或中断不会伪装为实时数据 | Server/Web 共同核对数据与展示；飞控提供数据 |
| P12 | 联调 QGC 全程任务闭环 | QGC 不与树莓派同局域网，也能经 Server 连上飞控，读取参数、规划和上传/读回 Mission、启动执行，并持续看到实时遥测；Web 同时更新航迹和 CNS 状态 | P1～P11；Server、Web、飞控、QGC 和主控板共同联调 |

P1～P12 均属 **V1.0 必须完成**。当前主控箱与飞控在一台树莓派上是二选一接入；如果最终演示要求同一时刻看到两者在线，需要各端先确认设备组成及对应树莓派数量，不能把单串口路由改造误认为已经解决该问题。

## 可延后

OTA 与周期自动检查更新、多机/多 QGC、动态通道、更多飞控型号、高级可视化和千设备容量测试，均不阻断本次单机 Mission 闭环。现有同局域网 QGC 功能可作为历史能力保留，但不充当 P6～P12 的远程链路验收结果。

本清单不制定握手协议，也不将 Mission 等飞控或 QGC 内部功能列为树莓派端开发任务。
