# 设备状态发布、内部三态与验收

修订日期：2026-11-11。

本文说明 F407 主控箱的常规设备状态帧、内部运行三态、固定身份绑定与验收方法。原 `runtime/status/v1` 五字段运行三态载荷由常规帧替换；本次在十字段基础上新增 `fault_modules`，以下为十一字段契约，新增字段尚未发布部署。现有 v1.0.8 安装包仍发送十字段。当前字段契约以 [常规设备状态上报](常规设备状态上报.md) 为准。内部三态继续用于控制门禁和实验 ACK；实验 Session 另见相应实验契约。

## 1. Topic 与载荷

主控箱发布 Topic：

```text
{namespace}/{device_id}/runtime/status/v1
```

- QoS：1；
- Retain：true；
- 连接后立即发布，之后每 10 秒发布一次；
- 载荷内容变化时立即发布，本地发布失败时下一轮重试，不推进周期；
- MQTT 每次成功连接或重连后，即使值未变化也重新发布当前在线状态。

更新后的载荷固定包含以下十一字段，未知角色号和产品资料为 null，不附加 `schema_version`。下例已取得模块数据，且没有已确认异常；示例版本号不表示已发布 v1.0.8 包包含新增字段：

```json
{
  "device_id": "DCDWCNS1EXAMPLE00001",
  "school_id": "示例职业技术学院",
  "dcdw_label": "DCDW-001",
  "model_version": "1.0.8",
  "device_name": "CNS 一代实训平台",
  "device_type": "cns_box",
  "capabilities": ["telemetry", "remote_id", "runtime_config", "box_private_control"],
  "product": {"manufacturer_code": "DCDW", "model_code": "CNS1"},
  "online": "0",
  "device_status": "0",
  "fault_modules": []
}
```

`online="0"` 表示 Pi MQTT 控制连接在线；`online="1"` 为主动离线声明或 Broker Last Will。`school_id` 取现场 `identity.school_name` 学校中文名。`device_status` 使用 `"0"` 可用、`"1"` 维修中、`"2"` 损坏：模块运行故障累计满 12 小时自动损坏，维修标记始终优先于自动判断。名称默认 `CNS 一代实训平台`；名称、类型、角色号、能力和产品信息支持可选 `device_status` 本地资料配置，配置后重启生效。

`fault_modules` 为只读 `string[] / null`：离线／故障立即列出模块名，例如 `["GNSS", "IMU"]`，不必等到 12 小时；降级和主动关闭不计。已累计满 12 小时的致损模块在重启、F407 断开或身份暂不可核验时仍列出，到明确恢复在线、降级或主动关闭才清除。没有已确认异常时为 `[]`，不代表全部模块已确认健康；不可核验或缺失模块数据且没有保留的致损模块时为 `null`。维修中仍报实际列表，不将 F407 整链路离线伪造为全部模块故障。名称及中文对照见 [异常模块明细](常规设备状态上报.md#异常模块明细)。

`model_version` 使用 Pi 软件的 CMake `PROJECT_VERSION`，当前为 `1.0.8`；CNS 一代不支持 F407 固件更新，本字段不表示 F407 版本。`version`、`provisioned_at` 已删除。设备 ID、Pi 版本、在线声明和异常模块明细只读，不接受本地资料或 Web 覆盖。Web 修改握手与云端下发尚未实现，维修仅预留内部设置/解除接口。详细计时、持久化和资料配置见 [常规设备状态上报](常规设备状态上报.md)。

registration 格式和资料来源继续沿用原约定，其中 `device_type` 仍为 `cns_box`。服务器旧 runtime 解析器须按新契约调整；本次只修改 Pi 端，不代表 Server/Web 已接入十一字段帧。

## 2. 内部三态与变化规则

下列 `control_status`、`business_status`、`identity_status` 保留为进程内部状态和 `inspect_pi_link` 等实验 ACK 的事实，不再作为 runtime 五字段帧发布。正常状态上报不依赖 F407 当前在线，也不依赖遥测通道是否启用。

### 2.1 控制链

MQTT 已连接时，内部 `control_status` 为 `online`，常规帧发布 `online="0"`。正常退出或通常的主动关闭 MQTT 会话时，尝试发布十一字段 `online="1"` 帧，最多等待 2 秒；超时仍继续关闭。registration 继续沿用原格式发布离线声明，不承诺任一离线消息必达。整机健康等级变化触发的遗嘱刷新是例外：程序主动重建 MQTT，不发送中间离线帧，重连后立即发布最新在线状态。

### 2.2 F407 业务链

有效业务帧必须同时满足：MAVLink CRC 校验通过、来自已识别的 F407 端点，并被现有标准遥测或主控箱扩展解码器识别。现有标准遥测（包括 HEARTBEAT）及可识别的 `NAMED_VALUE_INT`、`TUNNEL` 会刷新业务时间；身份帧、`COMMAND_ACK`、未知帧及 Pi 主动发送帧不刷新。

- 启动后尚无业务事实时为 `unknown`；
- 收到有效业务帧后立即变为 `online`；
- 距最后一条有效业务帧满 10 秒后变为 `offline`；
- 新有效业务帧到达后立即恢复为 `online`。

串口读写失败、USB 重新枚举或 10 秒静默只清理串口端点和瞬时遥测，不关闭已由主控箱绑定恢复的 MQTT 控制入口。重新收到 HEARTBEAT 只证明链路端点存在，不能继承旧链路的身份核验资格；必须收到与缓存一致的新 Basic ID 后才恢复主控箱控制和遥测。此时配置命令仍可接收；主控箱控制命令返回链路不可用或身份未核验，不向不确定设备发送。身份未核验或冲突期间的普通业务帧不写入共享遥测缓存。

### 2.3 身份核验

- `verified`：当前真实 Basic ID 与持久化绑定一致；
- `cached`：存在合法缓存，但本次启动尚未重新取得匹配的真实身份；
- `conflict`：当前真实身份与缓存冲突；保持原 Topic 和原绑定，不上传冲突设备遥测，也不向其下发主控箱命令；
- `unbound`：从未成功持久化合法身份。

## 3. 身份绑定文件

默认路径为 `/var/lib/cns-rpi/device_binding.json`，可通过 `identity.binding_file` 指定。示例配置已经包含该路径，启动日志会打印实际应用路径。

文件只保存固定配对事实，不保存在线状态、串口设备号、MAVLink sysid/compid、遥测或 MQTT 状态：

```json
{
  "schema_version": 1,
  "device_id": "DCDWCNS1EXAMPLE00001",
  "device_type": "cns_box"
}
```

首次没有绑定时，程序只接受真实且合法的 F407 Basic ID，并以临时文件加原子重命名方式建绑；配置文件不能预填或猜测 `device_id`。首次候选落盘失败后不会接受另一个身份替换该候选，落盘结果也必须与当前观测身份一致。重启时合法缓存用于恢复原设备 MQTT Topic，但不代表 F407 在线。真实身份重新出现后必须核对；冲突不会覆盖文件。绑定文件仍只记录配对事实，不保存常规帧里的在线声明或未知资料。

只有维修更换固定配对的 F407 时，维护人员才可在现场停止服务、备份并清除绑定：

```bash
sudo systemctl stop cns-rpi.service
sudo cp -a /var/lib/cns-rpi/device_binding.json \
  /var/lib/cns-rpi/device_binding.json.bak
sudo rm /var/lib/cns-rpi/device_binding.json
sudo systemctl start cns-rpi.service
```

清除后必须从新 F407 的真实 Basic ID 重新建绑。不得把此操作做成远程自动换绑、普通用户按钮或冲突自动恢复逻辑。

## 4. MQTT Last Will

主控箱在发起 Broker 连接前设置唯一 Last Will，与正常状态帧使用相同 Topic、十一字段结构、QoS 1 和 `retain=true`，其中 `online="1"`，名称和 Pi 软件版本仍在。例如只有绑定身份、尚无模块数据、角色号和产品信息，且没有已保存致损故障或维修标记时：

```json
{
  "device_id": "DCDWCNS1EXAMPLE00001",
  "school_id": "示例职业技术学院",
  "dcdw_label": null,
  "model_version": "1.0.8",
  "device_name": "CNS 一代实训平台",
  "device_type": "cns_box",
  "capabilities": ["telemetry", "remote_id", "runtime_config", "box_private_control"],
  "product": null,
  "online": "1",
  "device_status": "0",
  "fault_modules": null
}
```

整机健康等级变化时，程序重建 MQTT 连接以刷新遗嘱中的 `device_status`。`fault_modules`、角色号和产品等仍以该连接建立时的快照为准；仅异常列表变化不额外重连，之后取得新信息不会自动刷新已保存遗嘱。异常断线帧中的明细可能为 null 或早于最新在线帧，不能据此清除或回退已有资料、认定故障已恢复。null 表示设备尚未掌握可核验的事实；名称和 Pi 软件版本始终为字符串。

异常掉电、强制终止或网络中断时，Broker 在检测到异常断开后交付遗嘱，不承诺立即到达。retained 帧只表示最近一次声明，新订阅者不能把历史 retained `online="0"` 当作新心跳；接收端应结合后续实时消息与接收超时判断当前在线状态。

周期状态发布使用非阻塞接口，失败不阻断 registration、入站命令、串口发现/接收或遥测调度。需要离线声明的正常关闭会话才对离线帧做最多 2 秒的有界等待；健康变化刷新遗嘱时不发送中间离线声明。

## 5. 升级与配置检查

升级前记录当前提交并备份现场配置、绑定和健康进度文件：

```bash
cd /home/dcdw/cns_rpi
git rev-parse HEAD
sudo cp -a /var/lib/cns-rpi/config.json /var/lib/cns-rpi/config.json.bak
sudo cp -a /var/lib/cns-rpi/device_binding.json \
  /var/lib/cns-rpi/device_binding.json.bak 2>/dev/null || true
sudo cp -a /var/lib/cns-rpi/device_binding.json.health.json \
  /var/lib/cns-rpi/device_binding.json.health.json.bak 2>/dev/null || true
git pull --ff-only
./scripts/deploy.sh
./build/cns_rpi /var/lib/cns-rpi/config.json --check-config
systemctl status cns-rpi.service --no-pager
journalctl -u cns-rpi.service -n 100 --no-pager
```

旧现场配置缺少 `mqtt.topics.runtime_status` 或 `identity.binding_file` 时，当前加载器使用固定兼容默认值；仍应在维护窗口把示例中的对应段同步到现场配置，便于审计。runtime suffix 固定为 `runtime/status/v1`、QoS 固定为 1，配置加载时会拒绝改变跨端契约的值。

回滚到 V1.0.0：

```bash
cd /home/dcdw/cns_rpi
sudo systemctl stop cns-rpi.service
git fetch --tags origin
git switch --detach v1.0.0
./scripts/deploy.sh
systemctl status cns-rpi.service --no-pager
```

回滚不删除绑定备份。若之后重新升级，恢复目标分支或提交并再次执行部署脚本。真实密码、密钥和机器专用配置不得写入仓库或验收记录。

## 6. 真机验收与原始证据

先在可访问 Broker 的运维终端持续订阅，并把原始消息保存为证据：

```bash
mosquitto_sub -h <broker地址> -p <端口> \
  -u '<用户名>' -P '<密码>' \
  -t '<namespace>/+/runtime/status/v1' -q 1 -v \
  | tee runtime-status-raw.log
```

未启用认证时省略 `-u/-P`。验收按以下顺序执行：

1. 正常启动并连接原配 F407。确认首次连接后收到十一字段 `online="0"`，学校名称与现场配置一致，名称为配置值或默认 `CNS 一代实训平台`，软件版本为当前 Pi 软件的 `PROJECT_VERSION`，且没有 `version` 或 `provisioned_at`；之后持续收到约 10 秒周期帧，重新订阅可读取 retained 声明。尚无可核验模块数据且无致损进度时 `fault_modules=null`，取得模块数据且无已确认异常后为 `[]`。
2. 停止或断开 F407 业务超过 10 秒，确认 Pi MQTT 仍在线、常规帧仍为 `online="0"` 并持续周期发布；通过合法 `inspect_pi_link` 的 ACK 单独检查内部业务离线与身份事实。没有保留的致损原因时异常模块明细变为 `null`，已有致损模块时继续列出，不伪造全部模块故障。不要把常规帧的在线值当作 F407 业务正常。
3. 恢复原 F407，核对新业务帧与匹配 Basic ID。内部三态、普通控制门禁和实验 ACK 的恢复分别留证；常规帧在资料或异常模块明细变化时立即重发，不新增三态字段。
4. 正常停止业务进程，记录主动十一字段 `online="1"`，核对资料、整机状态和最近异常模块明细保留；同时检查离线发布失败时进程仍可在有界等待后退出。成功收到一帧不能证明所有断网情况都必达。
5. 在隔离 Broker 或维护窗口异常终止进程，或断开 Pi 网络，等待 Broker 检测中断并交付十一字段 `online="1"` 遗嘱。核对名称、Pi 软件版本、已保存整机状态；异常模块明细、角色号和产品取该连接建立时可得值，不把旧快照当作已恢复。考虑 systemd 自动重启可能很快覆盖离线声明。
6. Pi 重连后应立即发布十一字段 `online="0"` 覆盖离线声明，随后恢复周期上报。重新订阅收到旧 retained 在线值时，验证接收端不会单独将其作为设备当前在线证明。
7. Server/Web 按新契约接入后，再保存 MQTT 接收日志、资料字段合并结果、在线判定、REST 和 WebSocket 原始事件；核对 null 不清空已有资料、遗嘱不回退资料。该跨端验收尚不能用 Pi 本地结果代替。

故障累计单独留证：验证离线/故障模块立即进入 `fault_modules`，累计未满 12 小时时整机仍可用，满 12 小时报损坏；不同模块时长不能拼接，多个模块按固定编号顺序排列且不重复。重启后续计且关机不计，已致损模块名在重启或断开 F407 后保留；恢复、降级、主动关闭清零并移出列表，未知/启动暂停。维修中仍显示实际异常，普通资料配置不能覆盖 `fault_modules`。检查健康文件与 MQTT 重连后的遗嘱状态；仅列表变化不得额外重连。维修优先及解除当前通过内部真实类测试验证，不能声称云端已可操作。自动测试可注入单调时间验证边界，不能替代实体设备持续运行及掉电验收。

每组证据至少记录树莓派提交、配置路径、绑定文件是否存在、MQTT Topic、完整原始 JSON、Broker/Server 接收时间以及对应操作。软件回归、本机 Broker、实体 Pi、真实 F407 与 Server/Web 验收分别记录，不将本节验收步骤当作已完成结果。
