# GNSS 实验接口

日期：2026-11-10

## 变更

Pi 在唯一 F407 串口接收流程中恢复 `TUNNEL/0x8020` 分片，对完整原文核对 CRC16-CCITT-FALSE。NMEA 的 CR/LF、UBX 的零字节和接收机标记校验失败的完整报文均保留。官方生成的 MAVLink 文件未修改。

新增 `gnss_capture_start`、`gnss_capture_stop`、`gnss_status`，沿用箱子身份和实验动作信封；原始报文以 QoS 1、非保留批次发布到 `{namespace}/{device_id}/gnss/raw/v1`，不进入普通遥测快照。采集有时长、队列与档案上限，断链结束当前采集，不自动恢复采集或从档案补发。

普通定位沿用现有 `GPS_RAW_INT` 解码与 `telemetry.gps`。F407 已由用户确认改造，本轮没有修改或构建 STM32 固件，也未实现 Pi 定位协议解析。

配置新增可选 `gnss`，默认关闭。服务端协议、课堂流程和启用步骤见 [GNSS实验接口与服务器对接](../GNSS实验接口与服务器对接.md)。架构入口同步到 README 与 V1 设计文档。

## 验证

实施前基线：WSL Ubuntu 24.04、GCC 15、Release 构建，全量 CTest 69/69 通过。最终 Release 构建无编译警告，全量 CTest 73/73 通过，用时 81.32 秒；GNSS 真实进程/PTY/Broker 集成实际执行通过，覆盖普通定位连续性、原字节、启停、自动结束、断网重连和串口断开。详见 [验证记录](../validation/2026-11-10-gnss-pi.md)。

## 交付边界

初次开发在隔离分支 `codex/gnss-experiment` 完成，软件测试使用 PTY 和本地 Broker。后续按用户指令合并 main、推送 CI 并部署；现场部署与配置启用单独留存结果。实体 GNSS/F407/Pi 与服务器、网页的完整联调分别验收，不将模拟输入等同于实测定位表现。
