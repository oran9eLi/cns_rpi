# 变更记录：QGC 局域网自动连接与 5G 并行

日期：2026-07-29

## 变更摘要

在不改变飞控固件、服务器和现有 5G/MQTT 上报链路的前提下，为 PX4 真实飞控新增
同一局域网 QGroundControl 双向 MAVLink UDP 支路。树莓派仍由 `cns_rpi` 单进程独占
飞控串口，不引入第二个串口进程。

## 影响范围

- `docs/V1设计文档.md` 第 2 节：补充 PX4 接入后的 QGC 并行数据流。
- `src/network/qgc_udp_bridge.*`：新增非阻塞 UDP、LAN 子网发现、单 QGC 锁定和超时释放。
- `src/main.cpp`：仅在识别为 PX4 且配置启用时启动桥接；QGC 下行沿现有串口发送。
- `src/config/app_config.*`：新增可选 `qgc_udp` 配置；段缺失时默认关闭。
- `src/uart/mavlink_link.cpp`：有界读取先排空已组装帧，避免 5 ms 轮询下的额外等待。
- `config/config.example.json`：补充完整配置模板。

主控箱解析、身份模型、MQTT topic、遥测发布周期、服务器接口和 Web 数据结构均未改变。

## 关键约束

- 只允许配置列出的 LAN 接口参与发现，默认 `wlan0`、`eth0`，不包含 5G `usb0`。
- 未选择 QGC 时只广播 PX4 HEARTBEAT；选择后发送全部合法 PX4 MAVLink 帧。
- 只接受当前 LAN 子网内且 CRC 合法的 MAVLink 数据报；同时只锁定一个 QGC。
- `allow_commands=false` 可只看遥测；设为 `true` 才把 QGC 参数、校准、航线和控制帧写回飞控。
- UDP 发送非阻塞、无无限缓存，局域网故障不得拖慢串口、MQTT 或 Web 链路。

## 验证结果

- Ubuntu 26.04 WSL，C++23，`-Wall -Wextra` 完整构建通过，无新增编译警告。
- `ctest --output-on-failure`：32/32 测试通过。
- 新增测试覆盖：
  - CRC 错误帧不能建立 QGC 端点；
  - 合法同网段端点学习与 PX4 帧单播；
  - `allow_commands=false` 只读隔离；
  - QGC 超时释放；
  - 旧配置缺少 `qgc_udp` 时默认关闭；
  - 简短回滚配置；
  - 已组装串口帧在有界轮询前优先排空。
