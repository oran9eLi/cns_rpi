# 变更记录：主控箱与 PX4 统一身份数据结构

日期：2026-08-03

设计文档：`docs/2026-08-03-主控箱与PX4统一身份数据结构设计.md`

## 变更摘要

主控箱和 PX4 统一使用 `OPEN_DRONE_ID_BASIC_ID.uas_id` 作为唯一业务主键
`device_id`，删除 `vendor_id`、`remote_id`、PX4 `uid/uid2`、`gateway_id` 和
`rpi_serial` 这几套并行编号。树莓派不再拥有任何业务身份，只做 MAVLink↔MQTT 网关。
产品与版本信息与身份分开建模。注册和常规遥测升级到 schema v3（不兼容变更）。

## 已实施

身份获取：

- PX4 的 `device_id` 改为来自 Basic ID，不再用 `AUTOPILOT_VERSION.uid2/uid`
  生成 `PX4U2-*`/`PX4U1-*`。
- **PX4 在普通遥测链路上不主动发 `OPEN_DRONE_ID_BASIC_ID`**，新增按 2 秒节拍的
  `MAV_CMD_REQUEST_MESSAGE`(param1=12900) 主动请求，直到身份就绪。
- `AUTOPILOT_VERSION` 沿用同一套请求机制，但停止条件独立为"已收到该消息"。
  原先的停止条件是 `!device_id`，统一身份后 `device_id` 会先于版本消息到达，
  沿用会导致 PX4 产品与版本元数据永远采集不到。
- 两条请求用 `else if` 错开发送：`COMMAND_ACK` 不携带被请求的消息号。
- 身份校验对两类设备共用 `IsValidUasId`：非空、≤20 字节、字符集
  `[A-Za-z0-9-_.:]`（因此 MQTT 的 `+`/`#`/`/` 被拒），不再要求恰好 20 位。
  主控箱的 `DCDWCNS1` 前缀降级为告警，不参与类型判断，也不阻断建连。
- 会话内首个通过校验的 `device_id` 被锁定：`StateStore::UpdateDeviceId` 返回
  `kAccepted/kUnchanged/kConflict`，冲突时发布旧身份 offline、关闭 MQTT 会话、
  清空状态并重新识别设备，不再静默切换 topic。
- 身份未就绪时限频日志区分两种原因："PX4 未响应 Basic ID 请求"与"uas_id 非法"，
  各用独立限频器避免互相饿死；PX4 的未响应告警要等至少一次请求落空才发。

数据结构与协议：

- `TelemetryState` 删除 `vendor_id`、`rpi_serial`、`autopilot_version`；新增
  `product`、`version` 和 `autopilot_version_received`。`ResetDeviceState()`
  不再保留任何字段。
- 新增 `device/product_info.hpp`（`ProductInfo`/`VersionInfo`，全部字符串编码）。
- `protocol/identity`：删除 `ReadRpiSerial`（不再读 `/proc/cpuinfo`），
  `ExtractVendorId`→`ExtractUasId`，`IsValidCnsBoxVendorId`→`IsValidUasId` +
  `HasCnsBoxProductPrefix` + `CnsBoxProductFrom`。
- `protocol/px4_identity`：删除 `FormatPx4Uid2/FormatPx4Uid/FormatPx4DeviceId`；
  `BuildAutopilotVersionRequest` 泛化为 `BuildMessageRequest`，目标端点改用两个
  `uint8_t`，顺带去掉 `protocol/` 对 `control_command/` 的反向依赖。
- 注册载荷 schema v3：删除 `identity`/`endpoint`/`gateway` 三个对象，
  `school_name`/`dcdw_label` 平铺到顶层，新增 `product`/`version`。
- 常规遥测 schema v3：同样删除三个对象，`drone_id.basic_id` 不再输出 `uas_id`
  （完整身份只在顶层 `device_id` 出现一次）。
- PX4 高频实时遥测和 RTT 探测的 `schema_version` 保持不变，只换 `device_id` 取值。
- `mqtt/topic.*`、`config_command/config_request.*` 的 `vendor_id` 形参统一
  改名 `device_id`。

## 验证

- WSL Ubuntu 26.04 / GCC，C++23，`-Wall -Wextra` 完整编译通过，无警告。
- `ctest --output-on-failure`：33/33 通过（改动前基线同为 33/33）。
- 新增/改写测试覆盖：uas_id 通用校验与拒绝集、主控箱产品前缀拆分、PX4 产品与

  `AUTOPILOT_VERSION` 全未知时仍置位已收到标志、v3 注册与遥测的字段删除断言。

## 遗留 / 未完成项

1. **PX4 是否响应 `MAV_CMD_REQUEST_MESSAGE`(12900) 未经真机确认。** 若 PX4 不
   响应，退路是改用 `MAV_CMD_SET_MESSAGE_INTERVAL`(param1=12900,
   param2=1000000) 配 1 Hz 流，只需改 `BuildMessageRequest` 的调用参数。
   这是上线前的第一个必测项。
2. **PX4 侧未配置 UAS ID 时该设备完全不上线**（QGC 桥接仍工作，MQTT 全静默），
   这是设计文档 §8.3 确认的取舍，不做降级。现场需要先确认 PX4 参数已配置。
3. `cns_server` 尚未改：注册解析、数据库模型、命令路由和 Web 展示仍按 schema v2
   和旧 PX4 UID 主键工作，端到端链路在服务端完成前不能认为已上线。迁移期需同时
   接受 v2/v3，且不得把旧 `PX4U1-*`/`PX4U2-*` 与新 Basic ID 自动合并。
4. 遥测是否保留顶层 `school_name`/`dcdw_label`、产品与版本是否只走注册，两处按
   设计文档的取舍实施，需服务端确认无异议。
5. 设计文档 §6 提出的 `DeviceIdentity` 聚合结构未实施，当前仍是 `TelemetryState`
   上的扁平字段。验收标准不依赖它，留作后续纯重构。
