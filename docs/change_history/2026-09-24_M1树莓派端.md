# 阶段一 M1 树莓派端实施与验收边界

## 当前状态

Pi 端已在隔离工作树实现，本机与实体树莓派各 50/50 项自动化测试通过。2026-09-24 已部署到实体 Pi，并取得 B0=115200、F407 类型 4 接受、B0 三轮无回显、Pi 在线切 B1=57600、B1 新业务帧和 Echo，以及实体复位后恢复 B0 的真实证据。F407 实烧版本号仍未核验；当前实现不修改 Server、Web 或 F407 固件。

## 动作与事实

- `set_f407_baud` 只允许当前已核验的主控箱在双方 B0 且串口空闲时发送一次 MAVLink `TUNNEL` 类型 3。类型 4 必须在 5 秒内以正确端点、nonce 和 57600 目标速率到达；ACK 的 `accepted_baud_rate` 只表示 F407 在旧速率接受请求，不表示新速率已应用。响应缺失或串口中断后返回 `result_uncertain`，不自动重发。
- `uart_probe` 保持 Pi 原速率，依次发送三轮固定文本 `CNS_TEST`，每轮新 nonce、每轮至多等待 5 秒、相邻发送至少间隔 300 毫秒。只把本轮真实配对 Echo 记入接收帧和同一单调时钟 RTT；未配对时三个接收字段均为 `null`。完成只表示观察结束，不能把无回显单独解释成 F407 已切速。
- `set_pi_baud` 仅接受 57600 或 115200。原子持久化当前配置文件的 `serial.baud`，保留其他配置字段与原文件权限；随后停止后台串口发现，关闭旧链路，按原已核验拓扑路径打开并读回波特率。读回成功才返回 `serial_port_open=true`；配置写失败不关闭旧链路，重开失败保持 MQTT 入口在线并返回拒绝。
- H1 回显仍要求当前 F407 身份重新核验及新业务帧，不硬编码 B0；Pi 缓存身份只足以让失配探测和本地恢复命令到达，不会绕过普通飞控命令的当前身份门禁。

所有 M1 动作先持久化动作身份，重启后不盲目重做未完成的物理动作。H1 与 M1 互查动作 ID，避免同一 ID 被不同操作复用。ACK 沿用实验 Topic、QoS 2、非 retained，成功事实完整记录本轮 280 字节以内的线上帧；超过 4096 字节的 ACK 不截断。

## 部署前检查与恢复

现场先核对正在运行的 Pi 提交、`/var/lib/cns-rpi/config.json` 实际路径及 `serial.baud`，并确认 `/dev/serial/by-path` 的候选路径确实解析到 F407 的 CH340 节点；同一节点可有多个系统别名，实现会确定性选取其中一条。保存程序、配置、身份与服务状态备份；确认主程序是唯一串口读写者。首次 F407 类型 3 之前先用 H1 在 115200 下取得当前身份和真实回显。现场 MQTT 请求号每次使用新的 UUID，不能重复使用已落盘的动作 ID。

正常顺序：B0 H1 → B0 类型 3/4 → B0 三轮探测 → Pi 在线改 57600 → 新业务帧和 B1 H1。F407 按复位键后，它回 B0；Pi 仍在 B1 时经 MQTT 在线改回 115200，再等新的业务帧与 H1。若任一步缺少完整帧或当前拓扑路径，停止推进；不要靠猜测设备节点、自动重发类型 3 或把单纯串口打开写成 UART6 已通信。Pi 配置已改但串口重新打开失败时，MQTT 保持可接收恢复命令；必要时由现场人员按备份配置和服务恢复。

Server 端真机验收需保存每一步原始 MQTT 请求与 ACK、完整帧、两档 Echo 的文本和 RTT、运行三态、Pi 实际配置速率、F407 固件版本，以及复位后的新业务帧证据。Pi 本地自动化测试只验证本端解析、状态机、持久化和串口操作顺序，不能替代这组现场证据。
