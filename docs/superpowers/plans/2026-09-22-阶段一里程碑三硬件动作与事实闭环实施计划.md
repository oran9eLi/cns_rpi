# 阶段一里程碑三：硬件动作与事实闭环实施计划

> **执行约束：** 实施前必须阅读[已确认设计](../specs/2026-09-22-阶段一里程碑三硬件动作与事实闭环设计.md)，并使用 `superpowers:executing-plans` 逐任务执行；开始编码前从最新 `main` 建立隔离工作树。本文已于 2026-09-22 获用户确认；任务 1 已在隔离工作树通过本地协议测试、全项目类型检查及测试，尚未合并或部署；Pi 开发方正在独立实施，候选提交与部署版本待回传。任务原则上一次提交；云端部署另需现场授权。

**目标：** 在运行中的 `SERIAL-01` Session 内，让一次 `inspect_pi_link` 从 Web 经后端、路由服务到真实 Pi，再把 Pi 事实先存入 Server、后通知 Web，并在刷新和重启后可追溯。

**架构：** 沿用 Session/租约、固定 `web-console` 来源及路由命令状态机。路由服务独占写命令表，后端独占写实验动作与事件表；`action_id=request_id` 保持跨重试身份，`command_id` 由路由产生。Pi 实现属于 `cns_rpi` 仓库，由其开发方按冻结契约交付；本仓库负责 Server/Web 与跨端真机验收。

**技术栈：** C++23、libmosquitto 2.0.22、libpqxx 7.10.x、PostgreSQL、doctest；TypeScript、Fastify、Zod、MQTT、React、Vitest；云端 Mosquitto/Nginx/systemd。

**设计依据：** [里程碑三设计](../specs/2026-09-22-阶段一里程碑三硬件动作与事实闭环设计.md)、[总实施索引](2026-09-20-阶段一实验基座总实施索引.md)、[树莓派与主控板交接清单](../../2026-09-20-阶段一树莓派与主控板任务交接清单.md)。

## 全局约束

- 文档、代码注释、运行日志、提交说明正文和回答使用中文；Git 提交前缀保持英文，如 `feat: 中文说明`。
- 只允许 `inspect_pi_link`，只读 Pi 本机控制、身份、业务和串口端点状态；不新增 F407 命令、不向 UART6 发帧、不打开第二个串口读取者、不推进步骤或评分。
- `source_id=web-console`；四个 `experiment` MQTT topic 为 QoS 2、非 retained；Session 令牌只在浏览器与后端之间传输。
- 后端发令前校验 `running` Session、有效同一设备租约、`cns_box`、Pi 控制在线、身份 `verified|cached`；F407 业务离线不拦截本次只读动作。
- 动作有效期不超过 30 秒，也不得晚于租约到期；过期、释放租约或终态 Session 的待派发动作不得再下发。
- route_service 只写设备/命令核心表，backend_service 只读核心表并独占写实验表。迁移版本化、重复运行不重复破坏；不清空正式数据。
- Pi ACK 只有在后端动作和只追加事件提交后才能使 Web 显示“已记录/完成”；没有 Pi 事实时只显示失败、超时或待核验。
- 本地只跑无需正式数据库/Broker 的验证；数据库、Broker、systemd、Pi 真机和部署验证在用户授权的云端窗口进行。验收记录必须列明 Server/Pi/F407 实际版本，模拟 ACK 不算真机通过。
- 保留里程碑二遗留项：既有 Web 命令入口、飞控命令、一次配置请求超时原因及视觉补验；本轮需回归但不擅自写成已解决。

## 审查重点

1. 同一 `action_id` 携带不同 Session/操作/目标时，必须拒绝且不覆盖原动作；任务 2、5、6 的测试固定此行为。
2. 租约释放或 Session 结束与派发并发时，不得越过有效租约发出待派发动作；任务 5、6、8 的事务和并发测试固定此行为。
3. 设备 ACK 的 topic、`command_id`、`session_id`、`action_id` 或操作名不匹配时，不得写成成功；任务 3、4、7 的测试固定此行为。
4. 后端收到终态 ACK 后数据库暂时不可用、WebSocket 断开或进程重启时，不得假报成功，且能从路由既有终态补读；任务 7、8、9 的测试固定此行为。
5. Pi 控制在线但 F407 业务离线、串口状态 `unknown` 时，只读检查仍可执行且 UI 不称为 UART 已恢复；任务 2、4、7、9 的测试固定此行为。

```ts
type CreateExperimentActionRequest = {
  action_id: string; // UUID；等于路由 request_id
  operation: "inspect_pi_link";
};
type PiLinkFact = {
  control_status: "online" | "offline";
  identity_status: "verified" | "cached" | "conflict" | "unbound";
  business_status: "online" | "offline" | "unknown";
  serial_port_open: boolean | "unknown";
};
type ExperimentActionStatus =
  | "pending" | "dispatched" | "succeeded" | "failed"
  | "timeout" | "delivery_uncertain" | "not_dispatched";
```

来源 ACK 保留既有公共字段 `schema_version,request_id,command_id,command_type,status,business_status,occurred_at,target,error`；`command_type='experiment'` 时仅在合法设备终态下增加 `device:{session_id,action_id,operation,observed_at,fact,error_code}` 的受限投影。后端以已存动作的 `action_id=request_id` 核对来源 ACK；Pi ACK 则由 route 按命令记录交叉核对 Session/动作身份。Pi 拒绝错误码限定 `action_expired|identity_unavailable|observation_unavailable|duplicate_conflict|unsupported_operation`；路由自身拒绝继续沿用现有来源 ACK 的 `error.code`，不冒充 Pi 错误。时间统一 RFC 3339 UTC 毫秒格式，设备请求和 ACK 各不得超过 4096 字节，`lease_version` 为正整数。Pi 设备侧完整约束以[跨端契约](../../2026-09-22-阶段一Pi控制链自检跨端契约.md)为准。
