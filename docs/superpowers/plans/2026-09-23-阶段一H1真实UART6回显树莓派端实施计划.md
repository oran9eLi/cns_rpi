# 阶段一 H1 真实 UART6 回显树莓派端实施计划

> **实施者要求：** 使用 `superpowers:executing-plans` 按任务逐项执行；代码项先写失败测试、再写最小实现，每项结束复核并提交。本计划仅覆盖 Pi，不代替 F407 或 Server/Web 开发。

**目标：** 同一 Pi 业务进程经实际 UART6 链路完成一次受限学生文本回显，产生可核对的新业务帧、实际波特率、完整 TX/RX 帧和单调 RTT 事实。

**架构：** 保留现有 MQTT 实验 Topic 和唯一 `MavlinkLink` 串口读写者。请求解析、TUNNEL 编解码、原始帧证据和非阻塞动作状态机分别放在小模块，主循环只协调串口消息、MQTT ACK 与现有业务。无现场 B0、承载方式和三端字节契约的共同冻结记录时，本计划**止于任务 0**，后续任务不得执行；若冻结结果与候选 TUNNEL 布局不同，先修订本计划并请用户确认。

**技术栈：** C++23、官方生成 MAVLink C 头文件、nlohmann/json、doctest、CMake/CTest；真机 ARM 构建和部署留待另行授权。

**设计：** [本端设计](../specs/2026-09-23-阶段一H1真实UART6回显树莓派端设计.md)；跨端候选见服务器仓库 `docs/2026-09-23-阶段一H1真实回显跨端契约.md`。

## 全局限制

- 所有文档、注释、日志和提交正文中文；Git 前缀使用英文。保留当前用户改动，不整理无关文件。
- 本轮只做 `uart_echo`；旧 `inspect_pi_link`、配置、飞控、注册和高低频遥测行为保持原样。
- 学生文本编码后 1—48 字节、有效 UTF-8、非纯空白且不含 U+0000—U+001F/U+007F—U+009F；合法文本不裁剪、不规范化。`HELLO CNS` 仅是示例。
- 不新增第二个串口读者；不改 Pi/F407 波特率、不发送其他实验帧、不在普通日志输出学生原文或完整帧；不部署、不改 F407 或 Server/Web。
- Pi 响应包不超过 4096 字节；候选完整帧上限 280 字节、十六进制大写、长度字段按实际线上完整帧；所有候选数值都以任务 0 的三端冻结为准。
- 缓存身份可保持 MQTT 控制，但 H1 发帧须本次串口身份已核验；端点打开不能替代 F407 有效回复。
- 现有候选 Server REST 拒绝并不能阻止直接向固定来源 MQTT Topic 下发 `uart_echo`；来源 ACL 和 H1 门禁未核实前，禁止在现场部署可执行 Echo 的构建。

## 重点复核输入与失败模式

| 输入/状态 | 期望行为 | 所属任务 |
|---|---|---|
| 合法 MAVLink 2 的零尾裁剪 | 按逻辑 `payload_length` 和实际线上字节分别判断，不把合法裁剪误拒或把重编码当抓包 | 2 |
| F407 同 sysid 但不同 compid 的伪响应 | 拒绝匹配，不能只复用普通遥测的 sysid 判定 | 3 |
| 同动作发帧后进程崩溃并重投 | 不盲目第二次物理发送；结果不能确定就返回待核验 | 3、4 |
| 已打开串口却只有旧业务缓存、无本动作新帧 | 不形成成功事实 | 3 |
| MQTT 已收到 H1 请求但 F407 离线 | MQTT 控制链继续运行，返回受限拒绝/不确定结果 | 4 |
