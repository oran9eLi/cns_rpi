# 统一高低频遥测发布通道实施计划

> **面向代理式开发者：** 必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 按任务执行本计划；每个步骤使用复选框跟踪。

**目标：** 将完整快照和实时遥测收敛为两个同构发布通道，主控箱和 PX4 共用 `telemetry/snapshot/v1` 与 `telemetry/realtime/v1`，默认分别按 1 Hz 和 10 Hz 发布。

**架构：** `TelemetryState` 继续作为唯一最新状态存储；新增的 `telemetry::Publisher` 只负责两个通道的到期判断、单次快照获取和丢旧帧调度。JSON 构造器决定字段归属，`MqttClient` 仍然只发送已构造的字节，不感知高低频或设备类型。

**技术栈：** C++23、nlohmann/json、libmosquitto、doctest、CMake/CTest、Python 3 标准库、Bash、systemd。

## 全局约束

- 文档、日志和用户可见描述一律使用中文；Git 提交前缀保持英文，提交说明使用中文。
- 快照 Topic 固定为 `{namespace}/{device_id}/telemetry/snapshot/v1`，默认 1000 ms、QoS 0、`retain=false`。
- 实时 Topic 固定为 `{namespace}/{device_id}/telemetry/realtime/v1`，默认 100 ms，允许 50–1000 ms，QoS 0、`retain=false`。
- 高频发布失败时丢弃当前帧，不重传、不补发、不建立历史队列。
- 实时 JSON 只携带快变字段；主控箱的 `motor`与 PX4 飞行动态字段使用同一帧构造器，缺失字段直接省略。
- 不双发旧 `{device_id}/telemetry` 和 `{device_id}/px4/realtime/v1`；服务端必须先兼容新 Topic 再升级树莓派。
- 默认生产频率为 10 Hz，设计容量上限为 1000 设备同时以 20 Hz 发布；数据库不消费实时 Topic。
- 新确认的配置、Topic、字段和部署行为必须在同一任务中同步更新相关文档。
- 实施依据：`docs/superpowers/specs/2026-08-04-统一高低频遥测发布通道设计.md`。

- [ ] **Step 1：定义公共接口并写编译失败测试**

`publisher.hpp` 接口固定为：

```cpp
namespace telemetry {
using Clock = std::chrono::steady_clock;
using FrameBuilder = std::function<nlohmann::json(
    const state::TelemetryState&, std::uint64_t)>;
using SnapshotProvider = std::function<state::TelemetryState()>;
using PublishFunction = std::function<bool(
    const std::string&, const std::string&, int, bool)>;

struct ChannelOptions {
  std::string name;
  std::string topic;
  std::chrono::milliseconds interval;
  int qos{0};
  bool retain{false};
  bool enabled{true};
};

struct ChannelDefinition {
  ChannelOptions options;
  FrameBuilder build_frame;
};

struct PublishAttempt {
  std::string channel_name;
  bool succeeded{false};
  bool should_log_failure{false};
};

class Publisher {
 public:
  Publisher(std::vector<ChannelDefinition> channels, Clock::time_point started_at);
  std::vector<PublishAttempt> Tick(Clock::time_point now,
                                   const SnapshotProvider& snapshot_provider,
                                   const PublishFunction& publish);
 void Reset(Clock::time_point now);
 private:
  struct ChannelState {
    ChannelDefinition definition;
    Clock::time_point last_attempt;
    std::uint64_t sequence{0};
    bool failure_active{false};
  };
  std::vector<ChannelState> channels_;
};
}  // namespace telemetry
```

- [ ] **Step 2：写节拍、单次快照和丢帧测试**

使用 1000 ms 和 100 ms 两个通道，通过计数回调断言：
