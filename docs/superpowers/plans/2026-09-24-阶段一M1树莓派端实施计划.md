# 阶段一 M1 树莓派端实施计划

> **执行代理必用技能：** 用户确认本计划并完成双端冻结核对后，按 `superpowers:executing-plans` 逐任务测试驱动实施。每项以 `- [ ]` 跟踪；本计划不授权真机改参或部署。

**状态：计划已获用户确认；Pi 端已部署，树莓派原生构建和 50/50 测试通过。B0/B1 两档业务与 Echo、旧速率类型 3/4、三轮失配探测已采证；实体复位后恢复 B0 与 Server/Web 闭环待完成。**

**目标：** 在现有 Pi 进程和唯一 UART6 链路上完成三种受限 M1 动作：F407 旧速率接受、三轮失配观察、Pi 不退出 MQTT 的在线持久化换速，并保留 H1 两档真实回显能力。

**架构：** 沿用设备实验 Topic、QoS 2 ACK 队列、持久化动作去重和 `src/main.cpp` 的唯一串口所有者。请求解析、TUNNEL 类型 3/4 编解码、动作状态机和在线换速分别负责校验、帧证据、终态、配置与串口；不把 F407 接受帧推断为已应用，也不让串口失配销毁主控箱 MQTT 控制会话。

**技术栈：** C++23、CMake、doctest、官方 MAVLink C 头、libmosquitto、POSIX termios、现有 `config_command::PersistConfig`。

**规格：** [本仓库 M1 Pi 执行交接](../../2026-09-24-阶段一M1树莓派执行交接.md)。上游参照文件为服务器仓库的 `docs/superpowers/specs/2026-09-24-阶段一里程碑五串口教学闭环设计.md` 与 `docs/2026-09-23-阶段一H1真实回显跨端契约.md`；它们的现场构造向量不是实测帧。

## 全局约束

- 用户本轮只要求 Pi 端；不改 Server/Web/F407，不连接现场串口、不部署。文档、注释、日志、提交说明正文均为中文，提交类型前缀为英文。
- 先确认上游里程碑五实施计划已获用户批准，Pi/F407 共同核对类型 3/4 的 14 字节向量、F407 57600 8N1、类型 4 完帧后换速、复位回 115200；未通过则只保留文档，不编码硬件动作。`115200` 是 H1 已测 B0，`57600` 尚不是本轮已验现场事实。
- MQTT 请求只接受 `schema_version=1`、本设备主控箱绑定、合法 Session/动作/租约/有效期、契约所列字段及 4096 字节上限；未知字段拒绝。`action_id=request_id`。ACK 为 QoS 2、非 retained，终态 `completed+fact` 或 `rejected+error_code`，不增加中间成功态。
- 物理动作前持久化动作身份；跨 H1/M1 的相同 `action_id` 也不得执行不同操作。未确认完成的旧动作在重启后为 `result_uncertain`；任何已发 F407 改参帧均不盲目重发。
- 串口读写保持单一所有者。`uart_probe` 不要求当前 F407 身份帧，但必须有本机固定主控箱绑定及可证明的目标端点；重启后丢失端点事实时拒绝发送，不广播猜测目标。`set_pi_baud` 在 F407 离线、身份 cached 时仍可通过 MQTT 接收。
- F407 改参只在当前双方 B0、当前身份已核验且串口空闲时发送一次；Pi 改参白名单为 57600/115200，持久化与应用不依赖普通配置命令的主动退出流程。失配探测固定文本 `CNS_TEST`、三次、每次最多 5 秒、间隔至少 300 毫秒。
- 完整帧上限 280 字节，十六进制大写且长度与实际帧字节数一致；若最终 ACK 超过 4096 字节则拒绝，不截断。无本轮有效配对响应时 `valid_rx_frame_hex`、`rx_frame_bytes`、`round_trip_us` 同时为 `null`。

## 已核对的 Pi 代码基线与审查重点

- 当前 `main` 为 `40edb0f`，工作区起始无用户修改；`main.cpp` 由 `link` 持有串口，MQTT 订阅 `experiment/set`，H1 使用 `UartEchoTransaction` 的落盘去重与单调时间抓帧。`mark_link_disconnected` 对有持久化主控箱绑定的情况保留 MQTT，但会清空 `active_serial_device` 和 `controlled_device`；M1 失配后的探测与本地恢复不能因此猜端点。
- `SerialPort::Open` 支持 57600 与 115200，`AppliedBaud` 可读回 termios；这只证明 Pi 代码路径支持，不证明 F407 实烧 B1。现有异步发现按配置波特率扫描，必须在 M1 失配/在线重配阶段协调关闭与重新打开，不能同时拥有串口，也不能自动跟速。
- 示例配置 `serial.device=auto`；串口静默 10 秒后现有主循环清除节点和端点，重启后只靠 B0 的 MAVLink 发现不能重新识别已切到 B1 的 F407。因此需在本端设计确认时明确“已核验设备 ID → 稳定物理串口路径与最后已核验 sysid/compid”的最小持久化关联；优先使用 `/dev/serial/by-path` 的实际同一 USB 拓扑路径，并验证它确实解析到原 CH340。不存在可靠路径时安全拒绝探测/换速，不扫描任意串口冒充旧端点。此关联只用于失配期间找回本 Pi 的原端口，不代替当前 F407 身份核验。
- 普通配置命令经 `PersistConfig` 后要求进程退出；M1 不能复用该退出行为。部署服务采用 helper 写 `/var/lib/cns-rpi/config.json`；helper 保留目标权限。若在单测直写路径使用 `PersistConfig`，须核验并修正权限保持，不能让测试路径与现场语义分叉。
- H1 `OnFrame` 目前对同类 TUNNEL 错类型立即拒绝，M1 接入后必须先按类型分流；在任何情况下，错 nonce、旧帧和非受控业务帧都不能组成新的成功事实。

## 审查重点

1. F407 已收到改参请求但接受帧丢失：只返回 `result_uncertain`，重启或重投都不再次发类型 3。
2. 失配 10 秒或 Pi 重启后串口自动发现失效：MQTT 仍在线，Pi 本地换速可用，但探测不得向不确定节点或目标发帧；稳定路径不存在时报告明确拒绝。
3. 配置写入成功而串口重开/读回失败：ACK 不能为 `completed`，进程和 MQTT 保持运行；下次启动以持久化值恢复。
4. 三轮探测中一轮错 nonce、旧帧或其他设备帧：该轮三个接收事实同为 `null`，有效数仅计本轮配对 Echo。
5. H1 与 M1 复用动作 ID、重连 ACK 重投和 4096 字节边界：不重复串口动作、不截断事实、旧 H1 去重记录仍可读取。
