# V1.0 发布精简部署实施计划

> **供执行代理使用：** 必须使用 `superpowers:executing-plans` 或 `superpowers:subagent-driven-development` 逐项执行。本计划使用复选框跟踪进度。

**目标：** 将 V1.0 发布收敛为无需 OverlayFS 和配置卷、可在新树莓派上一键部署且保留两个常驻自启动服务的版本。

**架构：** 现场配置继续迁移并固定读取 `/var/lib/cns-rpi/config.json`，以隔离仓库模板和运行时参数。部署脚本仅安装配置写入 helper、主程序服务、5G 服务及运行支撑配置；主程序不再等待只读配置卷服务。

**技术栈：** C++23、CMake、doctest、Bash、Python 3、systemd、Raspberry Pi OS 64-bit（Debian 13）。

## 全局约束

- 文档、日志和面向用户的提示一律使用中文；Git 提交前缀使用英文。
- V1.0 不实现 PX4 接入、MQTT TLS/证书/ACL、OverlayFS 只读根文件系统或配置镜像卷。
- 保留 `cns-rpi.service` 与 `cellular-dialup.service`，部署后均须 `enable` 并立即启动或重启。
- 现场配置路径固定为 `/var/lib/cns-rpi/config.json`；仓库配置仅作为初始迁移来源。
- 新确认的选型或设计必须同步更新文档。

## 文件结构

| 文件 | 责任 |
|---|---|
| `systemd/cns-rpi.service` | 主程序开机自启、watchdog、配置写入 helper 参数，不再依赖配置卷服务。 |
| `scripts/deploy.sh` | 构建、安装 helper/两个常驻服务、迁移现场配置、启用并启动服务。 |
| `tests/test_cns_rpi_service.cpp` | 静态校验部署脚本和 systemd 单元的发布契约。 |
| `README.md` | 对外说明 V1.0 范围和一键部署入口。 |
| `docs/新设备部署手册.md` | 新设备从克隆到运行的唯一部署流程。 |
| `docs/V1设计文档.md` | 更新 V1.0 交付状态和未纳入范围。 |
| `docs/M7系统化部署设计.md` | 将只读根设计标记为后续增强，不作为 V1.0 验收项。 |
