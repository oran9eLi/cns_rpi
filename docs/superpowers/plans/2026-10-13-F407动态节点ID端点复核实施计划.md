# F407 动态节点 ID 端点复核实施计划

> **执行者：** 按 `superpowers:executing-plans` 或 `superpowers:subagent-driven-development` 逐项实施；每项先测后改。

**目标：** F407 重启换号后，Pi 保持 MQTT 与实验会话，复核同一 `device_id` 后安全切换 MAVLink 端点。

**架构：** 独立的端点复核状态机管理候选 `system_id`；主循环只负责串口、身份和 MQTT 事务接线。一个有界待发槽暂存身份复核期间的新 H1/M1 串口动作，复核后按原事务落盘、发帧。

**技术栈：** C++23、MAVLink、CMake/CTest、现有 H1/M1 事务。

**设计依据：** `docs/superpowers/specs/2026-10-13-F407动态节点ID与端点复核设计.md`

## 全局约束

- 仅处理已持久化绑定的 F407；PX4、首次未绑定、普通 `control/set` 排队和新节点 ID 实验协议不扩展。
- 不改 MQTT Topic、绑定 `device_id`、F407/Server/Web；不新增串口读者，不部署实体 Pi。
- 3 秒是待复核告警门槛，不是自动放行或会话终止时间。
- 注释、日志、文档和提交正文用中文；提交前缀保留英文。

## 重点回归输入

- 旧端点仍有迟到帧：不得取消待复核，也不得把它当作新身份。
- 候选端点身份不同或有第三端点：不得切 Topic、自动改绑或发帧。
- H1/M1 已发帧时换号：不主动中断；自然超时仍应形成原有真实终态。
- 待发动作重复、冲突、已过期或队列占满：不能重复物理执行。
- 拓扑记录仍保存旧 `system_id`：新实验帧只能寻址当前已复核端点。
