## 1. 范围与依据

本轮只设计 `uart_echo` 单次真实回显。学生输入受限中英文 UTF-8 文本；Pi 沿用现有业务进程及其已接管的串口读写者，发送给同箱 F407，核对来自 F407 的原样回显和当前实际波特率，并向既有 `experiment/ack` 报告本动作后的新业务帧结论、真实完整 TX/RX 帧及同一单调时钟 RTT。`HELLO CNS` 只是默认输入示例，不在设备程序里写死。不改波特率、不开发后续 M1/M2、不修改 F407 或 Server/Web、不部署。

输入依据是本仓库 `docs/协作规则.md`、`docs/2026-09-20-阶段一树莓派与主控板任务交接清单.md`、现有 Pi 代码，以及服务器仓库的《2026-09-20-阶段一树莓派与主控板任务交接清单》和《2026-09-23-阶段一H1真实回显跨端契约》。后者是**协议候选**；它的构造帧、示例 `57600` 和固定示例文本不构成现场证据。若现场事实与候选不一致，先三端修订契约，不单端改字段或降低验收标准。

## 3. 本端数据流与边界

既有 `experiment/set` 入口只在已持久化绑定的主控箱上订阅、QoS 2、非 retained；旧 `inspect_pi_link` 的解析、缓存与 ACK 语义保持不变。新 `uart_echo` 必须按操作名分流，严格校验当前 Topic/绑定设备、Session 与动作标识、租约版本、到期时间及输入文本。相同 `action_id` 同内容重投只取回既有终态，不重发物理帧；同 ID 改文本、Session、目标或有效期为冲突。可变动作的崩溃一致性不能照搬只读动作的 128 项/300 秒进程内缓存：当前候选实现保留最多 128 个不自动过期的持久动作标记，容量用尽时拒绝新的 H1；若设备可能在发帧后崩溃而没有终态，重启后只能报告结果待核验，不能盲目再次发帧。长期扩容与归档方式仍需三端冻结，不得直接清空记录。

H1 准入要求 `link` 已由业务主循环接管、受控设备确认为 F407 主控箱、当前串口会话身份与持久绑定重新核验一致、目标 sysid/compid 来自本次实际心跳，且没有另一个 UART 命令占用。缓存身份足以维持 MQTT 控制，但**不足以发送 H1 帧**；不能把旧自检的宽松门禁直接用于回显。串口打开不是 UART6 双向通信成功。若 F407 已静默断链，仍可收下 MQTT 消息并明确拒绝/返回不确定结果，而不是令 MQTT 控制链跟着离线。

请求只由现有 `MavlinkLink` 写入同一 fd；F407 应答也只由该 `MavlinkLink` 原有接收循环取得。接收分发须先以本次 F407 的 sysid **和 compid**、TUNNEL 目标、协议字段、随机 nonce、文本字节、动作时序匹配，再把其他正常业务帧交原有遥测路径。现有 `IsMessageFromControlledDevice` 对普通消息默认只校验 sysid（`src/control_command/control_endpoint.cpp:73-87`），不能单独充当 H1 响应身份校验。候选响应可由生成的 MAVLink TUNNEL 承载，但 F407 分发实现和双方逐字节向量未共同确认前不把 `0x8003` 写成已投产事实。

成功事实仅在本动作产生新的有效 F407 业务帧、有效回显与本次输入逐字节相等、F407 报告的当前已应用波特率与 Pi 当前端口实际波特率及现场 B0 一致、两帧原始字节均已取得后形成。Pi 自身波特率应从现有 fd 的已应用 termios 查询/校验，不能只抄 `config.json`；F407 数值必须来自 F407 自报的当前已应用配置，不能由 Pi 用请求值补造。只用 Pi 的 `steady_clock` 记录本次发送和接收时点计算 RTT；`observed_at` 仍是墙钟，不用于跨机器相减。新业务帧必须经本次动作开始后的现有接收路径实际解码，不能使用遥测缓存、retained 消息或发现阶段排队的旧帧。新业务帧的准确先后点、等待窗口与 Echo 超时需三端冻结。

TX 证据取本次成功写入 fd 的完整编码缓冲，RX 证据在唯一 `SerialPort::Read` → `MavlinkFrameAssembler` 路径中按通过 CRC 的那条帧保留实际字节和接收单调时间。当前 `mavlink_msg_to_send_buffer` 对 MAVLink 2 会裁剪尾部零字节（`src/mavlink/mavlink_helpers.h:451-489`），因此对解码后的 RX 消息再序列化**不保证**与线上字节完全相同。`payload_length` 描述 TUNNEL 逻辑数据长度，MAVLink 2 的合法零尾裁剪不能误判为业务载荷截断；该判据须在跨端字节向量中明确。原始帧只保留匹配本动作的一对、有界进入 ACK，不逐帧打印或全量上传业务流。写入 fd 成功也不等于 F407 已执行，只有匹配的真实 RX 可确认。

状态机在主循环中非阻塞推进：请求准入 → 单次发送 → 等待匹配回显与新业务帧 → 校验并形成终态 → 沿用 ACK 待发队列发布。等待期间注册、遥测、配置/飞控命令接收和 MQTT 重连仍可运行；对需要同一串口写入的并发动作明确拒绝或排队，不得在等待中阻塞主循环。超时、串口断开、身份变为缓存或冲突、MQTT 中断及进程退出均不得伪造成功。日志只打印动作标识和受限原因，不把学生文本或完整帧写入普通日志。

## 4. 三端共同冻结项和负向向量

以下是**待三端确认的候选项**，不是 Pi 单端宣布的最终协议：

1. 现场 Pi 的运行提交、systemd 配置路径、实际 `/dev/tty*`/USB 桥接器及 Pi TX/RX/GND 到 F407 UART6 TX/RX/GND 的逐线映射；F407 已烧录版本、引脚和双方实际 B0，以及实际 8N1/共同支持值。
2. `uart_echo` 的 MQTT 请求/ACK 精确字段、输入 `text` 在设备消息中的位置、`action_id` 幂等和崩溃恢复语义、设备 ACK 4096 字节上限、成功事实与失败错误码白名单；Server 必须用已存动作输入核对响应，不能只比较 ACK 的自报请求/响应文本。
3. UTF-8 与 Unicode 空白/控制字符的三端同一拒绝规则：编码后 1—48 字节、合法 Unicode、非纯空白、不裁剪或规范化合法文本；默认 `HELLO CNS` 以外还要冻结中文和中英混合向量。
4. 如果仍采用 MAVLink 2 TUNNEL：`payload_type=0x8003`、请求/响应类型与版本、目标 sysid/compid、nonce 编码及唯一性、字节序、长度、零尾裁剪判据、F407 从当前已应用 UART6 配置读取波特率的字段来源、完整帧及 CRC 向量。现有两个类型 `0x8001/0x8002` 不能被改用。
5. 动作开始/发送/响应/新业务帧的先后定义、Echo 与业务帧各自超时、RTT 起止点及单位、B0 比较时机、失败后能否提供部分证据及迟到响应处理。
6. Server 的 H1 准入和来源 MQTT ACL：目前候选文档记载 REST 暂拒绝 `uart_echo`，但固定来源 Topic 可绕过此门；来源访问控制和现场门禁未核对前不得部署会执行物理 Echo 的 Pi 版本。

负向测试必须覆盖：错误 Topic/设备/Session/租约或过期；同 `action_id` 改文本与跨重启重投；空文本、49 字节、截断或过长 UTF-8、非法序列、纯 Unicode 空白、控制字符及多余 JSON 字段；错误 TUNNEL 类型/版本/目标/来源组件/nonce/声明长度、非零尾随数据、CRC 错、重复或迟到响应、任一回显字节变化；F407 实际波特率与 Pi/B0 不一致；无新业务帧、串口已打开但无 F407 回包、断线中 MQTT 仍可收命令、身份 `cached|conflict|unbound`；帧抓取缺失、部分写入、ACK 发布失败及旧自检/配置/飞控/注册/遥测回归。每一项不得形成成功事实。

## 5. 实施与验收门禁

当前阻断项是现场未通电，B0 与接线、F407 实烧固件及 TUNNEL 接收能力、跨端字节向量均未核验。用户已授权依据候选契约先编写和测试本端代码；候选实现必须标识为待联调，不得把构造帧或示例波特率当现场值。现场恢复访问后先只读记录版本/配置/USB 节点/进程 fd 与接线资料，且不打开第二个串口读取者；再由 Pi/F407/Server 三方共同确认真实收发和失败向量。解除部署门禁前不得向实体设备派发 H1 动作。实施步骤见[树莓派端实施计划](../plans/2026-09-23-阶段一H1真实UART6回显树莓派端实施计划.md)。
