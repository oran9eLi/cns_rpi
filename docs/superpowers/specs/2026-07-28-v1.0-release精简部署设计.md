# V1.0 发布精简部署设计

## 目标

将当前树莓派端收敛为可在新 Raspberry Pi 上一次执行 `./scripts/install_deps.sh` 完成环境准备、构建、服务安装和启动的 V1.0 发布版本。

V1.0 的交付对象是接入 STM32 主控箱的树莓派数据节点。它需要在可用网络（Wi-Fi 或 5G）上建立 MQTT 连接，完成遥测上报、注册、命令接收和 5G 链路维护；不以实时控制为目标。

## 范围

### 纳入 V1.0

- STM32 UART/MAVLink 数据链路、串口自动发现与插拔恢复。
- 身份、遥测、注册与 MQTT 上下行命令链路。
- 5G 拨号、链路自恢复、质量上报和在线状态同步。
- `cns-rpi.service` 与 `cellular-dialup.service` 的 systemd 自启动、异常重启。
- 日志容量限制、swap 配置、运行时参数持久化和新设备一键部署。

### 不纳入 V1.0

- PX4 接入及其 MAVLink 消息兼容；相关设计文档不作为本次发布内容。
- MQTT TLS、客户端证书、ACL 等传输层安全机制。
- OverlayFS 只读根文件系统、配置镜像卷及其挂载服务。
- 服务端数据库、路由和管理前端实现。

## 配置策略

仓库中的 `config/config.example.json` 是版本管理的模板，现场配置由首次部署前复制生成 `config/config.json`。部署脚本在首次运行时将该文件迁移至 `/var/lib/cns-rpi/config.json`；此后主程序和 5G 服务只读取该持久路径。

收到合法配置命令后，主程序仍通过 `cns-rpi-apply-config` 原子更新 `/var/lib/cns-rpi/config.json`，随后退出，由 `cns-rpi.service` 自动重启并加载新配置。该策略不依赖只读根文件系统，同时避免 `git pull` 或重新部署覆盖现场参数、避免运行时写入污染仓库工作区。

## 服务拓扑

```text
install_deps.sh
  └─ deploy.sh
       ├─ 安装 cns-rpi-apply-config
       ├─ 安装 cns-rpi.service，并 enable + start/restart
       ├─ 安装 cellular-dialup.service，并 enable + start/restart
       ├─ 安装 journald 与 zram swap 配置
       └─ 初始化或迁移 /var/lib/cns-rpi/config.json
```

`cns-rpi.service` 不再依赖 `cns-rpi-config.service`。`/var/lib/cns-rpi` 是普通、可写的本地目录，属主为 `dcdw`。两个常驻服务共享 `/run/cns-rpi` 运行目录，但互不作为启动依赖：5G 无卡或暂时离线不得阻止主程序启动。

## OverlayFS 处理

V1.0 不安装也不启用 OverlayFS。为避免在遗留的 OverlayFS 设备上出现“部署后重启丢失”的假成功，`deploy.sh` 保留根文件系统类型检查：发现根目录为 `overlay` 时直接退出，并提示先停用 OverlayFS、重启后再部署。

不再安装、启用或引用以下只读根组件：

- `systemd/cns-rpi-config.service`
- `scripts/cns-rpi-mount-config.sh`
- `/boot/firmware/cns-config.img`

历史脚本和专项设计文档可以保留在仓库作为追溯资料，但部署入口、运行服务和用户手册不得将其描述为 V1.0 的组成部分。

## 验收标准

1. 新设备在 `dcdw@/home/dcdw/cns_rpi` 路径下准备好 `config/config.json` 后，执行 `./scripts/install_deps.sh` 可完成构建和部署。
2. 部署后 `cns-rpi.service`、`cellular-dialup.service` 均已 `enabled`，并被启动或重启。
3. `cns-rpi.service` 不包含 `Requires=` 或 `After=` 指向 `cns-rpi-config.service`。
4. 系统未启用 OverlayFS 时，现场配置位于 `/var/lib/cns-rpi/config.json`；配置命令后的服务重启仍能加载该文件。
5. 系统若已启用 OverlayFS，`deploy.sh` 明确失败且不安装不完整的发布状态。
6. README、部署手册、V1/M7 状态文档与实际交付范围一致，不把 PX4、MQTT 加密或只读根文件系统列为 V1.0 已交付能力。
