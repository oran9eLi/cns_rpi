# F407 动态节点 ID 与 MAVLink 端点复核设计

日期：2026-10-13
状态：已确认，Pi 端已在隔离工作树实现；真机换号尚未验收

## 目标与范围

F407 的 LoRa 节点编号可由学生修改，重启后会改变 UART6 MAVLink 帧头的 `system_id`（范围 1～250）。Pi 与 F407 仍是同一箱体内的一对设备，业务主键始终取 `OPEN_DRONE_ID_BASIC_ID.uas_id` 的 `device_id`。本次让 Pi 在**同一已打开串口**内识别这种端点变化，复核不变的设备身份后继续通信；节点编号和 `DCDW-XXX` 只作为可变标签，不作为持久化绑定、MQTT Topic 或跨端数据库主键。

本次不定义修改节点 ID 的新实验协议，不修改 F407、Server、Web 或 PX4，不引入第二个串口读者，也不设计普通飞控命令的排队、重试和有效期。现有 `control/set` 在复核期间必须继续受身份门禁约束，不能向旧或候选 `system_id` 写帧。配置命令和只读 `inspect_pi_link` 不因端点复核被整体停用。

## 已核对的现状与冲突

- `src/main.cpp` 将同一串口上不同 `system_id` 的主控箱 HEARTBEAT 判为设备冲突，关闭 MQTT、清空端点和遥测；这会中断实验控制入口。
- `IsMessageFromControlledDevice` 只接受已锁定的 `system_id`，因此新端点的 Basic ID 无法走到现有身份复核路径。
- `mark_link_disconnected` 会终止 H1/M1/普通控制事务，H1 主循环还会在当前身份未核验时主动终止等待中的回显动作；端点变更不得调用这条“物理串口断开”路径。
- `SerialAffinity` 同时保存稳定的 USB 拓扑路径和可变的 MAVLink 端点；换号后若仍用旧记录中的端点寻址实验帧，会向旧编号发送。
- `docs/2026-08-03-主控箱与PX4统一身份数据结构设计.md` 的“其他 `system_id` 的 Basic ID 不得写入当前设备状态”仍成立；新增的候选端点必须先与旧端点隔离、用绑定的 `device_id` 复核，不能直接把陌生帧写入遥测。

## 端点状态与身份判定

仅对已持久化绑定的 `cns_box` 启用平滑切换；PX4 和首次未绑定设备保留现有严格发现逻辑。当前串口、设备类型和 MQTT 会话不变。当同一串口收到合法主控箱 HEARTBEAT，组件号与已识别的 F407 UART6 组件一致、但 `system_id` 与当前值不同，记录**候选端点**并进入“待复核”。此时旧端点不被直接替换，原身份核验资格失效，运行三态的身份暂为 `cached`；仍维持 MQTT 控制链在线。候选端点的普通业务帧不进入遥测状态，也不被当作身份已核验的业务证据。

只接收与候选 `system_id` 对应、且组件号与候选 HEARTBEAT 一致的合法 `OPEN_DRONE_ID_BASIC_ID` 作为候选身份。其 `uas_id` 与本 Pi 的持久化 `device_id` 完全一致后，更新当前 MAVLink 端点、状态中的可变 `DCDW-XXX` 标签及串口拓扑关联，再恢复该端点的业务帧和新串口下行。`device_id`、绑定文件、MQTT Topic、registration 设备身份均不变化，也不向 Server 发起结束实验 Session 的动作。持久化拓扑更新失败要记录明确日志；实验下行不得从旧拓扑记录取旧 `system_id`，只能使用当前已复核端点。待复核时若又收到第三个不同端点的 HEARTBEAT，保持暂停并报告歧义，不自动选择其中之一。

候选 Basic ID 不合法时身份保持 `cached`；与持久化绑定不同则为 `conflict`。两种情况都不自动改绑、不切 Topic、不向候选端点发命令。不同设备类型或组件冲突仍走现有安全拒绝逻辑，不借本功能放宽。未见候选 Basic ID 时保持待复核，3 秒仅作为中文告警门槛，不自动放行或结束实验。该门槛不是保证完成的时间：现有消息清单所列 Basic ID 1 Hz 是当时 RemoteID 链路参考频率，不能作为当前 UART6 调度保证；等待时长需现场测量。

## 实验动作和下行边界

待复核期间，所有**新** F407 串口下行暂停。已经发出的 H1/M1 动作不因仅有端点编号变化而主动 `Abort`；原事务自己的帧关联、有效期和超时仍适用，不能把重启造成的无响应伪称成功，也不能把会话保持误写为单个动作必定完成。物理串口实际断开、波特率切换等既有路径不受此规则覆盖。

在待复核期间新到达的 H1 `uart_echo` 和 M1 中需要向 F407 发帧的 `set_f407_baud`、`uart_probe`，沿用现有解析、设备校验和 `expires_at`，最多保留一项待发请求；同一动作的重复消息不得重复入队或重发，不同内容复用动作 ID 按既有冲突语义拒绝。身份复核成功、串口空闲且请求尚未过期时，才由现有事务完成“先落盘后发帧”；过期请求按原 `action_expired` 语义结束，不补发。候选身份冲突、队列已满或串口实际失联时，使用既有拒绝语义给出终态，不无限积压。待发项只在进程内暂存，不宣称跨进程持久化；进程重启后由现有 Server 动作有效期与重试机制处理，不得产生不明原因的自动物理重发。

M1 的 `set_pi_baud` 是 Pi 本地动作，保留原有受信拓扑及失配恢复门禁；只读自检照常响应。普通 `control/set` 不新增待发队列，复核期间继续由现有未核验门禁明确拒绝。复核结束后若需要下发实验帧，目标 `system_id` 必须取新的已复核端点，不能使用上一次保存的角色号。

## 错误处理与验收

- 新 HEARTBEAT 只触发候选，不导致 MQTT、实验会话或唯一串口关闭；新 Basic ID 未核验前无任何新 F407 下行。
- 同一 `device_id` 的候选 Basic ID 到达后，端点切换、`DCDW-XXX` 标签和后续实验目标同步更新；MQTT Topic 与绑定文件不变。
- 无候选 Basic ID、非法 Basic ID、不同 `device_id`、不同设备类型、不同组件号和超时告警分别测试；任何失败路径均不能向未经核验的端点写帧。
- 已发 H1/M1 动作在端点变化时不因身份失效被主动中断；如果 F407 重启导致真实回显/接受帧缺失，则按原事务超时或不确定结果结束。
- 待发实验请求只在有效期内发送一次；重复、过期、队列已满、进程重启和串口实际断开的行为有自动化测试。
- 原有身份绑定、运行三态、MQTT 重连、H1/M1、普通控制命令和遥测测试继续通过；不以本机单元测试替代 F407 在线修改节点 ID 的真机验收。

实现时同步 `docs/V1设计文档.md`、`docs/设备标识符.md` 和统一身份设计中关于 `system_id` 固定及 `DCDW-XXX` 唯一性的过期表述，并在 `docs/change_history/` 记录验证范围。现场部署与固件修改不在本轮自动执行范围内。
