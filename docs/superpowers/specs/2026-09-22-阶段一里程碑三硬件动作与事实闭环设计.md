# 阶段一里程碑三：硬件动作与事实闭环设计

日期：2026-09-22

状态：2026-09-22 用户已确认设计与[逐提交实施计划](../plans/2026-09-22-阶段一里程碑三硬件动作与事实闭环实施计划.md)；Pi 设备侧细节见[跨端契约](../../2026-09-22-阶段一Pi控制链自检跨端契约.md)。当前仅完成文档交接，功能尚未实现；云端部署另需现场授权。

## 1. 目标和验收边界

本里程碑在已经运行的 `SERIAL-01` Session 内完成一条可追溯的真实动作链：学生点击“检查树莓派控制链”后，Web 把动作交给 `backend_service`；后端核验 Session 和设备租约，经 `route_service` 路由到绑定的 Pi；Pi 读取自身当前运行事实并应答；后端先持久化动作与事实，再通知 Web。页面刷新、后端重启和 WebSocket 重连后，学生仍能从 Server 读回相同结果。

首个动作固定为 `inspect_pi_link`，只读取 Pi 当前控制链、身份核验状态和串口端点状态；不打开第二个串口读取者，不向 F407 发帧，不修改 Pi/F407 参数。它证明云端到 Pi 的实验动作往返，但**不等于** UART6 真实收发。下一里程碑 H1 才用 F407 的 `HELLO CNS` 回显证明完整实验链路。

退出条件是：一台真实 Pi 上，同一个 Session 的一次动作具有一致的 `action_id`、路由 `command_id`、Pi 事实和 Server 事件；重复提交与 MQTT 重投不产生第二次 Pi 执行；断开 WebSocket 后补读一致；失败与超时显示为待核验或明确失败，不伪造成功。此时串口改参、Echo、评分、结果和导出仍不开放。

## 2. 已核对的实现基线

- `main` 已有固定 Scenario、PostgreSQL Session/步骤/只追加事件、设备独占租约、访问令牌、REST/WS 补读和 300 秒超时释放。现有工作台显示 UART 未验证；`H／8N1` 动画是独立教学示例。
- `backend_service` 现有 MQTT 网关只支持 `config`、`control`；浏览器命令映射在进程内，不能当作实验动作的持久化记录。
- `route_service` 现有 `commands` 表和 `(source_id, request_id)` 幂等机制只接受 `config`、`control`；来源 ACK 可回传结果，设备 ACK 原文保存在命令表，但现有来源 ACK 对设备字段做类型专用投影。
- Pi 本地仓库 `main` 为 v1.0.1 基线，已具备持久化设备绑定与 Pi 控制、F407 业务、身份三态；主控箱串口断开不再自动关闭 Pi MQTT 控制入口。尚无实验命令接收器或 `inspect_pi_link` 应答。
- 云端已部署 Session 基座和新版工作台。里程碑二获用户“带遗留项验收通过”；既有 Web 命令入口、飞控命令、一次配置请求超时原因及部分视觉检查仍按原验收记录保留，不能写成已通过。

## 3. 方案取舍

**采用：独立 `experiment` 命令类型，复用现有 `web-console` 固定来源与 route_service 命令状态机。** 后端新增实验动作持久表；路由服务新增来源请求、设备下发、设备 ACK 和来源 ACK 分支。Pi 在当前进程中处理读事实动作。这样保持设备命令只经路由服务，命令数据库仍由路由服务独占写入，实验表仍由后端独占写入。

未采用把实验动作塞进现有 `config`：它只支持四个运行参数，成功后会触发 Pi 进程重启，无法表达本次只读检查及后续串口实验。未采用后端直发设备 topic：这会绕过既定的寻址、来源幂等和 ACK 回程。未采用另起实验服务或通用动作脚本引擎：当前只有两种固定实验，额外部署和执行边界没有收益。

## 4. 职责与数据流

```text
Web（Session 令牌、action_id）
  → backend_service（校验并持久化动作）
  → MQTT 来源 experiment/request
  → route_service（校验来源、目标和命令幂等）
  → MQTT 设备 experiment/set
  → Pi（按 action_id 去重，读取本机事实）
  → MQTT 设备 experiment/ack
  → route_service（保存设备 ACK，发布来源 ACK）
  → backend_service（保存动作结果和 Session 事件）
  → WebSocket 通知，Web 再用 REST 补读权威事实
```

Server 的权威边界仍是两部分：`route_service` 写设备核心表和 `commands`；`backend_service` 写实验 Session、动作和事件。路由命令的 `succeeded` 只证明收到了符合协议的 Pi 终态 ACK；学生页面上的“已完成”必须等后端保存这条事实，不能由 MQTT 发布回调或动画推定。

### 4.1 Session 与动作准入

`POST /api/experiment-sessions/:id/actions` 使用现有 Bearer Session 令牌，提交 `action_id`（UUID）和固定操作名 `inspect_pi_link`。后端在同一数据库事务中核验 Session 为 `running`、设备租约仍属于该 Session 且未过期、目标为绑定的 `cns_box`，并写入动作及“学生提交”事件。相同 Session、相同 `action_id`、相同内容返回原动作；同 ID 不同内容返回冲突。其他 Session 令牌和终态 Session 均不得派发。

随后后端核验 Pi 控制状态 `online`、身份为 `verified` 或 `cached`；F407 业务链离线不阻止此只读检查。身份 `conflict`/`unbound`、Pi 控制离线或 MQTT 未就绪时记录可解释的拒绝或待派发状态，不要求主控板先恢复业务。所有重试继续使用同一个 `action_id`；刷新不自动新建动作。

动作只为当前租约有效期服务。排队中的动作在租约释放、过期或 Session 终结后不得再发出。已经发出的迟到 ACK 可以作为该旧 Session 的历史事实保存，但不能重新打开 Session、占用新租约、推进新 Session 的步骤或判为新的成功。此里程碑不改变现有主动结束与租约超时语义，因为 `inspect_pi_link` 不修改现场状态。

### 4.2 分层标识与 MQTT 契约

四个标识各有用途：`session_id` 标明实验归属，`action_id` 标明学生的一次操作并贯穿重试，`request_id=action_id` 是路由来源幂等键，`command_id` 由路由服务生成并标明一次设备下发。`source_id` 固定为现有后端来源 `web-console`。原始 Session 访问令牌只在浏览器与后端之间使用，不进入 MQTT、Pi、F407、日志或导出。

新增四个非 retained、QoS 2 的 topic，均使用现有命名空间：

| 方向 | Topic | 作用 |
|---|---|---|
| 后端→路由 | `{namespace}/sources/web-console/experiment/request` | 提交固定实验动作 |
| 路由→Pi | `{namespace}/{device_id}/experiment/set` | 下发带 Session 与动作身份的命令 |
| Pi→路由 | `{namespace}/{device_id}/experiment/ack` | 返回执行状态和 Pi 事实 |
| 路由→后端 | `{namespace}/sources/web-console/experiment/ack` | 派发、失败、超时及设备结果回程 |

来源请求限定 `schema_version`、`request_id`、`target.device_id`、`session_id`、`action_id`、`lease_version`、`operation` 和短有效期 `expires_at`；有效期不晚于当前设备租约到期，首版最长 30 秒。首版 `operation` 只能是 `inspect_pi_link`，不接受任意脚本、任意 topic 或透传参数。设备下发另带 `command_id`。所有层严格限制长度、类型和未知字段；路由服务仅向 `cns_box` 且 Pi 控制在线、身份非冲突/未绑定的目标派发。

Pi 终态 ACK 至少包含 `command_id`、`session_id`、`action_id`、`operation`、`status`、`observed_at` 及受限的 `fact` 或 `error_code`。成功事实只表示 Pi 在收到动作时观测到的 `control_status`、`identity_status`、`business_status` 和 `serial_port_open`；串口状态允许为 `unknown`。`serial_port_open=true` 不能解读成 F407 响应有效。Pi 的 `observed_at` 为设备时钟，Server 另记接收与落库时间，跨端排序以 Server 事件序号为准。

成功路径的最小消息样例用于三端对齐，正式字段约束和拒绝样例在实施计划首项固结：

```json
{
  "schema_version": 1,
  "request_id": "f886f45b-01f8-4a54-b2b6-a65b07477aa1",
  "target": { "device_id": "DCDWCNS1S2MEAG1VTA0C" },
  "session_id": "c4191037-9e2a-480c-a995-2174e4672563",
  "action_id": "f886f45b-01f8-4a54-b2b6-a65b07477aa1",
  "lease_version": 3,
  "operation": "inspect_pi_link",
  "expires_at": "2026-09-22T09:00:30.000Z"
}
```

```json
{
  "schema_version": 1,
  "command_id": "7d15e276-c7e1-4f52-aaee-7314a6417667",
  "session_id": "c4191037-9e2a-480c-a995-2174e4672563",
  "action_id": "f886f45b-01f8-4a54-b2b6-a65b07477aa1",
  "operation": "inspect_pi_link",
  "status": "completed",
  "observed_at": "2026-09-22T09:00:02.123Z",
  "fact": {
    "control_status": "online",
    "identity_status": "cached",
    "business_status": "offline",
    "serial_port_open": false
  }
}
```

路由服务必须核对设备 topic 身份、活动命令 `command_id`、动作与 Session 身份和终态字段；按新类型形成来源 ACK，把允许的 Pi `fact` 原样限制性投影到 ACK，不复用配置或飞控的设备字段。路由 `dispatched`、Pi `completed`、Pi `rejected`、路由 `timeout` 和 `delivery_uncertain` 分别映射成学生可理解的状态，不把未收到 Pi 事实解释为“检查成功”。

### 4.3 持久化、重试和补读

后端增加版本化迁移，建立 `experiment_actions`：关联 Session 与设备、`action_id`、路由 `command_id`、租约版本、操作名、输入、状态、错误码、创建/派发/终结时间和短有效期；`action_id` 唯一。动作状态和只追加 Session 事件在事务内一同提交。现有 `experiment_session_events` 保存学生提交、路由派发、Pi 应答、超时/待核验的先后事实；成功事件保存经校验的 Pi 原始事实、Pi 观测时间及 Server 接收时间。重复来源 ACK 只更新同一动作，不重复追加终态事实。

后端先落库再向 MQTT 发布，不在数据库事务内等待网络。服务重启后扫描仍有效的待派发动作，按相同 `request_id` 重试；已过有效期、租约已释放或 Session 终结的动作只收敛为未派发/待核验，不再发出。派发后 ACK 丢失时可在限定窗口内重发相同请求，让路由服务按 `(source_id, request_id)` 返回既有结果。后端不得仅依赖现有进程内 `commandTracker` 关联实验 ACK。

Pi 对 `action_id` 保存有界的终态结果记录；相同动作身份和内容重复到达时复用原事实，不再次读取执行分支，不以不同 `command_id` 绕过去重；若传输层出现新的合法 `command_id`，仅在 ACK 中使用新标识关联该次路由命令。同 ID 内容冲突则拒绝。现行 route 示例命令终态保留 30 天；Pi 本轮只读终态缓存选择进程内至少 128 项、至少 300 秒，覆盖 30 秒动作有效期及有界在途重投。Pi 进程重启后不保证仍有旧采样，此极端窗口重采样也不会改变 UART 或 F407；后续会改变参数的动作必须另行满足跨重启去重契约，不能凭本次只读验收宣称已验证可变动作的崩溃一致性。设备侧完整约束见跨端契约。

后端仅在事实事务提交后向已授权的 Session WebSocket 订阅者发送 `experiment.updated`，继续使用现有 `/api/experiment-sessions/:id` 与 `.../events?after=` 补读。Web 用事件游标恢复，不把 WS 消息本身作为持久化事实。数据库临时不可用时有界暂存已收到的 ACK 并重试；若进程中断或重试窗口耗尽，则通过原 `request_id` 向路由服务重取已保存的终态 ACK。仍无法核验时记录“执行结果待核验”，不向 Web 宣告完成，也不作为学生操作错误。

## 5. Web 工作台的本轮切片

沿用已经确认和部署的浅色青绿三栏工作台，不重新设计首页或三级页面结构。中央下方只增加一个“检查树莓派控制链”入口；按钮启用条件、提交中与重试状态由 Server 返回，双击或请求超时重试复用 `action_id`。右侧状态观察区只呈现 Pi 本次真实返回的字段和采集时间；右侧操作记录区分别显示“学生提交”“已路由至 Pi”“Pi 已应答”“Server 已记录”或相应失败。页面不把 Pi 控制可达、串口端点打开和 UART6 通信恢复混为一态。

当前 `H／8N1` 播放器继续标为教学示例；本轮 Pi 自检不会驱动其波形、点亮真实 UART 链路或推进七个串口步骤。F407 当前波特率仍为待核验，不填写默认值。若无真实设备可用，开发模拟器可展示协议和异常状态，但云端验收只认可真实 Pi ACK 与 Server 存档。

## 6. 失败语义与验证

| 场景 | 必须观察到的结果 |
|---|---|
| 重复点击、HTTP 重试、MQTT 重投 | 同一 `action_id` 和原结果；Pi 不产生第二次执行记录 |
| 相同 ID、不同参数或不同 Session | 明确冲突或拒绝；不派发 |
| 设备忙、租约失效、令牌错误 | 在后端拒绝；路由服务无新命令 |
| Pi 控制在线、F407 业务离线 | 只读检查仍可派发；事实如实显示业务离线 |
| Pi 离线、身份冲突或目标不是主控箱 | 不派发，保留可解释记录 |
| 路由派发后 Pi 拒绝或超时 | 显示拒绝、超时或待核验，不显示成功 |
| ACK 重复、乱序、迟到或目标不匹配 | 不产生重复终态；不污染新 Session；异常可追踪 |
| 后端重启、WebSocket 断线、页面刷新 | 从数据库和事件游标恢复同一动作，无新动作 |
| Session 到期或主动结束 | 未派发动作停止；旧 ACK 只归旧 Session 历史 |

本地先验证共享协议、路由状态迁移、后端数据库事务与重试、Pi 去重、前端恢复；PostgreSQL、Broker、systemd 和真实设备集成在云端按已确认提交执行。云端迁移只增量建表或扩展命令类型约束，必须可重复运行并保留旧数据；发布前备份结构与相关数据，部署后验证现有配置/飞控路由无回归。验收记录写明 Server、Pi、F407 固件版本与实际设备 ID；F407 本轮未改、未参与自检应如实注明。真实设备动作由用户指定可测试窗口，禁止把模拟 ACK 当成现场验收。

## 7. 跨端任务与后续衔接

| 端 | 本里程碑交付 | 依赖 |
|---|---|---|
| `backend_service` | 动作准入、持久化派发、ACK 落库、事件补读与 WS 通知 | 已有 Session/租约；route_service 新实验类型 |
| `route_service` | 实验命令解析、目标权限、命令表迁移、设备派发、ACK 回程和重启收敛 | 冻结的跨端样例；Pi ACK 适配 |
| Raspberry Pi | 同一 MQTT 进程处理 `inspect_pi_link`，返回自身事实并按动作 ID 去重 | 本文确认后的消息样例；现有持久化绑定/运行三态 |
| Web | 工作台自检入口、事实/阶段状态、操作记录和断线补读 | 后端共享协议与事件 |
| F407 | 无代码任务；保持当前固件 | H1 里程碑另行接入 Echo |

本轮先冻结跨端消息样例并交给 Pi 开发方，Server/Web 可并行实现模拟验证；真实闭环必须等 Pi 候选提交部署到设备后验收。里程碑三通过后，再设计 H1 的 UART6 受控 Echo、F407 实际波特率和原始 TX/RX 事实，不以本轮 Pi 自检替代 H1。

## 8. 实施前需核验的现场事实

这些是实施输入，不改变上述产品选择：云端当前 route_service 命令保留时间和固定来源配置、Pi 实际运行版本与新增实验 topic 的配置位置、设备 `device_id` 与控制三态、联调窗口及 F407 固件版本。若核验发现 Pi 无法在 F407 失联时接收本地实验命令，或现有 MQTT/数据库策略无法保证同一动作的结果追溯，应先修正设计并请用户确认，再写实施计划。
