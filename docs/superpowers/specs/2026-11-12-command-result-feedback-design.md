# Pi 命令结果提示设计

用户要求：Pi 处理命令后向 F407 发成功/失败两种提示，F407 自行控制蜂鸣器和灯光。用户已明确按命令最终处理结果反馈，进行中不提前报成功。帧格式与 Pi 实现由用户授权确定。

## 实现选择

复用唯一 F407 UART 上的 MAVLink 2 `TUNNEL`：不新增串口，不修改自动生成的 MAVLink 头文件。相比另造 UART 帧，可以复用现有组帧、校验和动态端点；相比 `COMMAND_LONG`，提示无需再应答，不与业务控制命令事务混用。

`payload_type=0x8040`，`payload_length=2`，数据为 `version:u8=1 | result:u8`。`result=1` 成功，`result=0` 失败；其他值无效。只有结果，不传颜色、音调、时长或云端标识。源与目标 system ID 都沿用当前 F407 system ID，源 component=191，目标为已确认 F407 component（当前 193）。MAVLink CRC 覆盖完整消息，不再添加内层 CRC。

## 命令范围与时机

- 配置 `config/set`：`applied`、`already_applied` 为成功，`rejected` 为失败。配置成功指保存/热应用成功；需要重启的配置在退出前提示。
- 控制 `control/set`：F407 的最终 `accepted` 为成功；`rejected`、`timeout` 为失败。`in_progress` 不提示。
- 实验 `experiment/set`：最终 `completed` 为成功；`rejected`、`failed`、`timeout`、`cancelled` 为失败。等待异步动作完成后再提示。采集开始命令成功表示采集已建立，不表示整个实验结束或结果合格。
- 本设备 Topic 上无法解析而明确被拒绝的请求提示失败；非命令数据不提示。
- 提示发生在结果形成时，不等待 MQTT ACK 交付。提示写入失败不更改业务结果，也不触发额外控制事务。

## 重试与链路

进程内保存最近 128 个提示键：设备身份、命令通道、`command_id`（实验使用 `action_id`）和成功/失败值。重复终态与 MQTT ACK 重试不重复响；同一标识的不同结果仍可提示。身份变化清空缓存。实验参数非法时仍提取可读取的非空 `action_id` 用于提示去重，不生成业务 ACK；无法取得标识的解析失败逐条提示。

只向已核验身份的当前端点发送。无串口、身份冲突或端点复核中不发送，也不在重连后补发离线期间的提示；不持久化提示队列。历史 H1/M1 ACK 恢复不重新触发提示。F407 不为提示返回 `COMMAND_ACK`，避免形成反馈循环。

## 验证与交付

单测覆盖成功/失败映射、进行中、重复结果、身份变化及官方 MAVLink 编解码，尤其失败结果末尾零字节的 MAVLink 2 截短。进程测试运行真实 `cns_rpi`，通过 PTY 和 Mosquitto 覆盖配置、实验、控制的成功、拒绝、异步 ACK、进行中和超时。

本轮只改 Pi 仓库及对接文档，不修改 F407 固件，不推送或部署设备。F407 解析和灯光/蜂鸣效果需要固件侧接入后联调。
