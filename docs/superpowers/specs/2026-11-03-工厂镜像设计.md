# 预装维护服务的工厂镜像

## 目的与范围

维护一份可重建的 Pi 5 / trixie ARM64 通用出厂镜像。同一镜像烧录后直接上电，首次启动无需下载或安装软件，即可启用 5G 和业务程序。运行中从 F407 自动获取设备编号，服务器人工确认设备后下发专属维护令牌，再开放现有 Web 指定版本更新。

用户已将实现方式交给维护者；以下选择由维护者作出，不增加设计确认步骤。

## 方案

采用 Raspberry Pi 官方 rpi-image-gen 的固定提交生成系统镜像，加入 CI 已验证的发布包和运行依赖。相较于复制现场 SD 卡，这能保留构建来源并避免携带样机身份；相较于维护程序首次联网自安装，这能避免只有 5G 的设备尚未安装拨号依赖的循环。

通用镜像预装业务基线、5G 拨号、维护程序及登记客户端，创建无默认密码的 `dcdw` 运行用户，使用普通可写根目录。构建时给出通用业务配置和服务器地址，不包含独立编号或凭据。镜像配方、构建脚本和手动构建工作流纳入仓库；不在每次业务提交时重建整盘镜像。

## 首次启动

本次用户明确选择同一镜像直接上电、服务器端确认后开通更新；取代先前逐台写 boot 配置的设想。镜像包含通用 `/var/lib/cns-rpi/config.json` 和 `/etc/cns-rpi-enrollment.json`（schema_version、server_url、business_config，可选 ca_file），不含正式维护配置、令牌、绑定文件或已使用的机器身份。

构建时使用真实 ARM64 程序与拨号解析器校验通用业务配置，配置与蜂窝接口匹配的 NetworkManager DHCP profile，禁用默认 networkd/iwd，启用 NetworkManager。业务、拨号正常启动；登记 timer 每 60 秒读取已有 `identity.binding_file`。首次尚未连接 F407 时正常等待，不自行读串口。真实绑定存在后生成随机 enrollment_id 和 claim_secret，root 0600 原子保存后经 HTTPS 提交，重启复用相同请求。

服务器保存待确认登记及 claim_secret 哈希；管理员确认具体登记后，为该设备创建 node_id/token 和 device_id→node_id 关联。后续相同登记必须携带匹配 secret 才能取得令牌，不能仅凭公开编号领取。未批准只返回 pending，拒绝返回 rejected；批准返回 approved、node_id、token。Pi 验证后原子写入 `/etc/cns-rpi-maintenance.json`，维护 poll 随后开始。内部 node_id 由服务器分配，无需人工输入，也不要求与 F407 字符串相同。

离线安装复用 Installer 的版本校验、目录发布、组件链接与 unit 安装；与配置导入、在线运行观察分开。现有正式配置存在时登记客户端不再申请；绑定或登记服务器变化拒绝自动改绑。无凭据时维护 service 的条件跳过执行，不影响业务/5G。网络或服务器故障不影响已保存登记，下一轮 timer 继续提交。

## 发布与验证

镜像工作流明确选择源码提交构建同源 ARM64 包，再生成压缩镜像、摘要和构建记录。构建记录包括源码 SHA、发布包 SHA、image-gen SHA 和已安装包清单。镜像不含共享更新凭据；构建配置不打印业务认证内容。生成镜像不等于发布；实际烧卡启动、登记审批和仅 5G 连接服务器由硬件验收单独记录。

服务器新增登记 API 与审批操作作为跨仓库接口契约，本工作线只实施 Pi 客户端；不擅自改动服务器仓库。不做远程整盘/内核更新、不自动升级维护程序，也不将实体设备上的卡反向复制为公共镜像。无默认 SSH 密码；现场恢复方式写入部署说明。
