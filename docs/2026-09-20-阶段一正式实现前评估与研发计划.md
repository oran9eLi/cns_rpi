# 阶段一正式实现前评估与研发计划

日期：2026-09-20

状态：设计与里程碑一（G0）详细实施计划已于 2026-09-20 获用户确认，功能编码尚未开始。阶段范围、技术架构、跨端边界、恢复方式、互斥规则和验收标准已收敛；实施前只剩串口节点、基准波特率 B0、固件实际行为和云端环境参数等客观事实核验，不再视为待用户决策的设计问题。本文中的任务和 10 天安排是研发路线，不替代后续按提交拆分的实施计划；后续里程碑继续按总索引滚动编写和确认。本文不代表功能已实现或现场验收已通过。

## 1. 评估结论与范围

现有系统具备设备接入、最新状态展示、受控命令往返和单机部署基础，可以承载两个教学实验的开发。但它目前是设备管理系统，尚未实现实验会话、步骤、场景、过程存证、评分或实验导出。阶段一属于在既有链路上增加实验子系统，不能按“补两个页面”估算。

最先需要解决的是四个前置条件：当前树莓派与服务器的注册、遥测协议已经不一致；Pi 的网络控制生命周期仍依赖主控板串口；Pi 侧串口映射待核验；现有最新值缓存不能作为完整实验记录。建议先恢复约定版本的业务基线并拆开网络控制与主控板链路状态，尽早贯通一轮 UART6 真实收发，再补齐考核和气压双模式。

本阶段交付范围：

- 两种实验定义：串口通信、气压高度原理与仿真测高；两个标准场景 `SERIAL-01`、`BARO-01`。
- 公共对象覆盖 Experiment、Scenario、Session、Step、Action、Realtime Data、Log、Result、Checkpoint、Evidence、Score。
- Server 权威维护实验状态、操作事实、评分和历史记录；Web 引导操作，Pi 提供真实执行事实。
- 串口取得 UART6 真实往返证据；气压包含真实观测，以及不依赖 Pi 在线的软件仿真。
- 里程碑顺序固定为 H1 单次 HELLO CNS 真实往返检查点 → M1 串口实验完整闭环独立验收 → M2 气压双模式闭环 → 阶段最终验收。M1 必须包含匹配—失配—恢复、真实数据、日志、证据、确定性评分、结果回看和 CSV/JSON 导出；H1 不能代替 M1。阶段一只有在 M1、M2 和最终回归均通过后完成。
- 多台设备允许分别承载多个学生的并行实验；同一 `device_id` 同时最多一个活动硬件 Session，由 Server 持久化独占租约并原子判定，不能只依赖进程内互斥锁。纯软件且不绑定设备的仿真不占设备租约。
- 场景可复现、评分确定、记录可追溯、CSV/JSON 可导出。

QGC、服务器 5760 原始 MAVLink 通道、mavlink-router 双路改造和 Mission 闭环继续属于总体 V1.0 后续路线，不列为本次两个实验的前置工程。AI 报告、精排 PDF/DOCX、复杂账号/课程、多实验并发调度、插件市场和千设备容量验收不阻塞本阶段。

网口收发不再属于本阶段两个实验。后续将 `NETWORK-01` 作为独立第三实验重新设计，可使用 Pi 以太网口和学生电脑轻量回显程序，但其协议、电脑端程序、SSH 接口复用、评分规则及验收不进入当前 10 天任务，也不阻塞串口和气压闭环。

交付优先级已确定为“最快、最简单地完成真实闭环”，不追求本阶段的整体最优架构。两个方案都能满足闭环 Demo 时一律选择实现、部署和操作更简单的方案，不为潜在扩展增加当前复杂度。先做到一个会话、一条动作、一份 UART6 真实收发记录贯通，再补评分和导出，最后用同一套薄公共能力接入气压实验；不先建设完整通用框架。简化的是实现和扩展能力，不删减已要求的真实收发、独立控制恢复、可复现、存证、确定性评分和 CSV/JSON 导出。

并行分工已确认：本开发代理负责 Server/Web 及跨端契约统筹，Pi 和 F407 分别有开发人员/代理，任务与反馈由用户转达。可转发材料见[树莓派与主控板任务交接清单](2026-09-20-阶段一树莓派与主控板任务交接清单.md)。这确认了人员分工，不等于实际接口、现场可用时间和跨端协议已经核验。

实验一详细设计见[串口通信交互流程与实现约束 v0.2](CNS实验一_串口通信交互流程与实现约束_v0.2.md)。已确认学生可现场复位 F407，随后通过 Web 恢复 Pi 参数并验证；UART 启停教学仿真只在 backend_service 的当前实验 Session 内生效，不下发设备端、不影响真实串口或设备总览。速率对比已确认同时保留 Pi 实测 RTT 和按 8N1/实际帧字节数计算的理论串行时间，评分不要求高波特率实测 RTT 必然更小。本设计已无其他待用户确认的架构选择；实际参数和报文字段在 G01/G02 中根据真实代码与实板核验后固结。

部署边界已更新：PostgreSQL、Mosquitto、route_service、backend_service、前端静态资源和 Nginx 最终统一部署到云服务器，树莓派直接连接云端服务。硬件服务器 `192.168.11.3` 及云端 frps 转发到硬件服务器 frpc 的旧链路仅是历史部署，不再作为开发依赖或阶段验收环境。云服务器系统、正式入口、端口、服务账户、数据迁移和回滚方案须在实施计划前补齐；本轮不据旧硬件服务器配置推断云端参数。

### 2.3 与现状冲突、必须显式处理的设计

| 冲突 | 证据和影响 | 建议处置 |
|---|---|---|
| 注册协议版本与身份字段不同 | Pi 的 `registration_payload.cpp` 发布版本 3、`device_id`；Server 的 `device_message.cpp` 要求版本 1、`vendor_id`，在线还要求学校 | 阶段一先支持当前主控箱的新版注册，保留旧设备数据和既有对外字段兼容；无学校真实飞控的全面模型迁移另排 |
| 遥测 topic 不兼容 | Pi 发布 `/telemetry/snapshot/v1` 和 `/telemetry/realtime/v1`；Server 只订阅 `/+/telemetry`，解析器拒绝额外层级 | 先接入完整快照；禁止直接把实时子集当完整快照覆盖。需要高频预览时才按设备订阅，禁止常驻通配消费所有高频流 |
| “发布次数”不等于“传感器采样次数” | Pi 从缓存生成新 JSON，`sent_at` 随发布更新；气压缓存没有独立的接收新鲜度记录 | 实验采样依据新传感器事实及有效性，不能重复计算同一旧样本；`time_boot_ms` 的主控含义还要核验 |
| 教学断链与网络控制耦合 | Pi 的 `SerialPort::Open` 使用独占锁；`main.cpp` 串口断链时关闭 MQTT 并清身份；创建 MQTT 和消费配置消息也依赖已取得的主控板身份 | 明确复用同一串口；解耦 Pi 网络控制，串口只有一个受控持有者。不能只删掉关闭 MQTT 一行，必须覆盖身份、启动、收消息和重连条件 |
| 恢复动作被离线校验阻断 | 后端 `deviceRoutes.ts` 拒绝离线目标；路由命令策略也检查目标状态 | 分离“Pi 控制可达”和“主控板业务链路正常”；仅为经过验证的 Pi 本地恢复动作按控制可达性放行，不放开离线主控板普通控制 |
| 把配置命令用作实验参数设置 | 现有远程配置只有四个运行参数，应用成功后请求进程退出重启 | 实验参数走独立动作，不用每次重启来修改波特率、载荷或仿真输入 |
| 最新状态与完整证据混用 | 设备遥测是 QoS 0、可丢弃；数据库合并只留最新值；Web 内存只留近期命令事件 | 实验证据采用独立追加存储和确认机制，显示可合并，评分事实不能静默覆盖 |
| 既有读权限与实验写入冲突 | 后端目前不具备实验表、写权限或迁移入口 | 新增实验存储边界和最小写权限；核心设备、来源与路由命令表仍归 route_service |
| 里程碑命名曾不一致 | 历史甘特图曾把 HELLO CNS 最小往返称为 M1 | 相关文档现已统一：最小真实往返称 H1，含评分/导出的完整串口教学闭环称 M1，避免提前宣告验收 |
| 千设备发布门槛与本次范围不同 | Pi 迁移文档提出千设备压测，但没有服务端实现或验收证据 | 本阶段按确认的教学规模验收，千设备测试列后续；不宣称容量已达标 |

这些不兼容结论针对已检查的两份本地代码和默认协议；现场可能运行旧版本，不能据此断言现场当前已经故障。

## 3. 阶段一技术架构

### 3.1 已选路线与取舍

| 路线 | 职责组织 | 对本阶段的影响 |
|---|---|---|
| A：在现有 backend_service 增加实验模块，采用 | TypeScript 承担会话、场景、规则评分、仿真和导出；C++ route_service 承担设备路由；Pi C++ 承担执行 | 复用现有 REST/WS、数据库连接及部署；后端只新增实验存储写权限，不写核心设备表 |
| B：独立 C++ experiment_service | 新 C++ 服务管理实验和评分，后端继续充当 Web 网关 | 便于以 C++ 维护业务，但增加服务部署、内部接口和跨服务恢复工作，10 天压力更大 |
| C：实验业务全部放入 route_service | 路由服务兼管步骤、评分、记录和软件仿真 | 数据写入集中，但扩大核心路由故障影响，Web 教学逻辑与路由耦合；不建议作为本阶段路线 |

用户授权以速度和简单性优先，据此选定路线 A。B/C 作为本轮已比较但不采用的路线保留，不再逐项讨论。下面任务和排期均按 A 编制；“Assessment Service”等名称仅表示现有进程内的代码模块，不是新增微服务。代价是首版页面和处理逻辑会直接绑定这两个实验，后续第三类实验可能需要调整代码；本阶段接受这项取舍。

### 3.2 职责与链路

```text
Web 引导页 ←REST / WebSocket→ backend_service 实验模块
                                  ├─ Scenario / Session / Step
                                  ├─ Log / Evidence / Score / Result / Export
                                  ├─ 气压仿真计算
                                  └─ 实验专用持久化存储
                                              │
硬件动作：实验模块 → MQTT → route_service → MQTT → Pi 实验执行器
动作回执：实验模块 ← MQTT ← route_service ← MQTT ← Pi
真实证据：实验模块 ← MQTT 实验证据事件 ← Pi ← UART6 被测链路/已有传感器
设备总览：保持既有 route_service → 数据库/状态事件 → backend_service → Web
```

实验模块只提交受控来源请求，不直接向设备发布动作；路由服务不负责判分。实验数据事件复用现有 Broker，但使用与可丢帧设备遥测不同的证据语义。Server 校验设备、会话、步骤、动作、轮次及事件归属后，才将 Pi 上报视为评分事实。

Server 内部写入边界：route_service 继续唯一写入 schools、devices、device_latest_states、command_sources、commands；backend_service 中的实验模块唯一写入实验会话、追加事件/原始数据、证据、学生提交和结果。复用同一个 PostgreSQL 实例，隔离实验存储权限；不要求每个概念都建一张独立表。版本化迁移不得改写旧迁移或覆盖现场数据。

### 3.3 最小公共模型和状态

| 对象 | 阶段一最小职责 |
|---|---|
| Experiment / Scenario | 固定文件定义两类实验和两个标准场景；包含版本、初始条件、步骤、允许动作、计算模型、评分规则及公开/隐藏内容 |
| Session | 创建时保存场景和规则快照；绑定设备或纯软件环境；设备绑定会话在操作前取得该 `device_id` 的持久化独占租约；Server 仅保存随机访问令牌摘要，浏览器保存原始令牌；独立于单次连接，支持查询、刷新恢复和归档 |
| Step / Action | Server 验证步骤前置条件、参数和允许动作；点击下一步或命令发出不能替代执行证据 |
| Realtime Data | 向页面提供实时观察；明确来源、单位、采集/接收时间和有效性；可限频显示，但不减少应保存的实验事实 |
| Log / Evidence | 追加保存接收、执行、失败、重试、提示、参数变更、采样、取消和恢复；原始收发/采样批次可定位，重复事件不重复存证 |
| Checkpoint / Score | 固定规则引用有效证据确定得分；保存规则版本、判定原因和证据引用，支持重算 |
| Result | 会话终态、学生提交、统计、分项得分、总评有效性及可发布结果；可查询和导出 |

会话采用需求文档的 `created`、`running`、`completed`、`cancelled`、`failed`；动作派发状态和评分状态单独表示。完成实验不等于及格。缺证和基础设施失败保留已确认分项，但总评标为无效或待重做，不自动算作学生答错。阶段一唯一产品目标是让一名学生通过 Web 完成一次真实、可追溯、可评分、可导出的实验闭环 Demo；不建设教师端、教师鉴权、全班会话管理或教师专用结果视图。

已确认首版按 `device_id` 互斥：每台实验设备只允许一个活动硬件 Session，不同设备可并行，纯软件且不绑定设备的仿真不占硬件资源。backend_service 必须通过数据库事务和唯一约束或等价的持久化租约原子取得占用，不能只用进程内 mutex；创建/启动竞争只有一个成功，其余返回明确“设备已被某活动 Session 占用”，且不得向 Pi 派发动作。仍要防止两个浏览器同时操作同一会话；不建设排队调度。

会话归属采用阶段一最小访问保护：Server 创建 Session 时生成高熵随机访问令牌，只向创建者返回一次并仅保存令牌摘要；Web 将原始令牌保存在当前标签页的 `sessionStorage`，页面刷新后以同一 `session_id` 和令牌读取 Server 权威状态、恢复实时订阅并继续心跳，不创建新 Session、不重新抢占设备，也不重放已经提交的动作。Session 的查询、心跳、动作、提交、结果和导出均校验令牌；无令牌、错误令牌或其他 Session 的令牌不得访问或续租。令牌不得进入 URL、日志、MQTT、Pi 或 F407。关闭标签页后令牌可消失，设备仍按既定 300 秒租约超时规则释放；本阶段不建设学生账号、跨浏览器接管或令牌找回。

租约有两条释放路径。正常路径是学生点击结束实验，Server 停止新动作并进入现场恢复流程；Pi 回到 B0，学生现场复位 F407 回 B0，并取得新业务帧和报告实际 B0 的真实 Echo 后，Session 进入终态并立即释放租约。兜底路径是 Web 当前实验页面每 30 秒发送 Session 心跳，正常实验操作也续租；Server 每次有效续租把到期时间更新为当前时间后 300 秒。300 秒未续期时，Server 原子释放租约并将原 Session 标记为超时/遗弃，记录释放原因，不尝试远程复位 F407，也不维护 `recovery_required` 设备状态。

为避免超时释放后的未知 UART 状态污染下一次实验，每个新硬件 Session 在普通实验步骤前必须重新建立基准：取得设备租约后，页面提示学生现场复位 F407，Server 经独立控制把 Pi 设置到 B0，然后等待新业务帧和报告 F407 实际为 B0 的真实 Echo。基准未验证时禁止进入改参、发送和评分步骤。浏览器瞬时断开不会立即释放，最多保留到租约到期；Server 重启后从持久化的最后续期与到期时间恢复判断，不自动重做有副作用的发送。

必须分离 Pi 网络控制可达、UART6 业务通信状态和实验执行状态。场景允许的串口失配是可观察的实验现象，Session 可继续等待学生恢复，不直接转 failed；5G/MQTT 失联、Pi 崩溃、不可补证等才按基础设施异常处理。正常结束/取消时如果尚未取得恢复证据，本 Session 保持“恢复未完成”，租约继续有效，并保留可用的 Pi 本地改参入口；若此后停止续租并达到 300 秒，则按超时/遗弃终结旧 Session 并释放租约，不生成设备级待恢复状态。

### 3.5 证据、复现和访问边界

- 每个会话冻结场景与规则快照；每轮收发单独关联 attempt，禁止拼接不同轮次的成功数据。默认按需求中的“最后一次完整轮次”评分，提示/重试不额外扣分，变更规则必须新发版本。
- 操作、设备事件、原始载荷和学生填写值分开标识。记录时间、会话、设备、步骤、动作、参数、新旧值、结果和关联标识，失败请求也留痕。
- Pi 在 Server 确认保存前保留有界待确认事实；网络重传复用事件身份，不能再次执行动作。无法恢复的缺口明确阻止有效总评。MQTT 发布完成不能替代 Server 持久化确认。
- 原始数据指本次实验的实际收发字节、采样值及关联元数据，不是常驻抓取全部业务 MAVLink 流。采样时长、载荷长度、轮次数量及缓存上限随场景固定，避免把本阶段扩成全量遥测历史平台。
- RTT 在 Pi 同一单调时钟上计算；Server 接收时间用于归档排序，不以跨机墙钟相减或浏览器耗时替代链路 RTT。串口速率对比还保存实际请求/响应帧线上字节数，并按 8N1 每字节 10 bit 由 Server 计算理论串行时间；该理论值不含主控处理和本地调度。实测 RTT 与理论值分别展示和评分，不要求高波特率实测 RTT 必然更小。真实气压保留设备时间信息和 Server 接收时间，不能把发布时间当采样时间。
- 学生只能提交动作和答案，不能提交“执行成功”“最终得分”等权威结果。Server 分别生成进行中视图和提交/终结后的结果视图；隐藏目标、答案和详细评分结果不得通过接口、WebSocket 或导出提前泄露。提交或终结后，同一 Session 令牌可以读取本次实验的分项证据、得分、原因和允许导出的记录。
- 学生 Session 访问已确认使用高熵随机令牌：Server 仅存摘要，Web 在 `sessionStorage` 保存原始值，刷新后继续同一 Session；所有会话读写、心跳、实时订阅和导出均验证令牌。令牌不进入 URL、日志或设备链路。本阶段不引入学生账号、跨浏览器接管或令牌找回，也不设计教师鉴权与教师端。
- CSV 分别导出日志、收发/采样明细及评分；JSON 导出允许访问的完整记录。完整结果内的证据引用应全部可解析；统一 UTF-8、时区、单位和数值精度。导出权限与页面一致。

### 3.6 两个实验的执行边界

串口方案已确认：树莓派现有串口接口 ↔ F407 UART6，复用业务链路，不采购/假定 USB 回环或空闲接口。UART6 是 F407 端名称，Pi 侧不能据此写成 `/dev/ttyS6` 或固定某个 `/dev/ttyUSB*`。本地 systemd 模板指向 `/var/lib/cns-rpi/config.json`，示例为 `serial.device=auto`、`baud=115200`；现场实际配置、自动发现结果和接线映射尚未取得。Pi 旧文档出现 UART1/USART1，是历史记录，与本次用户确认的 UART6 不能混用。

教学步骤为双方匹配通信 → 调整一侧或双方参数 → 观察无有效数据 → 经独立网络控制修改 Pi 参数 → 重新匹配 → 回显和业务通信恢复。考核目标是双方参数匹配、学生能用证据完成恢复；115200 只可能作为冻结的初始参数之一，不是唯一正确答案。Pi/主控板共同支持的波特率集合须核验后写入场景，其他帧格式首版优先固定以控制范围。

F407 明确新增 UART6 上的受控实验请求/响应，与原业务消息区分，携带可配对的轮次/序号、测试内容及 F407 从自身当前已应用 UART6 配置取得的实际波特率；不能把接到任意字节就回显作为默认行为，也不能把请求内的目标波特率原样当成实际值返回。Pi 复用现有串口持有者分发业务与实验消息，不额外启动第二个读串口进程。实验期间暂停自动发现或重置波特率等会干预学生观察的动作，超时只记录实际观察结果。

独立网络控制须在 UART6 无有效帧时仍能接受并应用 Pi 本地串口参数，并返回实际应用结果；不经 F407 转发、不等待再次取得主控板身份、不靠每次重启整个 Pi 程序生效。Pi 持久化最近一次由真实 F407 身份帧验证通过的 `device_id` 绑定，失配期间即使 Pi 重启，也可用该缓存身份重新建立 MQTT 控制连接并接收 Pi 本地恢复动作。缓存绑定只证明这台 Pi 的控制归属，不能据此宣告 F407 在线、业务链路正常或产生新身份事实。F407 身份重新出现后必须核对；一致时刷新验证记录，不一致时立即阻止本 Session 后续实验动作、记录绑定冲突并要求人工处理。首次启动或缓存丢失时不接受人工填写、自行生成或部署预配置的 `device_id`；Pi 必须先在 B0 下取得真实 F407 身份并原子持久化验证绑定，在此之前不得进入设备实验或接受设备定向动作。

真实产品形态中 Pi 与 F407 固定安装在同一实验箱内，阶段一按一对一固定配对实现，不建设 Web/API 换绑、远程换绑、自动搜索替代主控板或多 F407 选择。身份不一致只显示冲突并阻断动作，不自动改绑。若维修时确实更换 F407，由维护人员在 Pi 本地停止服务、清除绑定缓存并重启，再以 B0 从新 F407 的真实身份重新建绑；该维护流程不进入学生实验页面。

双方波特率都由 Web 修改已经确认，不以增加主控板本地设置页面为前提。操作分为“修改 F407 参数”和“修改 Pi 参数”，允许学生只改一侧后观察失配；不能由平台自动同时对齐双方参数，从而跳过教学过程。

首版固定采用以下最小切换过程：在旧参数仍匹配时，Pi 向 F407 发送改参请求；F407 校验参数后，仍使用旧波特率返回“已接受”；该回执完整发送后，F407 在安全的串口重初始化点切换到新波特率，参数只存 RAM。Pi 不自动跟随 F407 切换，链路按教学目标进入无有效数据状态；学生再经 Web→Server→5G 独立控制链修改 Pi 本地波特率。双方重新匹配后，必须取得新的真实 Echo，并由响应报告 F407 当前实际波特率，才确认切换成功和通信恢复。如果“已接受”回执丢失，Server 只记录“结果待核验”，不盲目重发、不宣告成功；学生可把 Pi 切换到目标值后用新 Echo 验证实际结果。首版不增加定时同步、双端自动同时切换或独立 F407 配置查询命令；具体字段和有限参数白名单在 G02 固结。

失配后，F407 改参入口应提示当前无法交付；Pi 改参入口继续可用。不能显示“F407 已设置成功”来替代实际生效证据，也不能经失配串口盲目重发 F407 改参。Server 保存已请求参数、由最新匹配 Echo 确认的参数、确认时间及待核验状态，Web 只展示已知事实；请求值、接受回执和历史值都不能冒充当前实际值。F407 实验波特率仅存 RAM，现场复位后回到启动默认业务参数 B0，不写 Flash；B0 数值及固件行为仍需实板核验。

恢复方案已确认：学生现场复位 F407 → F407 启动回 B0 → Web 经独立网络将 Pi 调回 B0 → 等待新的有效业务数据 → 真实 HELLO CNS 回显 → 确认恢复。只复位 F407，不把断开 Pi/5G 作为默认操作；不新增远程复位、自动波特率扫描、定时回退或教师专用恢复页。Web 提供现场操作引导，Server 区分人工声明、Pi 实际参数和新通信证据；点击“已复位”不能直接判成功。正常结束只有取得恢复证据才立即释放；未取得时继续显示本 Session 的恢复进度并保留 Pi 本地改参入口。若最终租约超时，则结束旧 Session 并释放，由下一硬件 Session 的强制基准步骤重新建立现场。

验收要包含“F407 接受切换但随后响应丢失”“双方参数未知/失配”“失配中 Pi 重启”及“现场复位 F407”。预期复位不等于 Pi 离线或整个实验失败。现场复位属于退出清理/兜底，不能替代学生在教学步骤中仅调整 Pi 参数完成的匹配恢复考核；二者分别记录和取证。

网口实验已经从阶段一移出。后续独立第三实验的候选路径是 Pi 以太网口 ↔ 学生电脑轻量回显程序，Web 通过云端读取由 Pi 回传并由 Server 保存的收发事实；普通浏览器不直接监听任意 TCP/UDP 或原始网卡。该候选尚未形成正式设计，本阶段不开发电脑端回显程序、不冻结 `NETWORK-01`、不验收以太网/SSH 共存，也不把云服务器作为实验对端。

气压真实模式复用主控板采集，经 Pi 按会话取得有效新样本；主控板不伪造气压。仿真由 Server 计算，保存输入、模型和基准，Web 显示来源及曲线。沿用需求给出的固定基准和两个目标点；冻结正反一致的计算模型、有效范围、精度及容差后才能产出标准答案。真实基准探索不是固定场景验收的前置条件，可在标准场景完成后增加。

## 6. 并行与串行关系

必须串行的主路径：

```text
接口/版本核验与最小边界冻结
  → G02 最小契约和固定场景
  → Server/Pi/Web 按契约并行
  → H1 一次真实往返
  → M1 串口完整评分与导出
  → M2 气压双模式复用
  → 异常/教学验收与版本冻结
```

可以并行：Server/Web、Pi、F407 三条工作线已有人负责，用户负责跨团队转达。S01/S02 协议兼容、P00 控制解耦与 B00/B02 硬件核验可并行；G02 后 Server/Web 推进最小会话和页面，Pi 推进 P01/P02/P03，F407 推进 B01/B04，必须共享消息样例。Server 与 Web 由本代理统筹，按接口先行、页面跟进安排，不默认额外存在一支独立 Web 团队。气压模型验证和真实传感器核验可提前，不占用首个闭环修复资源。

上述任务均按最小可运行部分推进：H1 只需要会话、一条动作、真实收发事实及页面回显，不等待所有场景、权限页面、评分和导出全部完成；这些是 M1 的验收门槛。不得把“公共模块全部写完”设为首次真机联调的前置。

必须等待：失配实测先通过 P00/P09/S17 的控制独立性验证；P04 等待 UART6 回显；两端改参等待切换/恢复契约；S11 等待可核验的串口收发事实；正式评分等待规则和容差冻结；M1 等待 `SERIAL-01` 及导出；M2 复用 M1 的会话/证据模块。P05 和 `NETWORK-01` 不在本阶段依赖链上。

## 7. 建议的 Git 提交粒度

每个任务表叶子项原则上形成一次独立可审查提交，目标是一个可运行/可验证效果，不按“把所有文件先建好”拆提交。较大的 S06、S08、S15 可按契约与迁移、业务实现、恢复行为拆成连续提交，但每个提交须可构建，不能单独上线不兼容的一半协议。

示例：`feat: 兼容主控箱新版注册消息`、`feat: 持久化实验会话与步骤状态`、`feat: 增加串口实验逐条收发证据`、`feat: 按冻结规则计算串口实验得分`、`test: 验证实验取消与断线后的资源释放`。

设计和计划文档在主工作区编写；实施时使用隔离工作树。建议按“接入基线、H1、M1、M2、最终验收”集成，每阶段合入可运行结果，再进入下一阶段。跨端部署记录 Server/Pi/固件三个提交号和场景版本，不用“都拉最新”代替版本矩阵。

新确认的契约、边界或验收标准同步本文件、阶段一路线/排期、相关子项目 README 和协议文档；树莓派变更同步其设计及对接文档。旧文档中的未来设想继续标为规划，不因本计划存在就更新为已实现。
