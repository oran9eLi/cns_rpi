# V1.0.5 发布说明

版本：`v1.0.5`。发布日期：2026-10-23。

工程版本为 `1.0.5`。本版本在 V1.0.4 基础上增加第二阶段链路排障实验的 Pi 端临时控制，并修复阶段一 H1/M1 动作去重记录中已过期终态未及时回收的问题。受控设备身份与现有 MQTT Topic 不变；本版本不修改 F407 固件或 Server/Web 协议。

## 主要变化

- 支持 `link_lab_set_cellular`、`link_lab_set_baud`、`link_lab_set_status_reporting` 和 `link_lab_restore` 四类受限实验动作。教学 5G 断开只作用于发给 F407 的 `RPICELL` 在线位，不改变真实拨号、MQTT 控制链或遥测中的真实 5G 状态。
- 临时波特率只作用于当前 Pi 进程的唯一业务串口，使用已核验的串口拓扑重开并读回速率；不修改持久配置或 F407 波特率。MQTT 控制链中断、300 秒保护期限到达或进程重启时清除临时覆盖并回到持久配置。
- Pi 端记录最高租约版本与 Session 身份，拒绝旧 Session 的新动作；同一活动 Session 的重复动作回放终态，不重复执行物理操作。发布失败的 ACK 保留原文等待 MQTT 完成确认。
- H1/M1 的持久化去重记录仅回收已经过期且已有终态的旧动作，为新动作释放容量；执行中记录仍保留，不通过清空现场文件绕过保护。

## 容量与验收边界

待发实验 ACK 队列最多保留 128 条尚未得到 MQTT 完成确认的消息，**不是 128 次累计命令上限**。积压达到容量时，新的链路排障动作暂不执行；仅调大常量不能解决 Broker 持续无法确认的问题。Server 应控制在途动作量，将无 ACK 保持为结果未确认，并在新 Session 前核对设备实际状态。

Pi 端自动化测试与实体 Pi 原生构建证明本端协议和代码路径可运行，不代替四类命令的真实 MQTT ACK、F407 屏幕显示、串口重新取得有效业务帧及 Server/Web 闭环验收。`RPICELL` 的 `report_sent=true` 只证明 Pi 已向串口写入，不证明 F407 已显示；`state=normal` 只清除教学覆盖，真实 5G 未拨通时仍须报告离线。

## 升级与回退

现场配置保留在 `/var/lib/cns-rpi/config.json`。升级前记录当前提交、程序校验值、服务状态以及 Pi/F407 当前波特率；确认未运行实验 Session 后，取得 `v1.0.5` 并在实体 Pi 原生构建、验证配置与自动化测试，再重启 `cns-rpi.service`。物联卡无法访问 GitHub 时，使用已验证的局域网 Git 包传输方式，不修改现场 MQTT 或拨号配置。

如需回退，先确认 Pi/F407 已恢复持久波特率，停止新的实验动作，恢复升级前保留的程序和对应代码版本，再重启主服务并核对 MQTT、F407 身份与业务帧。回退到 V1.0.4 将失去本版本链路排障四类命令能力；Server 不得继续向旧版 Pi 下发这些命令。
