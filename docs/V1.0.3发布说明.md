# V1.0.3 发布说明

版本：`v1.0.3`。发布日期：2026-09-25。

工程版本为 `1.0.3`。本版本收录自 V1.0.2 后已合入的阶段一 H1 真实 UART6 回显，以及 M1 双速率实验的树莓派端实现；不代表 Server/Web 实验闭环已完成。

## 主要变化

- H1 `uart_echo` 沿现有唯一串口读写者发送受限的学生中英文 UTF-8 文本，核对 F407 原样回显、双方实际波特率和动作后新业务帧，并在实验 ACK 中返回真实完整收发帧与同一单调时钟 RTT。示例文本不是固定指令。
- M1 增加 `set_f407_baud`、`uart_probe` 和 `set_pi_baud`：先在 115200 下发送 F407 换速请求并核对旧速率接受帧，再以三轮真实探测记录失配事实，最后将 Pi 的 `serial.baud` 在线持久化切至 57600。F407 复位后可经 MQTT 将 Pi 改回 115200，并重新核对业务帧与 H1 回显。
- 类型 4 接受帧只证明 F407 接受目标速率，不伪称换速已完成；响应缺失或串口中断时不盲目重发有副作用的请求。Pi 改参失败时保留 MQTT 恢复入口，不开启第二个串口读取者。

## 兼容性与边界

- H1、M1 沿用现有 `{namespace}/{device_id}/experiment/set` 与 `experiment/ack`；不修改 registration、运行三态、快照/实时遥测、配置命令和飞控命令的既有协议。
- M1 仅面向已核验的 CNS 主控箱及支持相应实验帧的 F407；不作为 PX4 功能发布。现场 F407 固件精确版本号尚未核验。
- `set_pi_baud` 会更新现场 `/var/lib/cns-rpi/config.json` 的 `serial.baud`。旧版本回退前，应先确认 F407 与 Pi 已恢复同一基准速率，不能只替换二进制。
- 本次不新增通用授时代码。2026-09-25 已针对现有实验箱配置系统授时，但该 Wi-Fi 路由属于机器本地运维配置；仅有白名单 5G 且不能访问 NTP 时，新设备仍须另行提供可达授时源。

## 验证与待验

- 本地 Release 构建成功，`cns_rpi --version` 输出 `cns_rpi 1.0.3`，50 项自动测试全部通过。QGC UDP 用例在允许本机套接字的环境中运行。
- M1 功能代码提交 `4fa800d` 已在实体 Raspberry Pi ARM64 原生构建并通过 50 项自动测试。直接 MQTT 联调取得 115200 下 H1 回显、F407 类型 3/4 接受帧、旧速率三轮无回显、Pi 在线切至 57600 后的新业务帧与 H1 回显，以及 F407 实体复位后 Pi 恢复 115200 的新业务帧与 H1 回显。原始 ACK 和完整帧见 [M1 树莓派端实施与验收边界](change_history/2026-09-24_M1树莓派端.md)。
- H1 与 M1 的上述证据只覆盖 Pi 直达 MQTT 和 Pi↔F407。Server 路由、实验会话、数据库、Web 展示的跨端闭环，以及 F407 固件精确版本号仍待核验。创建本标签不会自动替实体树莓派升级到 `1.0.3` 版本字符串。

## 升级与回退

在维护窗口确认 F407 与 Pi 均处于 115200 后，按现场可用的代码同步方式取得标签，再执行：

```bash
cd /home/dcdw/cns_rpi
git fetch --tags origin
git switch --detach v1.0.3
./scripts/deploy.sh
./build/cns_rpi --version
```

预期版本输出为 `cns_rpi 1.0.3`。如需回退，先确认双方已恢复 115200，并备份现场配置，再切回 `v1.0.2` 重新部署；部署脚本不会替现场自动回退 F407 固件或实验状态。物联卡 GitHub 访问受白名单限制时，应使用现场已验证的代码传输方式，不将拉取失败误判为程序故障。
