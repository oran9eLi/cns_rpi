# V1.0.4 发布说明

版本：`v1.0.4`。发布日期：2026-10-13。

工程版本为 `1.0.4`。本版本在 V1.0.3 基础上增加主控箱启动波特率自恢复，以及 F407 动态节点编号变化后的端点身份复核。树莓派仍以 `OPEN_DRONE_ID_BASIC_ID.uas_id` 作为稳定设备身份；节点编号和 MAVLink `system_id` 是可变的端点信息，不作为设备唯一键。

## 主要变化

- 当已绑定主控箱的 Pi 保存速率为 57600、F407 复位回到 115200 时，Pi 可在可信串口拓扑及身份绑定条件下被动探测基准速率。只有核验同一 Basic ID 和串口实际应用速率后才持久化恢复结果；恢复期间不盲发周期帧或抢占 M1 探测。
- F407 节点编号改变后，Pi 不自动改绑设备。新端点的 Basic ID 与持久化 `device_id` 一致时，更新 MAVLink 下行目标、可读节点标签及串口拓扑；复核期间暂停新的 F407 串口下行。候选身份冲突时维持原 Topic 并阻断下行。
- 已发出的 H1/M1 动作保持原有等待与不确定结果规则；复核期间新到达的串口实验动作最多暂存一项，并保留动作过期、去重及拒绝终态语义。普通飞控命令不进入待发槽。
- 候选身份冲突后的新串口实验动作立即拒绝；旧端点已发出的 H1 不会被新端点业务帧误判为完成。

## 兼容性与验证边界

- MQTT Topic 继续使用稳定 `device_id`；注册与遥测中的 `dcdw_label` 只是可变显示标签，同校设备可能重复。不修改 Server/Web 协议，也不修改 F407 固件。
- 发布分支在开发机完成 Release 构建和 53 项自动化测试。实体 Pi 对功能提交 `76637ba` 完成 ARM64 原生构建及 53 项测试，并观察到 F407 从 `sysid=1` 改为 110、复位后以同一 `device_id` 恢复身份核验与业务在线；主进程未重启，MQTT 控制链保持在线。详细时间与证据见 [动态节点 ID 实施与验证记录](change_history/2026-10-13_F407动态节点ID端点复核.md)。
- 现场复位伴随串口业务静默和一次经用户确认的 CH340 断开重枚举。因此尚未验证串口持续打开时的原位端点切换、执行中 H1/M1 动作连续性，以及 Server 实验会话、数据库、REST/WebSocket 和 Web 展示。启动波特率恢复也尚未完成实体断电场景验收。
- 发布标签创建时，实体 Pi 仍运行功能提交 `76637ba`，启动日志版本字符串为 `1.0.3`。2026-10-13 已通过局域网传输完整 Git 包，将实体 Pi 升级到标签对应提交 `2d850c7`；ARM64 原生构建及 53 项自动化测试通过，部署后的主进程版本为 `1.0.4`。现场配置校验和未变化；主服务与 5G 服务均处于运行、开机启用状态。此项部署验证不等同于换号期间执行中 H1/M1 或 Server/Web 闭环验收。

## Server 端验收要点

服务端以 `device_id` 关联原设备，接收同一 Topic 下节点标签从 `DCDW-001` 到 `DCDW-110` 的更新，不因标签变化创建新设备或拒绝与其他设备重复的标签。串口业务离线时，Pi 的 MQTT 控制链仍应能接收实验请求；复核恢复后检查注册、快照、实时遥测及运行三态的实际消息和持久化结果。执行中实验不中断的验收须另行安排，不能从本次复位恢复日志推断。

## 升级与回退

现场配置保留在 `/var/lib/cns-rpi/config.json`。在确认 Pi 与 F407 当前波特率一致后，可取得 `v1.0.4` 并运行 `./scripts/deploy.sh`；部署后使用 `./build/cns_rpi --version` 和 `systemctl status cns-rpi.service` 核对版本与运行状态。物联卡 GitHub 白名单不允许直接拉取时，应通过已验证的离线代码传输方式取得标签。

如需回退到 `v1.0.3`，先确认双方波特率一致并备份现场配置，再切换标签重新部署。旧版不能在 F407 节点编号发生变化后保持当前端点复核能力，回退前应恢复节点号或停止相关实验。
