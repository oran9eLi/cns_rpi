# 阶段一 H1 真实回显：树莓派端离线实现与待验收

日期：2026-09-23

状态：仅在隔离工作树完成候选协议代码与本地合成测试；未部署树莓派，未收到 F407 的真实回显。跨端文档《2026-09-23-阶段一H1真实回显跨端契约》仍为候选稿，本文不将合成帧、示例波特率或默认文本认定为现场事实。

## 已实现的本端行为

- 已持久化绑定的主控箱沿用 `{namespace}/{device_id}/experiment/set`、QoS 2 订阅和重连恢复；`inspect_pi_link` 继续原有只读分支。新 `uart_echo` 严格校验设备目标、动作和会话 UUID、正数租约版本、UTC 毫秒有效期、精确字段以及编码后 1—48 字节的受限 UTF-8 文本。`HELLO CNS` 不是代码常量。无法安全关联动作的非法请求只记录中文原因，不猜测 ACK。
- H1 发帧要求本次串口会话的 F407 身份已与持久化绑定核验一致、身份帧由所学习的 F407 `sysid/compid` 端点发出、唯一业务串口已打开，且没有另一项下行控制事务。`cached` 身份仍可用于原只读自检和 MQTT 控制入口，但不能发送 H1。串口已打开不表示 UART6 收发成功。
- 同一进程的 `MavlinkLink` 在现有 fd 写入候选 `TUNNEL payload_type=0x8003` 请求，并在原有接收路径保留 CRC 通过的完整 RX 线上字节；没有第二个串口读取者，也不改波特率。Pi 波特率从该 fd 的 termios 已应用值读取，F407 波特率只取匹配回显中的报告值。匹配时同时核对 F407 来源 sysid、compid、Pi 目标、版本、长度、随机 nonce 和原样文本。有效的新业务帧必须在本动作发送后由现有解码器实际识别；心跳、身份元数据与旧遥测缓存不算。成功事实含 TX/RX 完整帧十六进制与字节数、两端报告波特率、原样请求/响应文本、nonce 和同一 Pi 单调时钟的微秒 RTT。
- 发帧前将 `action_id` 与完整动作比较内容写入 `identity.binding_file` 同目录的 `<绑定文件名>.h1-actions.json` 并同步到磁盘；可关联动作的预检拒绝也保存终态。最多保留 128 个持久动作标记，不按有效期自动删旧 ID；达到上限时拒绝新增 H1，防止回收旧 ID 后再次物理执行。终态落盘在改名之前失败时返回 `result_uncertain` 并禁用后续 H1；若改名已完成但目录同步失败，则结果可能已经可见，同进程后续请求也暂不应答，留待重新装载记录，避免前后发布相矛盾的结果。重启后的未决记录只返回 `result_uncertain`，不盲目再次发送。同动作同内容的已确定终态可复用，改内容返回 `duplicate_conflict`。该文件是运行时状态，不是示例配置，也不得放入 Git。长期使用超过 128 项前，须由三端另行冻结安全的扩容/归档策略，不能直接清空去重记录。
- 终态沿用 `{namespace}/{device_id}/experiment/ack`、QoS 2、非 retained 和原有内存 ACK 待发队列；MQTT 发布调用仅表示已入队，必须等 QoS 完成回调才移出待发队列。超时、断线或重连后只重试同一 ACK，不重发 UART 请求。重启恢复的历史 ACK 每次仅在队列空闲时补入一条，不占满队列妨碍实时只读自检。回显等待及 ACK 确认均由主循环非阻塞推进；期间注册、遥测及原只读自检继续处理。配置和飞控命令与 H1 下行互斥。串口失联、身份不再核验、错误回显、超时或缺失新业务帧均不生成成功事实。

## 尚未冻结的边界

1. 实验箱断电，Pi 实际运行版本、配置路径、串口节点、USB 桥到 F407 UART6 的接线，以及双方实际基准波特率 B0 均**未核验**。代码只核对 Pi 已应用波特率与 F407 自报值相等；现场 B0 是否也相等，必须由三端联调确认，不能从示例配置推断。
2. F407 已烧录固件是否支持 `0x8003`、当前实烧版本、真实完整 TX/RX 帧及中文向量均**未核验**。当前请求/响应布局、`5 秒`回显超时和`10 秒`新业务帧截止值是离线候选实现，不构成三端冻结值；冻结结果不同须先同步契约、代码和测试。
3. Pi 校验 `session_id` 和 `lease_version` 的字段格式与有效期，不持有 Server 的活动租约权威状态；Session 归属、撤销和来源 MQTT ACL 必须由 Server 门禁保证。候选 Server 文档注明 REST 暂拒绝 H1，但直接向固定来源 Topic 派发仍可能绕过它；在来源门禁核验前禁止现场部署可执行 Echo 的版本。
4. ACK 在同一进程内未获得 QoS 完成确认会重试；进程重启后从持久化记录恢复已确定终态并再次发布，Server 须按动作身份处理重复 ACK。终态落盘在改名之前失败时给出 `result_uncertain`，此 ACK 不能保证在异常重启后自动恢复；改名后目录同步失败时暂不发布 ACK，Server 需按超时收敛。实体 MQTT 重连和 Server 入库未验证。
5. 本轮没有新增 `config.json` 字段，因此示例配置不变；也没有修改 F407、Server/Web、波特率或其他实验阶段。
