# Pi 命令结果提示与 F407 接口

Pi 完成服务器下发的命令后，向当前连接的 F407 发送一次成功或失败提示。F407 根据结果控制蜂鸣器和灯光，具体声音、颜色和持续时间由 F407 决定。

## 1. 传输接口

复用 Pi 与 F407 现有串口和 MAVLink 2 协议，不新增串口或 MQTT Topic。

| 项目 | 值 |
| --- | --- |
| MAVLink 消息 | `TUNNEL`，消息 ID `385` |
| `payload_type` | `0x8040`（十进制 `32832`） |
| `payload_length` | `2` 字节 |
| 源 `system_id` | 当前 F407 的动态 system ID，与现有 Pi 下行命令一致 |
| 源 `component_id` | `191`，Pi |
| `target_system` | 当前 F407 的动态 system ID，不固定为某个编号 |
| `target_component` | 当前 F407 的 component ID，目前为 `193` |
| 校验 | MAVLink 自带 CRC，无额外内层校验 |
| 应答 | 单向通知，F407 无需返回 `COMMAND_ACK` |

## 2. 数据格式

以下偏移均相对于解码后的 `TUNNEL.payload`，不是串口整帧的偏移。

| 偏移 | 字段 | 类型 | 含义 |
| --- | --- | --- | --- |
| `0` | `version` | `uint8` | 协议版本，固定 `1` |
| `1` | `result` | `uint8` | `1` 成功，`0` 失败，其他值无效 |

成功的数据区：

```text
01 01
```

第一个 `01` 是协议版本；第二个 `01` 是成功。

失败的数据区：

```text
01 00
```

`01` 是协议版本；`00` 是失败。这里的结果值独立于 `MAV_RESULT`，不能把 `MAV_RESULT_ACCEPTED=0` 直接当成提示结果发送。

**MAVLink 2 会省略消息尾部的零字节。** 失败帧的外层 MAVLink `len` 可为 `6`，成功帧可为 `7`，均为正常编码；两者解码后的 `TUNNEL.payload_length` 都是 `2`。F407 应使用标准 `mavlink_msg_tunnel_decode()`，由其补齐尾部零，不应要求外层 `len` 等于完整 `TUNNEL` 结构长度。

## 3. 提示时机

只按命令最终处理结果提示；刚收到命令、排队或执行中均不提示。

| 命令入口 | 成功提示 | 失败提示 |
| --- | --- | --- |
| `{namespace}/{device_id}/config/set` | 配置保存或热应用成功：`applied`、`already_applied` | 配置被拒绝：`rejected` |
| `{namespace}/{device_id}/control/set` | 收到 F407 的最终成功 ACK：`accepted` | 拒绝、执行错误或超时：`rejected`、`timeout` |
| `{namespace}/{device_id}/experiment/set` | 当前实验动作完成：`completed` | 拒绝、执行错误、超时或取消：`rejected`、`failed`、`timeout`、`cancelled` |

- `pending`、`in_progress` 不提示；异步动作等待终态后再提示。
- “开始采集”命令成功表示采集已建立，不表示整个实验完成或数据合格。
- 本设备上述命令 Topic 收到无法解析的请求并拒绝处理时，提示失败。
- 需要重启进程的配置在成功保存后、进程退出前提示；不等待进程重启后的检查。
- 提示在结果形成时发送，不依赖 MQTT 回执是否送达，也不改变原有 MQTT 回执内容。

## 4. 重复消息与链路异常

- Pi 进程内记录最近 `128` 个结果，按设备身份、命令通道、请求标识和成功/失败值去重；配置/控制使用 `command_id`，实验使用 `action_id`。同一结果的重复投递、ACK 重发不重复提示。
- 同一标识后来产生不同结果时可再次提示。参数非法但仍可读取 `action_id` 的实验请求也按该标识去重；没有可读取非空标识的非法请求逐条提示失败。
- 去重记录不跨进程重启保存；重启后恢复的 H1/M1 历史实验回执不会补发提示。
- 仅向自身组件身份已核验的当前 F407 发送。串口不可用、身份未核验/冲突或端点复核期间丢弃提示，恢复后不补发旧提示；异步视频动作即使 MQTT ACK 队列已满，也在终态形成时处理提示。
- 串口写入失败只记录日志，不重试提示；本通知不保证 F407 一定收到。

## 5. F407 接入及建议联调流程

F407 先完成 MAVLink 帧校验，确认源 Pi 组件、当前 system ID 和目标端点，再处理 `TUNNEL/0x8040`。标准解码后检查 `payload_length==2`、`version==1`、`result` 为 `0` 或 `1`，将结果交给灯光/蜂鸣器逻辑；不认识的版本或结果忽略，不返回应答。

1. 下发一条合法配置命令，确认收到 `01 01`，触发成功效果。
2. 下发一条参数不合法的配置命令，确认收到 `01 00`，触发失败效果。
3. 下发异步控制命令，先回 `MAV_RESULT_IN_PROGRESS`，此时不应提示；再回最终成功或拒绝 ACK，只提示最终结果。
4. 下发控制命令后不回 ACK，等待 Pi 判定超时，应收到失败提示。
5. 使用相同请求标识重发同一命令，确认重复回执不会反复触发效果。

控制联调应选择不会驱动实际执行机构的安全条件。F407 对业务控制命令的原有 ACK 仍正常返回；只有本文的结果提示不需要应答。
