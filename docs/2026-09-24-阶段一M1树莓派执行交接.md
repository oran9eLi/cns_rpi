# 阶段一 M1：树莓派执行交接

日期：2026-09-24
状态：可直接转交 Pi 实现方核对和排期；编码须等里程碑五实施计划获用户确认，部署到现场树莓派须由现场负责人另行安排

## 目标与现有基线

在现有 Pi 进程和 Pi↔F407 UART6 业务串口上，支持“F407 先从 115200 切到 57600 → Pi 保持 115200 观察失配 → Web 经独立 5G/MQTT 控制 Pi 切到 57600 → 新 Echo 验证恢复 → 最后 Pi 回 115200、现场复位 F407”的真实闭环。Server 将在 B0/B1 两档分别采集 10 轮同条件 Echo，Pi 继续提供每轮完整 TX/RX 帧和同一单调时钟 RTT；不是让 Pi 计算分数或拼接实验结果。

请先核对自己的实际分支、现场进程、配置路径、绑定设备号和串口节点。服务器仓库核对到的 Pi 本地 `main` 为 `40edb0f`，其 H1 回显交易由 `src/experiment/uart_echo_transaction.*` 实现，`src/main.cpp` 持有唯一串口读写路径；这不是当前实机一定运行该提交的证明。基准 B0=115200 已由 H1 真机记录支持；B1=57600 的实烧切换须与 F407 方再次核对。设计依据：[里程碑五设计](superpowers/specs/2026-09-24-阶段一里程碑五串口教学闭环设计.md)、[H1 字节契约](2026-09-23-阶段一H1真实回显跨端契约.md)、[F407 本次交接](2026-09-24-阶段一M1主控板执行交接.md)。

## 共用动作与传输契约

沿用现有 `{namespace}/{device_id}/experiment/set` 和 `/experiment/ack`、QoS 2、非 retained、`schema_version=1`、`command_id`、`session_id`、`action_id=request_id`、`lease_version`、`expires_at` 及既有有效期/去重边界。本次仅新增三种 `operation`；所有未知字段、过期动作、错设备/会话或同 `action_id` 不同参数都拒绝，不能因为当前 Broker 匿名就跳过本机校验。单条 JSON 不超过 4096 字节。设备 ACK 继续用现有 `status=completed` 加 `fact` 或 `status=rejected` 加 `error_code`，不增加“执行中即成功”的语义。

| 操作 | 设备命令新增字段 | 完成 ACK 的 `fact` 精确字段 | 含义 |
|---|---|---|---|
| `set_f407_baud` | `baud_rate:57600` | `nonce`、`accepted_baud_rate`、`pi_baud_rate`、`tx_frame_hex`、`tx_frame_bytes`、`rx_frame_hex`、`rx_frame_bytes` | F407 在旧速率接受了切换请求；不证明新速率已应用。完整帧均大写十六进制，长度为实际线上字节数。 |
| `set_pi_baud` | `baud_rate:57600` 或 `115200` | `pi_baud_rate`、`serial_port_open:true` | `config.json` 已原子保存目标值，唯一串口持有者已按该值重新打开并读回实际配置；不证明 F407 当前值。 |
| `uart_probe` | 无额外字段 | `pi_baud_rate`、`attempted_count:3`、`valid_response_count`、`samples` | 只记录失配阶段的三次真实发送和对应有效回显观察；`completed` 只表示观察已保存，不表示串口通信成功。 |

`samples` 固定为恰好 3 个按发送顺序排列的对象，各含 `nonce`（16 位小写十六进制）、`tx_frame_hex`、`tx_frame_bytes`、`valid_rx_frame_hex`、`rx_frame_bytes`、`round_trip_us`。后三项在未取得**本轮有效配对 Echo**时统一为 `null`；取得时均为实际值。完整帧上限沿用 H1 的每帧 280 字节，十六进制长度与字节数一致。`valid_response_count` 必须等于三轮中非空配对响应的数量。错 nonce、错目标、旧帧和任意非受控业务帧不能充作有效响应。若 4096 字节上限不足以容纳事实，拒绝并报告，不截断后伪称完整证据。

新增受限错误码：`unsupported_baud_rate`、`config_write_failed`、`serial_reconfigure_failed`；保留现有 `result_uncertain`、`serial_unavailable`、`duplicate_conflict`、`action_expired` 等。F407 请求已实际发出却未收到旧速率接受帧时返回 `result_uncertain`，不能返回确定的“未切换”或自动重发。配置写入失败不得开始换速；配置已写入但串口重开/读回失败，返回 `serial_reconfigure_failed` 并保持 MQTT 可用、把设备状态标为待核验，不能报 `completed`。

## Pi↔F407 字节契约

复用 MAVLink 2 `TUNNEL payload_type=0x8003`，保留 H1 类型 1/2。类型 3 请求与类型 4 旧速率接受响应都严格为 14 字节：`版本:u8=1 | 类型:u8=3或4 | nonce:u64 小端 | 目标/接受波特率:u32 小端`。白名单仅 115200/57600、8N1；本次正常 F407 切换只发 115200→57600。构造向量：nonce `0x0102030405060708`、目标 57600 时，类型 3 为 `01 03 08 07 06 05 04 03 02 01 00 E1 00 00`，类型 4 为 `01 04 08 07 06 05 04 03 02 01 00 E1 00 00`。这两串只是 TUNNEL 数据区，不能当实机完整帧。Pi 只能接受当前 F407 身份、目标、nonce、类型、长度和目标速率均匹配的类型 4；F407 应在旧速率完整发完类型 4 后再切换。两端在任何实机改参前逐字节确认这组向量及 TX 完成时序。

`uart_probe` 复用 H1 类型 1/2 Echo 格式，固定文本 `CNS_TEST`，每轮新 nonce。Pi 仍在 B0 发送三次，每次最多等待 5 秒，相邻轮次至少 300 毫秒；不能启用自动发现/自动跟速把失配悄悄修好。探测不要求新业务帧或 F407 当前身份重新已核验才能发送，但必须通过已有的固定绑定确认目标 Pi；本地串口打不开、真实帧未发送时返回拒绝，而不是填三个“超时”。失配中仍须接收经 MQTT 到达的 `set_pi_baud`，即使 F407 业务状态为离线、身份仅是已缓存。

## 分项工作与验收

### P1：受限解析、共享向量与去重

在现有实验请求解析和终态持久化机制上新增三个操作；同一 `action_id`、同参数只返回已存结果，不再次发送 UART 帧或再次写配置，参数变化返回 `duplicate_conflict`。在可能产生物理副作用前持久化动作身份；崩溃后不明结果返回/保留待核验，不能把重启当作新动作。用 F407 交接的 14 字节正向量及错版本、错长度、错目标、错 nonce、重复动作作为单元测试。输出：解析/ACK/终态测试及提交号。

### P2：F407 旧速率受控切换与三轮探测

只让 `src/main.cpp` 现有串口持有者实际写帧、收帧。`set_f407_baud` 在当前双方 B0、有当前有效 F407 身份、串口空闲时发送一次类型 3；收到完整类型 4 后保存旧速率完整 TX/RX 帧并返回“接受事实”，不要把目标值写成 F407 当前实际值。发送后接受帧丢失、Pi 重启或串口中断都只报待核验。`uart_probe` 串行执行三次，不与 H1 回显或其他串口动作并发。输出：无响应、部分响应、三次响应、TX 失败、过期和重启的测试与抓帧。

### P3：Pi 在线持久化与应用波特率

`set_pi_baud` 不调用现有“写 config 后主动退出等 systemd 重启”的普通配置命令路径。对运行配置的 `serial.baud` 做原子写入，再由当前唯一串口持有者停止本轮读写、关闭旧链路、用原节点以目标速率重新打开并读回实际配置；整个过程 MQTT 控制连接不能退出。保留旧配置其他字段、文件权限、备份与原子写入要求；掉电后从已持久化值启动，最终恢复 B0 时也持久化 B0。读回失败要保留 Pi 控制在线并报告，不声称 F407 已匹配。输出：注入写失败、重开失败、写入后崩溃、业务无帧仍改参及重复动作测试。

### P4：H1/B0/B1 与现场恢复回归

对现有 `uart_echo` 不硬编码 B0：Pi 只校验当前实际本机值等于同次 F407 响应实际值，Server 另按场景步骤判断 B0/B1。B0 与 B1 都返回新的业务帧、原样文本、完整 TX/RX 和同一单调时钟 RTT；两档 10 轮不会跨轮拼接帧。现场按 F407 复位键后，Pi 可经网络改回 B0 并取得新业务帧及新 Echo。普通遥测、身份、配置命令、飞控命令和 H1 旧三步会话不得回退。输出：固定版本矩阵、源提交号、实机日志和每一阶段至少一组完整帧。

## 停止条件与交付格式

若 F407 的 57600 不稳定、类型 3/4 与 H1 冲突、运行中换速需要第二个串口读者、Pi 在 F407 失联后无法保持 MQTT 控制，或新 ACK 超过 4096 字节，请停止相关真机操作并把事实反馈给 Server/F407 方；不得私改波特率、协议字段、超时或把“无回显”写成已证明的波特率根因。Pi 不计算成绩、不建立历史导出、不新增网口实验或远程复位。

建议 P1—P4 各自独立 Git 提交，前缀英文、说明中文。交付给 Server 方：仓库分支与提交号、构建和测试结果、实际服务所用配置路径与串口节点、F407 固件标识、两档实测完整帧与 RTT、失配时 MQTT 仍在线和 Pi 在线换速的证据、失败/不确定案例、已知限制。密码、真实配置、持久化动作数据和设备私有目录不提交。现场更新先备份并确认单一串口持有者，是否部署由现场负责人决定；Server 的 M1 Session 联调由服务器方另外执行。
