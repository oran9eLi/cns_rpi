用户已授权 F407 暂未连接时，使用已有合法持久化箱子绑定上报 RTK，前提是无身份冲突。缓存身份帧不携带旧 F407 普通传感数据，runtime 如实 cached/offline/unknown；本地 `box:{device_id,identity_verified}` 与 PX4 实验身份分开。没有箱子绑定时仅本地观测，不以 PX4 注册。

本轮 WSL 全量 68/68 CTest（19.82 秒），Pi ARM64 相关测试 8/8，增量构建 0 条警告。F407 未接时，以合法缓存箱子 `DCDWCNS1GHC0G6LF8MY6` 唯一注册 `cns_box` 的真实 MQTT 遥测、状态查询、RAM 配置 ACK/读回及正式箱子 HTTP 快照持久化已验证，详情与原始证据见 [最新缓存身份记录](2026-11-06-rtk-box-cached.md)。F407 接回后的实体三链路/G2 同时运行仍须单独验收；室外 Survey-in 成功、移动站 Fixed 和网页实验页面仍未验或未做。下方“历史实际链路与结果”起保留纠正前的证据。

本轮补容器前的检查已收到 43 帧 MQTT 遥测及操作 ACK，但 HTTP 未见新快照落库。原因是现有服务器 `ParseTelemetry` 要求 schema 3 的 `drone_id.basic_id` 两层为对象，缓存空状态缺少该结构。Pi 现为缓存 RTK 快照补精确空 `"drone_id":{"basic_id":{}}`，不填 `id_type`、`ua_type` 或任何 F407 实时观测值；schema 1 实时帧仍无该字段。服务器源码 probe 已验证缺容器拒绝、补空对象 accepted 且 payload unchanged，三 PTY 新断言用旧二进制先 RED；服务器代码未改。修复后的 Pi/云端复验收到 37 帧 RTK 遥测/44 条消息，正式箱子 HTTP 返回 200 且快照时间为 `2026-11-06T06:26:39.921Z`，证实空容器兼容有效；MQTT 到达与 HTTP 落库已分别核对。

## 同轮发现并修复的真实时序问题

基站此前已持续观测，再次写入相同参数时，旧流程虽通过最终 RAM 读回，计时仍从 9622 秒延续。这说明配置 ACK 不能替代导航内部状态切换的证据。

在同一台 HPG 1.50 接收机上做 RAM-only 对照：[原始状态切换记录](2026-11-06-rtk-cloud/survey-mode-transition.jsonl)。

1. 1091 ms：停用配置 ACK，读回 `TMODE_MODE=0`。
2. 1784 ms：下一导航周期首次报告 `active=false / duration=0`，比 ACK 晚约 693 ms。
3. 5092 ms：重新启用，配置 ACK 且读回 `TMODE_MODE=1`。
4. 5784 ms 起：真实观测时长重新从 1、2、3、4、5 秒递增。

修复为 `disable ACK → awaiting_stop → 新 epoch 的 inactive → enable → 最终参数读回`。等待停止最长 3 秒，取消、过期和停止确认超时均不能继续启用。没有增加固定 sleep。

进程级回归先在旧二进制上复现失败：“导航周期尚未停用，驱动就重新启用了 Survey-in”；修复后通过。驱动单测也覆盖旧/重复样本、停止确认、超时和取消。

修复后真实云端动作再测：[操作前状态](2026-11-06-rtk-cloud/before-survey-action.json) 中旧时长为 402 秒；同一操作完成后，[MQTT 的最新观测](2026-11-06-rtk-cloud/mqtt-verified.json) 已是新一轮 2 秒，随后正式 API 读到 13 秒，测试结束后的快照为 47 秒。新一轮测量已实际开始。
