# 阶段一里程碑三：Pi 控制链自检跨端契约

日期：2026-09-22

状态：里程碑三设计与实施计划已获用户确认；本文冻结首个只读实验动作的设备侧对接格式。Pi 与 Server 实现、云端真机验收尚未完成。

适用范围：`cns_box` 设备、运行中的 `SERIAL-01` Session、固定动作 `inspect_pi_link`。本文可分别放在 `cns_server/docs/` 与 `cns_rpi/docs/`；两份内容必须保持一致。总设计见《阶段一里程碑三硬件动作与事实闭环设计》，Server 逐提交顺序见《阶段一里程碑三硬件动作与事实闭环实施计划》。

## 1. 本轮唯一目标与禁止事项

学生在 Web 发起一次检查，Server 经 `route_service` 把它送到对应 Pi；Pi 读取**此刻本机已掌握的事实**并返回。Server 保存 Pi ACK 后，Web 才能显示“已记录”。此次检查不能证明 UART6 双向收发，F407 的 `HELLO CNS` 属于下一里程碑 H1。

- Pi 不向 UART6 发送任何实验帧，不读取第二份串口数据流，不打开第二个串口句柄，不修改 Pi/F407 参数。
- Pi 不计算学生分数、不决定 Session 步骤完成与否，也不接收浏览器 Session 访问令牌。
- MQTT topic 的设备段必须来自既有持久化设备绑定，不能从载荷自认新设备；`flight_controller`、身份 `conflict|unbound` 均拒绝本动作。
- `identity_status=cached` 且 Pi 控制链在线时允许这项**只读**检查；F407 业务链离线也允许。现有飞控命令的 `CanSendDeviceCommands()` 要求本次串口身份实时核验，不能直接拿它拦截此自检；两种命令的安全边界不同。

## 2. MQTT topic 与投递

`{namespace}` 沿用现有 MQTT 配置，`{device_id}` 与当前连接所用绑定身份一致。以下 topic 均为 QoS 2、`retain=false`；不得依赖 retained 重放，重连后按既有 MQTT 订阅生命周期恢复订阅。

| 方向 | Topic | 本端责任 |
|---|---|---|
| Server 来源→路由 | `{namespace}/sources/web-console/experiment/request` | Pi 不订阅、不发布 |
| 路由→Pi | `{namespace}/{device_id}/experiment/set` | Pi 订阅，只接受固定动作 |
| Pi→路由 | `{namespace}/{device_id}/experiment/ack` | Pi 发布受校验的终态 ACK |
| 路由→Server 来源 | `{namespace}/sources/web-console/experiment/ack` | Pi 不订阅、不发布 |

同一个动作有四层身份：`session_id` 是实验归属，`action_id` 是一次学生操作且在重试中不变，`request_id=action_id` 是 route 来源幂等键，`command_id` 是 route 生成的本次设备命令 UUID。Pi 不向自己的 topic 发布 `dispatched`；那是 route 服务的来源 ACK。Pi 只发布 `completed` 或 `rejected` 终态。

## 3. Pi 接收载荷

`experiment/set` 使用严格 schema v1；单条载荷 UTF-8 编码后不得超过 4096 字节，只接受以下字段。未知字段、错误类型、非 UUID、非正整数租约版本、非固定操作名均拒绝；`device_id` 沿用既有设备 ID 校验和最长 20 字符边界。`target.device_id` 必须与 topic 设备段及当前持久化绑定相同，`request_id` 必须等于 `action_id`。`expires_at` 是 RFC 3339 UTC 毫秒时间，首次处理已过期的新动作不得执行；同内容旧动作的重投优先命中去重记录，不重新读取事实。Server 保证首次派发时有效期不超过 30 秒且不晚于设备租约到期；Pi 不自行续租或判断 Server 的 Session 状态。

```json
{
  "schema_version": 1,
  "command_id": "7d15e276-c7e1-4f52-aaee-7314a6417667",
  "request_id": "f886f45b-01f8-4a54-b2b6-a65b07477aa1",
  "target": { "device_id": "DCDWCNS1S2MEAG1VTA0C" },
  "session_id": "c4191037-9e2a-480c-a995-2174e4672563",
  "action_id": "f886f45b-01f8-4a54-b2b6-a65b07477aa1",
  "lease_version": 3,
  "operation": "inspect_pi_link",
  "expires_at": "2026-09-22T09:00:30.000Z"
}
```

Pi 不根据这份载荷自行认领绑定、改变 UART 参数或进入其他实验动作。结构非法但能安全提取合法 `command_id` 与动作身份时，可返回 `rejected`；无法可靠关联命令时只记中文诊断、不发布含猜测标识的 ACK，由 Server 超时收敛。

## 4. Pi 终态 ACK 与事实语义

成功 ACK 必须完整返回四项事实，所有字段从**当前进程状态**读取，不用旧遥测或部署配置补造。`observed_at` 是 Pi 采样时的设备 UTC 时间；Server 另记接收/落库时间，跨端先后以 Server 事件序号为准。

```json
{
  "schema_version": 1,
  "command_id": "7d15e276-c7e1-4f52-aaee-7314a6417667",
  "session_id": "c4191037-9e2a-480c-a995-2174e4672563",
  "action_id": "f886f45b-01f8-4a54-b2b6-a65b07477aa1",
  "operation": "inspect_pi_link",
  "status": "completed",
  "observed_at": "2026-09-22T09:00:02.123Z",
  "fact": {
    "control_status": "online",
    "identity_status": "cached",
    "business_status": "offline",
    "serial_port_open": false
  }
}
```

| 字段 | 合法值 | 精确含义 |
|---|---|---|
| `control_status` | `online|offline` | Pi 当前 MQTT 控制连接；收到命令且能回 ACK 时正常应为 `online` |
| `identity_status` | `verified|cached|conflict|unbound` | 现有设备会话的身份核验事实；`cached` 不代表当前 F407 在线 |
| `business_status` | `online|offline|unknown` | 现有运行三态的 F407 有效业务帧事实 |
| `serial_port_open` | `true|false|"unknown"` | 当前程序是否持有已打开的串口端点；不能解读成电平正常、参数匹配或 F407 响应有效 |

Pi 当前代码的 `DeviceSession::CurrentOnlineStatus()` 能提供前三态；串口端点状态需从现有 `MavlinkLink` 所在运行路径取得，不能为了检查而重新打开设备。若已有对象只表示“曾经打开”、无法安全判断当前端点，返回 `"unknown"`，不要猜 `true`。已取得真实三态而 F407 业务离线时，应照样返回 `completed` 与 `business_status=offline`。

拒绝 ACK 不携带 `fact`，必须携带 `error_code`；`observed_at` 是作出拒绝判断的 Pi 时间。ACK UTF-8 编码后也不得超过 4096 字节。首版错误码只允许：`action_expired`、`identity_unavailable`、`observation_unavailable`、`duplicate_conflict`、`unsupported_operation`。错误码表达设备端事实，不复用 route 自身的错误码。

```json
{
  "schema_version": 1,
  "command_id": "7d15e276-c7e1-4f52-aaee-7314a6417667",
  "session_id": "c4191037-9e2a-480c-a995-2174e4672563",
  "action_id": "f886f45b-01f8-4a54-b2b6-a65b07477aa1",
  "operation": "inspect_pi_link",
  "status": "rejected",
  "observed_at": "2026-09-22T09:00:02.123Z",
  "error_code": "identity_unavailable"
}
```

未知字段不进入 ACK。Pi 不把串口端点 `true`、控制链 `online` 或 MQTT 发布成功解释为 UART6 真实收发成功。ACK 发布失败时只重发原 ACK，不重新取样或生成新动作；仍无法发布时保留诊断，由 Server 超时或待核验收敛。

### 来源 ACK 样例（由路由服务发布，Pi 不处理）

派发阶段只说明路由服务已下发，不携带设备事实：

```json
{
  "schema_version": 1,
  "request_id": "f886f45b-01f8-4a54-b2b6-a65b07477aa1",
  "command_id": "7d15e276-c7e1-4f52-aaee-7314a6417667",
  "command_type": "experiment",
  "status": "dispatched",
  "business_status": null,
  "occurred_at": "2026-09-22T09:00:01.000Z",
  "target": { "device_id": "DCDWCNS1S2MEAG1VTA0C", "school_name": "SEU", "dcdw_label": "DCDW-001" }
}
```

只有符合设备终态校验的来源 ACK 才能投影白名单事实；后端仍需先落库，Web 才能显示已记录：

```json
{
  "schema_version": 1,
  "request_id": "f886f45b-01f8-4a54-b2b6-a65b07477aa1",
  "command_id": "7d15e276-c7e1-4f52-aaee-7314a6417667",
  "command_type": "experiment",
  "status": "succeeded",
  "business_status": "completed",
  "occurred_at": "2026-09-22T09:00:03.000Z",
  "target": { "device_id": "DCDWCNS1S2MEAG1VTA0C", "school_name": "SEU", "dcdw_label": "DCDW-001" },
  "device": {
    "session_id": "c4191037-9e2a-480c-a995-2174e4672563",
    "action_id": "f886f45b-01f8-4a54-b2b6-a65b07477aa1",
    "operation": "inspect_pi_link",
    "observed_at": "2026-09-22T09:00:02.123Z",
    "fact": { "control_status": "online", "identity_status": "cached", "business_status": "offline", "serial_port_open": false },
    "error_code": null
  }
}
```

来源请求不含签发时间，30 秒有效期和不晚于租约到期的判定需要由持有当前时钟、租约事实的一侧执行；只靠静态 JSON 结构不能证明该请求仍有效。

## 5. 去重、过期与最小实现边界

以 `action_id` 查有界终态记录，比较 `target.device_id,session_id,request_id,lease_version,operation,expires_at`；`command_id` 不参与业务内容比较。相同动作内容重复到达，复用原 `status,observed_at,fact|error_code`，ACK 的 `command_id` 使用本次合法下发的值，以便 route 关联；内容冲突返回 `duplicate_conflict`，不得覆盖原结果。首次处理过期动作返回 `action_expired`，不得读取事实后伪装执行成功。

首版 Pi 终态缓存至少容纳 128 个动作、保留不少于 300 秒；超限按最早终结时间淘汰。此窗口覆盖 30 秒动作有效期与有界在途重投，route_service 的命令终态另按现有配置保留，当前示例为 30 天。首版只读动作可以使用进程内缓存，但必须在交付记录中明确：Pi 进程重启后不保证仍有旧采样；该极端窗口即使重采样也不能触碰 UART/F407。后续任何改变参数的动作不得直接沿用此进程内去重保证，必须先另行设计崩溃一致性。禁止把 QoS 2 本身当作业务幂等保证。

Pi 只按本机已有状态工作；`lease_version` 不是 Pi 自行判断某 Session 是否仍占用设备的权威依据。Server 在派发前原子检查租约，过期未派发动作不得再进入设备 topic。旧 ACK 只能关联原 Session 历史，不打开新 Session。
