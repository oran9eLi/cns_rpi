# 树莓派首次安装与 Web 远程更新

目标为 Pi 5 / trixie ARM64、`dcdw` 运行用户、普通可写根目录。批量设备优先使用[工厂镜像](工厂镜像手册.md)：同一镜像上电后从 F407 获取编号并生成接入密钥，服务器首次确认后开放更新。已安装系统保留下面的 LAN/Wi-Fi 初始化入口。Pi 不需要 Git、CMake 或编译器。

## 服务器准备

按[接口契约](远程更新接口契约.md)部署 MQTT 更新通道、统一 poll 和下载入口。首次 poll 按 F407 device_id 保存接入密钥哈希及待确认状态，服务器确认后认可同一密钥；不另建节点或签发升级令牌。物联卡白名单覆盖 API 和下载地址；只有手工初始化还需覆盖 apt 源，工厂镜像已安装全部运行依赖。

CI 通过后，从版本 Release 取得 ARM64 包、`.sha256`、`manifest.json`、`bootstrap_pi.py`，导入服务器并核对版本、完整 Git SHA 与 SHA-256。发布包不含现场配置或令牌。只有在 Web 点击更新形成任务后，设备才安装指定版本。

从 `v1.0.7` 起，运行依赖包含 `ffmpeg`，为 G2 有限采集验证提供 `ffprobe`。视频默认关闭；需要视频的 Pi 还须预装支持 libav/MPEG-TS/SRT 的 `rpicam-vid`，摄像工具不在通用 Debian 发布包内。现有设备升级前须确认这两项工具已准备；普通业务组件更新不会替设备安装新的系统依赖。

首装模板来自仓库 `config/config.example.json`、`config/maintenance.example.json`，仅填写通用服务器和业务参数，不依赖包内存在样例，不填写设备编号或密钥。

## 已安装系统的首次初始化

1. 烧录 trixie 64-bit，创建 `dcdw` 用户并启用 SSH。准备真实业务配置、维护配置，确认网络与服务器 HTTPS 信任链。
2. 参照 `config/maintenance.example.json` 填写 `server_url/business_config`，保存为 `maintenance.json`。business_config 指向安装后的 `/var/lib/cns-rpi/config.json`；私有 CA 可增加绝对路径 ca_file。无须预置凭据。
3. 从服务器提供的固定入口下载 `bootstrap_pi.py`，按随版本交付的摘要核对脚本；下载失败或文件不完整时不要执行。以下地址和版本是占位示例：

```bash
curl --fail --show-error --output bootstrap_pi.py https://YOUR_SERVER/bootstrap_pi.py
sha256sum bootstrap_pi.py
sudo python3 bootstrap_pi.py --version 1.0.7 --maintenance-config ./maintenance.json --business-config ./config.json
```

初始化入口检查 root/系统/架构/根目录与旧配置卷，按服务器元数据下载并验证包，只安装运行依赖，保留已有现场配置和身份/实验状态。不会改写 apt 镜像源。旧 OverlayFS/配置挂载设备须先按旧部署手册迁移。

安装后核对：

```bash
systemctl status cns-rpi.service cellular-dialup.service cns-rpi-maintenance.timer
journalctl -u cns-rpi-maintenance.service -n 50 --no-pager
/opt/cns-rpi/current/bin/cns_rpi --version
```

`/etc/cns-rpi-maintenance.json` 仅保存通用参数；自动生成的设备接入密钥位于 `/var/lib/cns-rpi-maintenance/access.json`（root 0600）。运行配置继续使用 `/var/lib/cns-rpi/config.json`。版本位于 `/opt/cns-rpi/releases/`，不同链接分别指向业务、拨号和维护组件。不要手工清除正在使用或上一版本目录。

## Web 更新与回退

Web 选择设备、版本后发起 `app` 更新。服务器创建任务，Pi 空闲时约每 60 秒领取；下载和配置预检完成前继续运行当前版本。新业务观察至少 40 秒，通过后回报成功，否则恢复旧业务与本次更新前的配置。绑定文件、实验状态不随配置回退清除。普通业务更新不重启 5G。

`cellular` 任务需明确选择，下载完成后重启拨号；观察窗口为 180 秒，同时检查服务和服务器 API 连接。暂时失联时 Web 显示等待结果；结果未回传不能推断成功。正式交付须在禁用 LAN/Wi-Fi、仅 5G 的条件下验证。

人工回退使用同一 Web 消息通道，`action=rollback`；仅恢复该组件实际保留的上一版本，仍会预检与当前另一组件的配置兼容性。不兼容则拒绝切换。`needs_attention` 表示中断或恢复未确认，应先查设备状态，再处理后续任务。

维护程序自身不接受任务升级；更换须在受控维护窗口执行初始化/安装入口。系统/内核/整盘升级不在应用版本包范围。生产维护不要调用仍面向源码构建的 `scripts/install_deps.sh` 或 `scripts/deploy.sh`，避免恢复源码路径和同时重启两个服务。

## 开发与验收

Windows 使用 Ubuntu-24.04 WSL 构建和测试，不在普通 WSL 执行 Pi 初始化/安装命令。新测试对临时根目录和 systemd 边界替身运行真实安装逻辑，不会改宿主服务。

本地单元/HTTP 联合测试、GitHub Actions ARM64 构建、服务器/Web 联调、实体 Pi 首装和纯 5G 更新分别记录。任何一项未执行均不能由其它检查替代。
