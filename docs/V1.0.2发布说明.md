# V1.0.2 发布说明

版本：`v1.0.2`。发布日期：2026-09-22。

工程版本为 `1.0.2`。本版本在 V1.0.1 的主控箱运行三态和身份绑定基础上，补齐阶段一里程碑三的首个只读 Pi 控制链自检动作 `inspect_pi_link`。它只交付 Pi 侧设备入口和应答，不代表 Server/Web 实验闭环已完成。

## 主要变化

- 对已持久化绑定的主控箱，在现有 MQTT 客户端订阅 `{namespace}/{device_id}/experiment/set`，并向 `{namespace}/{device_id}/experiment/ack` 发布终态；两者均为 QoS 2、非 retained。MQTT 重连后自动恢复订阅。
- 严格校验设备目标、命令与动作身份、字段、租约版本和过期时间；以 `action_id` 进行有界去重，同内容重投复用原事实，内容冲突或过期动作给出规定的拒绝 ACK。
- 从当前进程读取 MQTT 控制链、身份、F407 业务链和串口端点事实。身份为 `cached` 且 F407 业务离线时，仍允许完成此只读动作；身份冲突或未绑定时拒绝。串口端点不确定时返回 `unknown`，端点打开不代表 UART6 已通信成功。
- ACK 发布调用失败时保留原 ACK，连接恢复后重发，不重新采样。本轮不向 UART6 发送实验帧，不启动第二个串口读取者，也不修改 Pi/F407 参数。

## 兼容性与范围

- 不增加 `config.json` 字段；命名空间沿用现有配置。registration、运行三态、快照/实时遥测、配置命令和飞控命令的既有 Topic 与载荷不变。
- PX4、从未持久化绑定的设备不订阅本动作。Server 路由、实验 Session、数据库落库、Web 展示和 F407 真回显不属于本次树莓派发布。
- Pi 去重缓存只在进程内，进程重启后不保证恢复旧采样；不能把这一策略直接用于未来有副作用的改参动作。

## 验证与待验

v1.0.2 候选在本地完成 Debug 构建与 42 项自动测试；独立本地 Broker 重启检查通过。其 Pi 功能代码提交 `e4b9a18` 曾在树莓派完成 ARM64 原生 Release 构建及 42 项自动测试，直达 MQTT 测试收到 `completed` 和过期 `action_expired` 两类真实 ACK。现场运行的程序尚未更新为 v1.0.2 版本号；详细部署提交与原始消息见 [Pi 控制链自检实现与验证](阶段一Pi控制链自检实现与验证.md)。

尚未现场验证 `cached` 身份与 F407 业务离线的组合、实际 Broker 故障后的待发 ACK，以及 Server 路由、落库与 Web 展示。直达设备 Topic 的成功 ACK 不能替代跨端闭环验收。

## 升级与回退

在树莓派维护窗口执行；部署脚本会保留现场 `/var/lib/cns-rpi/config.json`：

```bash
cd /home/dcdw/cns_rpi
git fetch --tags origin
git switch --detach v1.0.2
./scripts/deploy.sh
./build/cns_rpi --version
```

预期版本输出为 `cns_rpi 1.0.2`。如需回退，切回 `v1.0.1` 并重新执行 `./scripts/deploy.sh`；回退不会清除现场身份绑定和配置。版本发布本身不自动替实体树莓派执行升级。
