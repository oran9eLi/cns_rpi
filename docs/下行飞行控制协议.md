# 主控箱控制接口

本文件记录 F407 主控箱六类飞行控制动作和五模块启停与切屏的接口。控制回执采用 F407 受理语义。

控制命令只发给已核验身份的当前 F407。显式启用 `rtk_base` 时，独立 3DR/PX4 串口不接收这些命令；RTK 动作仍使用同一箱子 `device_id` 的 `experiment/set`，见 [RTK 第一实验动作](RTK基站第一实验操作与接口.md)。

## 1. MQTT 请求

默认 `namespace=cns_rpi`，`device_id` 为 F407 提供的设备 SN。消息为 UTF-8 JSON。

| 方向 | Topic | QoS | retain |
| --- | --- | ---: | --- |
| 下发命令 | `{namespace}/{device_id}/control/set` | 2 | false |
| 受理回执 | `{namespace}/{device_id}/control/ack` | 2 | false |
| 实际状态 | `{namespace}/{device_id}/telemetry/snapshot/v1` | 0 | false |

软件发布控制请求时须使用 `retain=false`。树莓派忽略 broker 在订阅时补发的保留请求。

请求必须包含 `command_id`、`command`、`parameters`。`command_id` 为非空字符串，UTF-8 编码不超过 128 字节。新操作使用新标识，同一请求重投保持标识和内容一致。单电机调速和模块启停使用各自的 `parameters`，其余命令传 `{}`。

```json
{"command_id":"arm-001","command":"arm","parameters":{}}
```

```json
{"command_id":"takeoff-001","command":"takeoff","parameters":{}}
```

```json
{"command_id":"land-001","command":"land","parameters":{}}
```

```json
{"command_id":"disarm-001","command":"disarm","parameters":{}}
```

```json
{"command_id":"stop-001","command":"emergency_stop","parameters":{}}
```

```json
{"command_id":"motor-001","command":"set_motor_pwm","parameters":{"motor_id":1,"pwm_us":1300}}
```

`motor_id` 为 `1..4` 的整数，`pwm_us` 为 `1000..2000` 的整数，单位 μs，表示 PWM 高电平脉宽。调速仅修改指定电机，另外三路由 F407 保持当前输出。旧 `unlock`、`lock` 名称和四路 `pwm_us` 数组不属于本版接口。

```json
{"command_id":"module-001","command":"set_module_enabled","parameters":{"module":"lora","enabled":true}}
```

模块启停请求的 `command_id` 不能全为空白。`parameters` 必须恰好包含模块字符串 `module` 和 JSON 布尔值 `enabled`。模块标识仅支持下表中的五种小写写法。`true` 请求开启并切页，`false` 请求关闭。模块参数缺失、多余或类型错误均返回 `invalid_parameter`。

## 2. MAVLink 映射

复用 F407 UART6，默认 115200 bit/s、8N1，采用标准 MAVLink 2 二进制帧。`S` 为当前 F407 的动态 system ID：Pi 来源为 `S/191`，F407 目标为 `S/193`；ACK 来源为 `S/193`，目标为 `S/191`，不固定 system ID。

请求使用 `COMMAND_LONG`（消息 ID 76），`confirmation=0`。

| command | 命令号 | param1 | param2 | param3..7 |
| --- | ---: | --- | --- | --- |
| `arm` | 31093 | 0 | 0 | 全部 0 |
| `takeoff` | 31091 | 0 | 0 | 全部 0 |
| `land` | 31092 | 0 | 0 | 全部 0 |
| `disarm` | 31094 | 0 | 0 | 全部 0 |
| `emergency_stop` | 31090 | 0 | 0 | 全部 0 |
| `set_motor_pwm` | 31014 | `motor_id` | `pwm_us` | 全部 0 |
| `set_module_enabled` | 31015 | 模块编号 | `1.0` 开启，`0.0` 关闭 | 全部 0 |

单电机参数通过 MAVLink `float` 承载，但入口值必须是上述范围内的整数。

| `module` | `param1` | 开启后 F407 显示 |
| --- | ---: | --- |
| `gnss` | `0.0` | 定位页 |
| `imu` | `1.0` | 姿态页 |
| `baro` | `2.0` | 气压计页 |
| `lora` | `4.0` | 通信页 |
| `rid` | `7.0` | Remote ID 页 |

F407 开启指定模块并切到对应页，模块已开启时也切页。关闭时保留当前页，若停留在该模块页则显示「已关闭」并清除旧读数。F407 拒绝请求时保持原有模块状态和页面。

模块启停需要支持 MAVLink `31015` 的 F407 固件。气压计停用后，树莓派在快照与实时遥测中省略 `telemetry.pressure`，重新开启并收到新采样后恢复该字段。

## 3. 受理回执

Pi 成功写入串口后立即回 `in_progress`，随后等待最多 2 秒的 F407 受理应答。**`accepted` 表示 F407 已接受请求。模块启停、屏幕刷新、电机及声光动作可能仍在执行。** 本版只使用 `MAV_RESULT=0..4` 作为受理结果。Pi 忽略 `MAV_RESULT_IN_PROGRESS=5` 等其他结果，继续按原截止时间等待。

下列是完整回执中的典型字段；由 `command_id` 关联原请求，按 `status`、`error_code` 处理，`message` 用于显示。

```json
{"command_id":"motor-001","command":"set_motor_pwm","mavlink_command":31014,"status":"in_progress","result_code":"pending","message":"命令已下发，等待F407受理"}
```

```json
{"command_id":"motor-001","command":"set_motor_pwm","mavlink_command":31014,"status":"accepted","result":0,"result_code":"accepted","message":"F407已接受命令"}
```

```json
{"command_id":"motor-001","command":"set_motor_pwm","mavlink_command":31014,"status":"rejected","result":2,"result_code":"denied","error_code":"device_locked","message":"设备未解锁"}
```

```json
{"command_id":"takeoff-001","command":"takeoff","mavlink_command":31091,"status":"timeout","error_code":"mcu_ack_timeout","message":"未收到F407受理结果，执行状态未知"}
```

串口不可用、身份未核验/冲突、请求非法或串口写入失败时不发布 `in_progress`。发出前的门禁失败返回 `rejected`；写入失败或下发后断链时返回 `timeout`、`device_link_unavailable`，因为不能断言 F407 未执行。受理超时表示是否接受、是否执行均未知；Pi 不自动重发原命令，软件也不得据此继续下一动作。

### F407 应答字段与原因

`COMMAND_ACK`（消息 ID 77）的 `command` 对应原命令号，`progress=255`，接受时 `result_param2=0`。只接受当前已核验端点、目标及在途命令号匹配的应答。

| result | result_code | 含义 |
| ---: | --- | --- |
| 0 | `accepted` | 已接受，允许执行 |
| 1 | `temporarily_rejected` | 暂时不能接受 |
| 2 | `denied` | 参数、门禁或状态不允许 |
| 3 | `unsupported` | 不支持该命令 |
| 4 | `failed` | 执行准备或内部检查失败，未接受 |

| result_param2 | F407 原因 | 对应 result | MQTT error_code |
| ---: | --- | ---: | --- |
| 0 | 无细分原因 | 0、3 或无细分拒绝 | 接受无错误码；result=3 为 `unsupported_command`，其余拒绝为 `mcu_rejected` |
| 1 | 未解锁 | 2 | `device_locked` |
| 2 | 动作忙 | 1 | `device_busy` |
| 3 | 参数非法 | 2 | `invalid_parameter` |
| 4 | 当前动作状态不允许 | 2 | `invalid_state` |
| 5 | 起飞内部检查未通过 | 4 | `device_check_failed` |

未识别的原因值同样使用上述拒绝兜底，不猜测具体故障。原始 `result`、`result_param2` 保留在完整 MQTT 回执中。

## 4. 在途请求、优先级与重投

- 普通请求等待受理时，新的普通请求返回 `command_busy`。
- `disarm`、`emergency_stop` 可绕过正在等待的其他命令号，立即下发；各命令号的受理 ACK 独立匹配，允许乱序返回。Pi 允许下发不代表 F407 一定接受，锁状态和动作门禁仍由 F407 决定。
- MAVLink ACK 只有命令号，没有 MQTT `command_id`。同一命令号已有在途请求时，新标识请求返回 `command_busy`；不能用两个相同命令号同时等待 ACK。
- 某命令号受理超时后，保留 10 秒迟到 ACK 隔离期；该期间该命令号的新请求也返回 `command_busy`，迟到 ACK 不关联为新请求的成功。
- 上锁、急停成功写入串口后，中止 H1/M1 及待发串口实验的后续发送；实验仍回报中止结果，但不追加失败声光，以免覆盖停车动作提示。控制回执异步发送并追踪 MQTT 完成；结束会话时最多等待 2 秒排空已入队的回执。
- Pi 进程内使用有界缓存重放同一设备相同 `command_id` 的处理结果。同一设备重建 MQTT 会话时保留缓存和迟到 ACK 隔离；相同标识改用不同内容返回 `command_id_conflict`。缓存的有效范围是当前进程，收到未知超时后应由业务方确认再决定下一步。
- 五个模块共用命令号 `31015` 和迟到 ACK 隔离期。重投时按模块和目标开关值比较请求内容。需要再次切到已开启模块的页面时，使用新的 `command_id`。

## 5. 实际动作、声光与锁状态

Pi 负责入口校验、身份与端点核验、串口转发和受理回执。**F407 负责锁门禁、动作忙判断、起飞内部检查、实际电机输出与整次动作的声光编排。** Pi 不维护替代性的解锁状态，也不在受理后补发动作阶段命令。

| 动作 | F407 接受后的流程 | 实际锁状态 |
| --- | --- | --- |
| `arm` | 低音 1 秒结束，随后四电机进入怠速 | 真正进入怠速后已解锁 |
| `takeoff` | 高音快速三声结束，随后执行内部起飞并缓慢提速 | 保持已解锁 |
| `land` | 内部降落与高音间歇鸣响并行，每次约 0.5 秒，直到四电机怠速 | 保持已解锁 |
| `disarm` | 四电机立即停车、锁定，同时高音 1 秒 | 锁定 |
| `emergency_stop` | 立即取消当前动作、四电机停车并锁定，随后高音快速两声 | 锁定 |
| `set_motor_pwm` | 成功声光结束，随后仅修改指定电机 PWM | 保持已解锁 |

`takeoff`、`land`、`disarm` 和 `set_motor_pwm` 由 F407 检查解锁门禁。模块启停可在锁定或锁态未知时提交，是否受理由 F407 根据当前状态决定。已解锁时 `disarm` 可打断起飞、降落或调速；急停可打断包括解锁声光在内的所有流程，停车不能等待排队、声光或 ACK 发送。被打断流程不能恢复后续提速或调速。怠速约 1200 μs 仅为示例，实际怠速、停车输出、起降曲线及声光细节由 F407 确定。

F407 受理六类动作或模块启停请求后，自行执行本次动作的声光。**只有收到与当前请求匹配的 F407 明确拒绝 ACK（`result=1..4`）时，Pi 才追加一次 `TUNNEL/0x8040` 失败通知 `01 00`。** 本地拒绝、链路失败和受理超时均不追加控制声光。配置和实验命令保留各自终态提示规则，见 [Pi 命令结果提示与 F407 接口](Pi命令结果提示与F407接口.md)。

F407 用 `HEARTBEAT.base_mode` 的第 7 位（掩码 128，`MAV_MODE_FLAG_SAFETY_ARMED`）报告实际解锁状态。Pi 原样透传到 `telemetry.heartbeat.base_mode`，读取方式为 `(base_mode & 128) != 0`；保留其他位含义，不将整个字段与 128 判等。上电及解锁声响期间位为 0，真正怠速后为 1，降落后保持 1，上锁/急停停车后为 0。没有新鲜心跳或设备失联时状态未知，不能从 PWM、`run_state` 或 `accepted` 推断。

本地工具及隔离联调方式见 [本地主控箱命令测试工具](本地飞控下发测试工具.md)。
