# Pi 5 通用工厂镜像

同一镜像供一批设备烧录。镜像预装业务基线、5G 拨号、维护和登记客户端及运行依赖；不携带样机的设备编号、绑定文件或更新令牌。出厂不需要逐台 SSH、编译或输入编号。

## 现场操作

1. 用 Raspberry Pi Imager 的自定义镜像入口烧录 `.img.xz`，连接 F407、RM500U-CNV 模块及适配的物联卡，上电。
2. 5G 拨号和业务服务启动；业务程序从 F407 的 `OPEN_DRONE_ID_BASIC_ID.uas_id` 获取真实编号并持久化绑定。
3. 登记客户端向服务器发起待确认登记。管理员核对设备编号并确认具体登记记录，服务器下发专属维护令牌，Pi 自动保存。
4. Web 选择设备和版本，点击更新，沿用现有远程更新流程。

编号是设备身份；令牌是访问更新接口的凭据。二者不需要操作员在 Pi 上填写。服务器的内部维护 node_id 由服务器分配，并与 F407 编号关联。首次开通审批和后续 Web 更新各有明确用途：前者决定是否接受新设备，后者决定安装哪个版本。

首次部署不下载软件、不访问 apt。物联卡需能访问构建时配置的服务器；通用 APN、AT 接口号、网卡名和 MQTT 地址须适合这一批设备。默认样例针对当前 RM500U-CNV/NCM 参数，不代表任意运营商或模块都可直接使用。

## 镜像维护者构建

源头为官方 [rpi-image-gen](https://github.com/raspberrypi/rpi-image-gen)，固定提交记录在 `image/rpi-image-gen.rev`。目标仅为 Pi 5、Debian trixie ARM64；image-gen 提供的 Pi 硬件层及 MBR/FAT/ext4 布局用于生成镜像，不复制现场设备的 SD 卡。

在 GitHub Actions 的 **Factory image** 手动选择分支/提交，填写 `server_url`（公开 HTTPS 登记入口，不含凭据）和仓库内通用 `business_config` 路径。工作流先执行完整 ARM64 CI，再用同一源码提交的发布包制镜像。源码和编译器保留在 CI，不进入成品镜像。

开发分支首次推送镜像构建文件会自动进行候选构建，使用 `https://maintenance.example.invalid`。这个候选用于验证制镜像链路，不能交付现场；正式候选须改用真实维护服务地址，服务器接口也须就绪。镜像构建不自动创建 GitHub Release 或发布到设备。

产物 `factory-image-pi5-<source SHA>` 包括压缩镜像、SHA-256、`build-record.json`、`readback.json`、`packages.tsv`、运行库检查及构建日志。记录关联源码、发布包摘要、image-gen 提交和镜像摘要。该工作流目前需要原生 ARM64、privileged Debian trixie Docker；普通 Windows/WSL 开发环境不要执行制镜像安装依赖或目标部署脚本。

镜像使用普通可写 ext4；各组件仍位于 `/opt/cns-rpi/releases/`。NetworkManager 管理 DHCP/IP/DNS/路由，蜂窝守护程序拥有 AT 串口；默认 networkd/iwd 和可能抢占 AT 口的 ModemManager 被禁用。日常业务更新不重建系统镜像，不重启 5G。

## 开机状态与排查

`cns-rpi.service`、`cellular-dialup.service` 正常运行。`cns-rpi-enrollment.timer` 开机约 20 秒后开始、每 60 秒尝试一次登记；无 F407 绑定时正常等待，不妨碍业务运行。获批前 `cns-rpi-maintenance.service` 因缺少正式配置跳过执行；获批后下一轮维护 timer 开始轮询。

登记状态位于 `/var/lib/cns-rpi-maintenance/enrollment.json`；正式凭据位于 `/etc/cns-rpi-maintenance.json`，均仅 root 可读。请求与随机登记凭据在重启后保留，不重复创建新设备。更换绑定或登记服务器不会自动改绑；已有正式配置时不再自动申请。不要清空绑定/登记文件来掩盖服务器审批冲突。

镜像中 `dcdw` 账户锁定密码，不配置默认 SSH 登录密码或 sudo。确需现场登录时，由维护者在制作维修镜像时加入受控 SSH 公钥并按维修流程授予权限；未准备登录方式时，可断电取卡检查日志与配置。设备不能联网时，先查模块枚举、APN、DHCP/IP/DNS/默认路由及物联卡访问范围；不要用重新烧录代替保留故障证据。

## 验证边界

临时根目录测试验证真实 Installer、配置布局、离线 systemctl 与 DHCP profile；真实 loopback HTTP 测试验证登记 pending/approved 和重启复用。镜像工作流回挂只读 root 分区，检查源版本、权限、锁定账户、相对链接、无现场身份及运行库。

构建成功不能证明实体启动或纯 5G 接通。交付前用实际 Pi 5/F407/物联卡完成：烧录启动、获得 IP/DNS/路由、自动发现编号、服务器审批、Web 更新指定版本和故障回退。服务器登记/审批、MQTT 更新任务和 Web 状态仍由服务器工作线实现与联调。
