# Pi 5 通用工厂镜像

同一镜像供一批设备烧录，预装业务基线、5G拨号、维护服务和运行依赖。不携带样机编号、绑定文件或共享接入密钥，不逐台SSH、编译或填写身份。

## 现场流程

1. 用 Raspberry Pi Imager 自定义镜像入口烧录 `.img.xz`，连接 F407、RM500U-CNV 模块和匹配的物联卡，上电。
2. 5G和业务启动；F407 的 `OPEN_DRONE_ID_BASIC_ID.uas_id` 自动成为 device_id，现有业务程序持久化绑定。
3. 维护程序首启生成一份设备接入密钥，首次 poll 在服务器显示待确认。服务器确认后认可此密钥，不再签发另一份升级令牌。
4. Web 选择设备、版本和组件，点击更新；Pi 从同一个 poll 接口领取并回报结果。

device_id 标识设备，密钥验证访问权限。不另设树莓派节点编号或独立登记接口，也不要求现场填写凭据。无F407绑定时维护正常等待，不阻塞业务或拨号。重启保留绑定、密钥和任务结果。

首次上电不下载软件或访问apt。通用APN、AT接口号、网卡名、MQTT地址需适合该批设备；样例针对当前RM500U-CNV/NCM配置，不代表所有SIM/模块通用。物联卡需访问服务器API和下载地址，设备系统时间及HTTPS信任链正常。

## 镜像构建

采用固定提交的官方 [rpi-image-gen](https://github.com/raspberrypi/rpi-image-gen)；版本见 `image/rpi-image-gen.rev`。目标仅为Pi5/trixie ARM64，普通可写ext4，不复制现场SD卡。

Factory image 工作流先构建测试同源ARM64包，再制镜像、只读回挂检查、压缩及上传；镜像不带编译器或源码。合入默认分支后可在Actions手动选择源码版本，填写公开HTTPS `server_url` 和仓库内通用 `business_config` 路径。当前开发分支的镜像相关文件推送也触发候选构建。

自动候选使用 `https://maintenance.example.invalid` 验证构建链，不能用于现场接入。交付候选须填写正式地址，并接入服务器poll/开通/任务功能。构建不自动tag、发Release或部署到设备。

产物包括 `.img.xz`、SHA-256、build-record.json、readback.json、packages.tsv、运行库检查和构建日志。记录对应源码SHA、包SHA、image-gen SHA和镜像SHA。仅有工作流绿色状态不足以证明产物存在，交付时核对这些文件。

构建需要原生ARM64、privileged Debian trixie Docker。普通Windows/WSL只做开发测试，不运行制镜像安装依赖或目标部署脚本。镜像通过NetworkManager提供DHCP/IP/DNS/路由；禁用networkd/iwd和可能抢占AT口的ModemManager，AT口仍由蜂窝守护程序唯一持有。

## 配置与排查

`/etc/cns-rpi-maintenance.json` 只含schema_version、server_url、business_config。F407绑定路径由业务配置identity.binding_file指定。密钥自动保存于 `/var/lib/cns-rpi-maintenance/access.json`，root0600、目录0700，不输出到日志。已有密钥遇到编号/服务器改变不会自动换绑。

维护timer开机约60秒开始，空闲时每60秒poll一次；pending/rejected响应不得带更新任务。服务器首次确认只做一次，每次Web点击仍决定是否更新及版本。断网时本地保存任务结果，恢复后回报，不能因没收到结果就推断成功。

镜像dcdw账户锁定密码，无默认SSH密码或sudo。确需现场登录，由维护者在受控维修镜像中加入SSH公钥并授予必要权限；无网络时可断电取卡保留日志和配置。先查USB枚举、APN、DHCP、DNS、路由及物联卡访问范围，不以清空身份/密钥文件掩盖问题。

## 验证边界

临时root测试运行真实Installer和离线systemctl；真实loopbackHTTP测试验证任务、接入状态和重启复用。镜像CI回挂检查源版本、权限、锁定账户、相对链接、无设备密钥/绑定和运行库。

构建成功不代表实体启动。交付前另行验证Pi5/F407/实际SIM的烧录启动、编号获取、纯5G网络、服务器确认、Web指定版本更新与回退。服务器代码由另一工作线实施；本仓库不替代联调。
