# 高低频遥测发布协议

版本：2026-08-04

状态：已实施（树莓派端）

## 1. 目标

主控箱和 PX4 共用两条同构的 MQTT 发布通道。两条通道都从同一个
`TelemetryState` 读取当前最新状态，差别只在发布周期和 JSON 字段范围：

- 快照通道按低频发布完整状态，供服务器维护设备状态和数据库；
- 实时通道按高频发布快变字段，供当前正在查看设备的 Web 页面使用。

发布器不保存历史帧。MQTT 发布失败时丢弃本周期帧，下一周期重新采样最新状态，
不重传、不补发，避免旧数据积压后放大显示延迟。

## 2. MQTT Topic

| 通道 | Topic | 默认周期 | QoS | Retain |
|---|---|---:|---:|---:|
| 快照 | `{namespace}/{device_id}/telemetry/snapshot/v1` | 1000 ms（1 Hz） | 0 | false |
| 实时 | `{namespace}/{device_id}/telemetry/realtime/v1` | 100 ms（10 Hz） | 0 | false |

`device_id` 统一来自 `OPEN_DRONE_ID_BASIC_ID.uas_id`。主控箱和 PX4 不再使用不同的
遥测 Topic。以下旧 Topic 已废弃，设备不会双发：

```text
{namespace}/{device_id}/telemetry
{namespace}/{device_id}/px4/realtime/v1
```

设备在线状态仍由 retained registration 表达，不能根据遥测是否有 retained 消息判断。

## 3. 配置

```json
{
  "telemetry_publish": {
    "snapshot": {
      "enabled": true,
      "interval_ms": 1000
    },
    "realtime": {
      "enabled": true,
      "interval_ms": 100
    }
  },
  "mqtt": {
    "topics": {
      "telemetry_snapshot": {
        "suffix": "telemetry/snapshot/v1",
        "qos": 0
      },
      "telemetry_realtime": {
        "suffix": "telemetry/realtime/v1",
        "qos": 0
      }
    }
  }
}
```

- 快照周期允许 100～60000 ms；
- 实时周期允许 50～1000 ms，即上限 20 Hz；
- 两个 Topic 后缀必须非空且不能相同；
- 两个通道的 QoS 固定为 0，retain 固定为 false；
- 远程参数名 `telemetry_publish_interval_ms` 为兼容既有命令保持不变，但只更新
  `telemetry_publish.snapshot.interval_ms`。

`deploy.sh` 会在重启主程序前幂等迁移旧现场配置。配置卷处于只读挂载时，脚本先在
`/run/cns-rpi` 生成并验证候选，再通过正式配置 helper 短暂切换读写状态、原子替换
并恢复只读，不直接写挂载点。旧实时默认值 50 ms 会迁移为新的生产默认值 100 ms；
符合新范围的其他显式周期保持不变。已经是新结构的配置不会被重新格式化或写回。

## 4. JSON 字段边界

### 4.1 快照帧

快照帧继续使用 `schema_version=3`，包含当前已知的完整遥测、5G 链路状态、模块、
告警、日志和 Open Drone ID 数据。未收到的字段省略，不输出 `null` 占位对象。

```json
{
  "schema_version": 3,
  "device_id": "DCDWCNS1S2MEAG1VTA0C",
  "device_type": "cns_box",
  "school_name": "SEU",
  "sent_at": "2026-08-04T02:00:00Z",
  "telemetry": {
    "motor": {},
    "cellular_5g": {}
  },
  "modules": [],
  "alarms": {},
  "logs": {},
  "drone_id": {}
}
```

### 4.2 实时帧

实时帧使用独立的 `schema_version=1`，`sent_at` 保留毫秒，`sequence` 按 MQTT 会话
内每个通道从 0 递增。它可以同时容纳主控箱电机字段和 PX4 飞行动态字段：

```json
{
  "schema_version": 1,
  "device_id": "DCDWCNS1S2MEAG1VTA0C",
  "sequence": 42,
  "sent_at": "2026-08-04T02:00:00.123Z",
  "telemetry": {
    "heartbeat": {},
    "attitude": {},
    "gps": {},
    "global_position": {},
    "sys_status": {},
    "battery": {},
    "pressure": {},
    "motor": {
      "duty_percent": [10, 20, 30, 40],
      "run_state": true,
      "speed_level": 2,
      "pwm_us": [1500, 1510, 1520, 1530],
      "pwm_time_usec": 123456
    }
  }
}
```

实时帧不携带 `school_name`、`device_type`、`cellular_5g`、`modules`、`alarms`、
`logs` 或 `drone_id`。具体快变字段仍遵循“收到才输出”的规则，因此主控箱帧不会
伪造 PX4 数据，PX4 帧也不会伪造主控箱电机数据。

## 5. 服务端消费边界

- 数据库和设备状态维护服务只订阅快照 Topic；
- Web 实时服务只为当前正在查看的 `device_id` 订阅实时 Topic；
- 禁止服务端常驻通配订阅全部实时 Topic 后再按页面筛选；
- Web 侧每台设备最多保留最新一帧，处理不过来时覆盖旧帧；
- 服务端必须先兼容新 Topic，再升级树莓派。设备端不双发旧 Topic。

## 6. 性能与控制边界

默认生产频率是 10 Hz，允许配置到 20 Hz。1000 台设备同时按 20 Hz 发布时，实时
流量为 20000 条/秒，另有约 1000 条/秒快照。此数字是容量设计目标，不代表已经
通过验收；上线前必须在服务端完成持续 1 小时的 Broker、消费者和 Web 链路压测。

提高实时遥测频率只能让界面更快看到主控箱电机状态或 PX4 飞行状态，不会缩短
MQTT 命令路由、MAVLink 下发或设备动作执行时间。实时频率还受固件/PX4 原始消息
上报节拍限制，树莓派不会凭空生成更高频的新状态。

## 7. PX4 真实 RTT 探测

PX4 的真实 RTT 探测仍使用以下专用 Topic，不与通用遥测通道合并：

```text
{namespace}/{device_id}/px4/latency/probe/v1
{namespace}/{device_id}/px4/latency/ack/v1
```

两者均为 QoS 0、retain false，只在飞控模式订阅和应答，不进入遥测状态或数据库。

## 8. 运行日志

MQTT 会话创建后，主程序分别打印两个通道的启用状态、实际周期和完整 Topic，不打印
原始 JSON。某通道连续发布失败时只记录第一条警告，恢复成功后若再次失败才重新记录。
