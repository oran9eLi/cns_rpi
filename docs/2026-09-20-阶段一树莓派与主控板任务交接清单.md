## 1. 共同目标与范围

约 10 天内跑通两类实验：UART6 串口通信，以及真实气压观测加 Server 软件仿真。优先最快、最简单的实现，不新建通用实验框架。网口实验延期为独立第三实验，不进入本清单的阶段一交付。

- 串口使用现有 Pi 串口 ↔ F407 UART6，允许因学生修改波特率而暂时中断业务；不假设另有空闲串口或 USB 回环设备。
- 两端波特率都从 Web 修改。F407 改参先在原串口匹配时送达；失配后通过独立网络改 Pi 重新匹配，不能假装仍能经失配串口修改 F407。
- 首版改参时序已固定：F407 在旧波特率下校验请求并完整发送“已接受”回执，随后在安全的重初始化点切换到新波特率；Pi 不自动跟随。学生再从 Web 修改 Pi，最终以新波特率下的真实 Echo 确认结果。回执丢失时标记“结果待核验”，不盲目重发、不声称已成功。
- 每次 F407 受控实验 Echo 响应都必须携带 F407 从自身当前已应用 UART6 配置取得的实际波特率。首版不增加独立配置查询命令；请求目标值和接受回执都不能冒充实际值，失联时只保留最后已知值并标记待核验。
- 速率对比的两组测试固定 payload、8N1 帧格式、次数、间隔、超时和统计方式，只改变双方匹配波特率。Pi 提供实际请求/响应帧字节数及同一单调时钟的真实 RTT；Server 按每字节 10 bit 计算理论串行时间。评分不要求高波特率实测 RTT 必然更小。
- 已确认学生可以现场复位 F407。退出/兜底采用现场复位 F407 回 B0，再由 Web 调 Pi 回 B0，以新业务数据和真实回显验证；不增加远程复位、复位接线或自动波特率扫描。F407 临时波特率只存 RAM，复位回默认值的行为仍须实测。
- Web → Server → 5G → Pi 的控制路径必须独立于 UART6。主控板无有效数据不等于 Pi 不可控。
- Server 的 PostgreSQL、Mosquitto、路由、后端、前端与 Nginx 全部部署到云服务器，Pi 经 5G 直接连接云端；硬件服务器和旧 FRP 转发链路均不再参与正式运行。
- 本阶段不开发 `NETWORK-01`、学生电脑回显程序或 Pi 以太网实验适配器，也不验收以太网与 SSH 共存；后续第三实验另行设计和交接。
- Server 保存实验状态、原始记录、证据和成绩；Pi/F407 只提供真实执行及采集事实，不计算学生最终分数。
- 多个学生可使用不同设备并行；同一设备同时只能属于一个活动硬件 Session。Server 按 `device_id` 持久化独占租约并原子判定，Web 页面每 30 秒心跳且正常操作也续租 300 秒；Pi 按 `session_id` 拒绝陈旧或不属于当前任务的动作。正常恢复 B0 并由真实数据验证后立即释放；300 秒未续期兜底释放旧 Session，不维护设备待恢复状态。每个新硬件 Session 均先提示学生现场复位 F407，并由 Pi B0、新业务帧和真实 Echo 建立基准。
- Session 访问令牌仅用于 Web 与 Server 的学生会话归属：Server 只保存摘要，Web 在当前标签页的 `sessionStorage` 保存原始令牌并在刷新后恢复同一会话。令牌不得转发给 Pi/F407；设备侧继续只按 Server 已校验后的 `session_id` 和动作身份执行或拒绝。
- 阶段一只验收学生侧完整实验闭环 Demo，不建设教师端、教师鉴权或全班会话/成绩管理；Pi/F407 不承担任何教师端适配任务，只需提供完成真实闭环所需的执行和采集事实。
- 阶段一仍包含串口和气压两个实验。H1 只验证一次 HELLO CNS 真实往返；M1 必须独立验收串口完整闭环，包括匹配—失配—恢复、完整执行/采集事实以及供 Server 形成日志、证据、评分和导出的数据。M1 通过后继续交付气压双模式 M2，不能用 H1 提前替代串口里程碑。
- Pi 持久化最近一次由真实 F407 身份帧验证通过的 `device_id` 绑定。UART6 失配或 Pi 重启后，用该缓存恢复 MQTT 控制和 Pi 本地参数恢复入口；不得据此伪报 F407 在线。F407 身份重新出现后必须核对，一致时刷新验证记录，不一致时阻止实验动作并上报绑定冲突。首次启动或缓存丢失时不允许人工填写、部署预配置或由 Pi 自行认领 `device_id`；必须先在 B0 下取得真实 F407 身份并持久化，绑定前拒绝设备实验和设备定向动作。
- Pi 与 F407 固定安装在同一实验箱内，按一对一固定配对实现；不要求设备端支持 Web/API 换绑、远程换绑、自动搜索替代主控板或多 F407 选择。身份冲突不得自动改绑。维修更换 F407 时，仅由维护人员在 Pi 本地停止服务、清除绑定缓存并重启，再从新 F407 的真实身份建绑。
- 跨端实现遇到复杂方案和简单方案都能满足闭环 Demo 时，一律选择简单方案；不得为未进入阶段一验收的扩展性提前增加协议、状态、配置入口或后台页面。
- 气压仿真、固定基准、模拟压力/高度、曲线和评分在 Server/Web 实现；不要求 Pi/F407 伪造传感器数据，也不要求移动箱体。
- UART Enable/Disable 教学仿真也只在 Server 的当前实验 Session 实现。Pi/F407 继续真实通信和上报，不新增仿真开关，不停止串口，也不改变设备总览。
- QGC、5760 原始透传、mavlink-router 改造、OTA、复杂并发调度不作为本次两实验的前置。

### 1.1 G0 运行三态交付

Pi 开发人员在 `{namespace}/{device_id}/runtime/status/v1` 以 QoS 1、retained 发布运行三态，精确载荷和合法组合见 Server 仓库 `route_service/docs/2026-09-20-新版设备接入基线契约.md` 及对应 fixture。

输入：Pi 的 MQTT 连接状态、F407 有效业务帧接收状态、最近一次真实身份核验与持久化绑定状态。

输出：

- `control_status=online|offline`，只表示 Pi MQTT 控制链；
- `business_status=online|offline|unknown`，只表示 F407 业务帧；
- `identity_status=verified|cached|conflict|unbound`，只表示身份核验；
- Pi 控制在线期间，连续 10 秒没有有效 F407 业务帧后把业务状态改为 `offline`；新有效帧到达后恢复 `online`；
- 三态任一字段变化时发布，不增加周期心跳；
- MQTT Last Will 使用 `control_status=offline`、`business_status=unknown`，已有合法缓存身份时为 `cached`，否则为 `unbound`。

最小验收：Broker 新订阅者能收到 retained 当前值；失去 F407 业务超过 10 秒时 Pi MQTT 仍在线且只改变业务状态；Pi 异常断线时 Last Will 不伪报 F407 离线；F407 身份恢复一致后发布 `verified`，冲突时发布 `conflict` 且不自动改绑。

F407 不直接连接 MQTT、不发布运行三态，本任务不要求 F407 增加代码；它继续只向 Pi 提供真实业务帧和身份事实。

不要求增加主控板本地实验界面、课程逻辑、评分逻辑、仿真注入、完整实验日志存储或网络协议栈。F407 参数不写 Flash，学生现场复位回 B0 的恢复边界已确定；在线切换按本文第 1 节的固定时序实现。B0 数值、共同支持的波特率白名单、UART/DMA 安全重初始化点仍须根据真实固件核验并同步场景，不能各端采用不同默认值。

Pi 保持网络控制，不代替学生向 F407 发复位命令；收到新的业务帧及匹配回显后才上报恢复。Server/Web 提供现场复位引导，将学生“已复位”的声明与实际恢复证据分开保存。退出兜底不替代学生通过修改 Pi 参数恢复通信的考核。

## 5. Server/Web 方提供什么

由服务器开发方统筹，并通过项目负责人传达给两端：

1. `SERIAL-01`、`BARO-01` 两个固定场景的步骤、允许动作、轮次、payload、间隔、超时与证据要求，以及可直接测试的成功/失败样例；串口速率对比冻结同条件两组测试和 8N1 理论公式。
2. 实验请求、执行结果、原始事实和保存确认的公共契约；控制身份、会话归属、重复消息及错误语义。学生 Session 访问令牌只在 Web/Server 边界使用，不进入设备协议；Pi/F407 只接收 Server 已校验的会话与动作身份。Echo 契约必须包含由 F407 生成的当前实际波特率语义，但具体 Topic、字段名和承载格式在契约确认后统一发布，本清单不提前指定。
3. 兼容当前 Pi 注册/遥测版本的服务器入口，以及实验动作路由；不能因主控板串口失配而拒绝 Pi 本地恢复动作。Server 同时提供按设备持久化租约，同设备并发开始只有一个成功，竞争失败不向 Pi 派发动作；页面每 30 秒心跳和正常操作续租 300 秒；恢复验证后立即释放，300 秒未续期兜底释放并阻止旧 Session 迟到动作。每个新硬件 Session 在普通动作前强制完成现场复位与 B0 基准。
4. Web 操作页、Server 权威状态与记录、确定性评分、结果查询、CSV/JSON 导出及气压软件仿真。
5. Server 端 UART 数据流启停仿真：只停止当前 Session 纳入/推送新的 UART 观测，持续记录操作和错误；设备总览继续更新，重新启用等待新数据。
6. 联调入口、固定版本组合和端到端验收用例。两端本地自测通过不等于整链验收通过。

Pi/F407 应先反馈实际接口和已有消息能力，再由三端冻结最小契约。不要求两端等待完整页面或评分完成才准备本端能力，也不能各自定好新协议后再要求其他端迁就。

## 6. 按闭环交付，不一次性交付全部改动

| 批次 / 目标时间 | Pi 与 F407 交付 | Server/Web 配合与通过门槛 |
|---|---|---|
| 第一批 / D1–D2 | 现场信息、控制解耦、Pi 本地改参；F407 回显与改参最小能力 | 冻结契约并准备动作入口。先验证串口失联后控制仍可达，不等评分页 |
| 第二批 / D3–D5 | 真实串口收发、失配/恢复和原始证据 | 先 H1 单次真实往返，再完成 M1 串口步骤、评分、存档和导出 |
| 第三批 / D6–D7 | 可信气压新样本、失效与停止采集 | M2 真实观测和软件仿真双模式、曲线、考核及导出 |
| 第四批 / D8–D10 | 取消、丢消息、断线/重启、业务恢复和候选版本记录 | 联合异常回归、非开发人员试跑、部署与最终验收 |

D1 从设计/实施计划确认且具备实施条件后计算。上述为目标窗口，不承诺未核验硬件已经可用。若控制恢复或 F407 回显延误，应尽早反馈并调整联调，不拿模拟器结果代替真机成果。

每个任务原则上对应一个可独立验证的提交；较大任务按实际可运行效果拆分。提交说明使用英文前缀加中文正文，例如 `feat: 增加受控串口实验回显`。每批返回：完成的任务编号、源码提交/固件版本、运行方法、真实记录、已知限制与下一项阻塞。新增协议和行为同步各自仓库文档，不只通过聊天传达。

两端每批必须同时交付可核对证据：构建、烧录或运行命令，所用配置与版本，一份成功记录，一份对应失败或断链记录，以及能证明真实 UART6 收发的原始帧或日志。只提供截图、汇总成功数或“本地没问题”不作为跨端验收依据。如现有代码或实板与本清单冲突，先返回事实证据和影响，不自行扩大范围、修改跨端契约或降低验收标准。
