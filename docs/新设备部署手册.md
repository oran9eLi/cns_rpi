# 新设备部署手册

版本：2026-09-14，V1.0 发布收尾。

目标平台为 Raspberry Pi 5 / Raspberry Pi OS 64-bit（trixie / Debian 13）。V1.0 使用普通可写根文件系统，不启用 OverlayFS，不创建独立配置卷；两个常驻服务仍安装并开机自启动。本轮新设备与重复部署、重启验收待实机执行。

## 1. 准备用户与网络

烧录系统时创建 `dcdw` 用户，确认能 SSH 登录并具备 sudo 权限。部署仓库固定为 `/home/dcdw/cns_rpi`，不要用 root 执行整个安装脚本。免密 sudo 可直接执行；未配置免密时请在交互终端输入 sudo 密码。自动化无人值守执行需要预先提供可用的 sudo 授权。

初次安装需要能访问 apt 软件源和 Git 仓库。安装脚本会切换至清华 TUNA apt 源，并配置当前用户 GitHub URL 的镜像重写。

## 2. 克隆并准备现场配置

```bash
git clone https://ghfast.top/https://github.com/oran9eLi/cns_rpi.git /home/dcdw/cns_rpi
cd /home/dcdw/cns_rpi
cp config/config.example.json config/config.json
nano config/config.json
```

镜像地址用于直连 GitHub 不稳定的环境；若直连可用，也可使用仓库原始地址。只在首次部署、尚无本地配置时复制样例，避免覆盖已有配置。

| 配置项 | 现场检查 |
|---|---|
| `mqtt.connection.host` / `port` | broker 地址和端口；样例为 `112.124.52.232:1883`，按现场服务入口确认 |
| `mqtt.auth` | 按 broker 配置填写认证信息，真实凭据不提交 |
| `identity.school_name` | 主控箱学校名称；身份仍由受控设备上报 |
| `serial.device` / `baud` | 通常保持 `auto` 与双方约定波特率，不写死 USB 枚举号 |
| `device.mode` | 通常保持 `auto`；同一时间只连接一台受控设备 |
| `cellular.apn` | 与物联卡业务匹配；同时确认探测目标在白名单内 |
| `telemetry_publish` | 快照默认 1000 ms、实时默认 100 ms；服务端需支持对应 Topic |
| `mqtt.connection.reconnect` | MQTT 重连初值及上限 |

校验 JSON 语法：

```bash
python3 -m json.tool config/config.json >/dev/null
```

## 3. 一键安装、构建和部署

```bash
./scripts/install_deps.sh
```

依赖包括 `build-essential`、`cmake`、`git`、`pkg-config`、`libmosquitto-dev`、`nlohmann-json3-dev`、`doctest-dev`、`python3`、`python3-serial`、`iproute2`、`iputils-ping`、`util-linux` 和 `sudo`。脚本完成依赖准备后调用 `deploy.sh`，执行构建、配置初始化、helper 与 systemd 配置安装，随后启用并启动 `cns-rpi.service` 和 `cellular-dialup.service`。

部署采用 Release 构建和 2 个并行构建任务。可使用 `./build/cns_rpi --version` 查看程序版本；`./build/cns_rpi --check-config /var/lib/cns-rpi/config.json` 仅校验指定绝对路径的配置，不打开串口或建立 MQTT 连接。

首次部署以仓库内 `config/config.json` 初始化 `/var/lib/cns-rpi/config.json`。后者是两个服务共同读取的现场配置；重复部署保留已有现场参数。后续不要把修改仓库样例当作修改运行配置，运行时配置命令仍通过 helper 原子更新现场文件。

`/run/cns-rpi` 是重启后重建的临时运行目录，用于 5G 状态快照及配置候选等运行数据，不是持久配置目录。两个常驻服务共享它，不相互等待拨号或 MQTT 就绪，单个服务重启不应删除另一个服务仍需使用的数据。

## 4. 验收

```bash
systemctl is-enabled cns-rpi.service cellular-dialup.service
systemctl is-active cns-rpi.service cellular-dialup.service
journalctl -u cns-rpi.service -u cellular-dialup.service -n 100 --no-pager
```

检查主程序启动日志中的配置是否与现场参数一致；连接受控设备后确认串口发现、Basic ID 身份就绪、MQTT 注册与两个遥测 Topic。没有合法身份时不会建立设备 MQTT 会话。PX4 仅验收已实现的消息解析，不以主控箱私有命令测试飞控。

5G 模块未插入或无 SIM 卡时，联网失败不代表主程序不能启动；应观察守护服务记录的等待和恢复状态。网络不可用与服务异常退出要分别判断。

完成首次启动后，再重复执行 `./scripts/install_deps.sh`，确认现场配置保留；安排重启并再次检查两个服务自启动、配置持久化、串口和 5G 恢复。测试需记录版本、配置和结果，不能用历史设备结果替代本次验收。

开发验证可执行 `ctest --test-dir build --output-on-failure`。本轮本地 37 项测试已分批通过，其中 `qgc_udp_bridge` 需在允许 UDP 套接字的环境运行，原失败确认为沙箱限制。本地结果不等同于 ARM 构建、QGC 或其他硬件功能实机验收；最终记录见发布准备清单。

## 5. 更新与配置维护

```bash
cd /home/dcdw/cns_rpi
git pull --ff-only
./scripts/deploy.sh
```

需要重新安装依赖时执行 `./scripts/install_deps.sh`。手工维护现场配置前备份 `/var/lib/cns-rpi/config.json`，变更后检查 JSON 语法并重启受影响的服务。修改 5G 参数时，需让 5G 守护服务重新读取配置。

升级前记录 `git rev-parse HEAD`，并将现场配置备份到仓库外、限制访问权限。需要回退时，在维护窗口停止两个服务，恢复对应的旧代码版本和与之匹配的配置，再按该版本部署步骤构建和启动。配置结构及遥测 Topic 有变化时必须同步核对服务端兼容性；不要只换旧二进制而保留不兼容的新配置。跨只读存储方案的回退需要专项迁移，不由 V1.0 脚本自动完成。

两个服务的日志可使用同一个 `journalctl` 命令查看。journald 使用内存存储和 16 MiB 上限，设备重启后不保留上次启动日志；需要验收留档时及时导出。

镜像失效时可撤销 Git 重写，再按可用网络访问原始仓库：

```bash
git config --global --unset url."https://ghfast.top/https://github.com/".insteadOf
git remote set-url origin https://github.com/oran9eLi/cns_rpi.git
```

## 6. 旧只读设备迁移边界

已启用 OverlayFS、独立配置镜像或 `/var/lib/cns-rpi` 挂载的旧设备，必须先迁移，再执行 V1.0 部署。部署脚本不承担自动修改启动分区、卸载配置卷或停用系统级只读方案的职责。

脚本发现根挂载为 OverlayFS、`/var/lib/cns-rpi` 为挂载点，或仍存在 `/etc/systemd/system/cns-rpi-config.service` 时会拒绝部署。仅删除旧单元文件不能代替迁移，应先确认实际存储和启动配置。

迁移前备份实际挂载卷中的现场配置、仓库未提交改动和启动配置，并安排可物理接触设备的维护窗口。按旧设备实际启用方式停用 OverlayFS 与旧配置挂载，重启确认根文件系统可写、现场配置已恢复到普通目录且不再依赖旧挂载单元。确认这些条件后再部署 V1.0；不要直接删除镜像或仅删除服务依赖。

历史方案及恢复背景见 `docs/OverlayFS只读根文件系统设计.md`，该文档不是 V1.0 新设备安装步骤。
