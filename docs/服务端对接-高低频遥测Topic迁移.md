# 服务端对接：高低频遥测 Topic 迁移

版本：2026-08-04

## 1. 新订阅契约

```text
数据库/route_service：cns_rpi/+/telemetry/snapshot/v1
Web 实时服务：       cns_rpi/{device_id}/telemetry/realtime/v1
```

数据库只消费快照 Topic。Web 实时服务只在用户正在查看某台设备时订阅该设备的实时
Topic，页面关闭或切换设备后取消订阅。禁止常驻订阅
`cns_rpi/+/telemetry/realtime/v1` 后再在应用层筛选，否则 1000 台设备的全部高频流量
都会无条件进入单个消费者。

实时消费队列按设备最多保留最新一帧。新帧到达时可以覆盖尚未处理的旧帧，不允许
建立无界队列，也不把实时帧写入 PostgreSQL。

## 2. 废弃 Topic

```text
cns_rpi/{device_id}/telemetry
cns_rpi/{device_id}/px4/realtime/v1
```

树莓派升级后不会继续发布这两个 Topic，也不会迁移期双发。服务端完成新订阅后，
才能部署新版树莓派。

## 3. 部署顺序

1. `route_service` 增加 `cns_rpi/+/telemetry/snapshot/v1` 订阅并验证入库；
2. Web 实时服务实现按当前页面设备动态订阅 `realtime/v1`；
3. 确认监控中能区分快照和实时消息流；
4. 再升级树莓派并由 `deploy.sh` 迁移设备配置；
5. 观察新 Topic 稳定后删除服务端旧 Topic 订阅代码。

回滚时应整体回滚树莓派程序和现场配置备份，不能只恢复旧订阅，因为新版设备不双发
旧 Topic。

## 4. 字段处理

- 快照帧：`schema_version=3`，沿用现有完整遥测解析和数据库更新逻辑；
- 实时帧：`schema_version=1`，按 `device_id` 和 `sequence` 更新页面最新状态；
- 两类帧都允许省略尚未收到的数据字段；
- 实时帧中的 `motor` 适用于主控箱，飞行动态字段适用于 PX4，同一解析器按字段存在
  与否处理，不根据设备类型维护两套 JSON 外壳。

## 5. 容量验收门禁

正式发布前，在服务端仓库另行实现压测工具并完成以下验收：

- 1000 个设备身份；
- 每设备实时 Topic 20 Hz，快照 Topic 1 Hz；
- 连续运行 1 小时；
- Broker 无持续积压或异常断连；
- 数据库只收到快照，写入负载符合预期；
- Web 消费者仅订阅正在查看的设备，页面队列始终为“最新一帧”；
- 记录 CPU、内存、网络、消息吞吐和端到端显示延迟。

压测工具和服务端实现不属于 `cns_rpi` 仓库。在上述验收完成前，只能声明树莓派端
功能验证通过，不得声明“1000 台设备容量验收通过”。
